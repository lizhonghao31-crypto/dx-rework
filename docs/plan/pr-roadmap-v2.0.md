## 4. 执行规则

1. 任何实际PR创建前，必须从最新 `main` 或平台注入的已核验基线创建分支。
2. 每个实际PR只对应一个明确路线目标；环境兼容等计划外工作使用 `BASE-*` 或明确例外编号，不挤占业务路线ID。
3. PR描述必须记录路线ID、GitHub PR号、base SHA、head SHA、修改范围、测试证据、风险和回滚方法。
4. 不允许跳过前置依赖；可并行项目必须保持独立文件与模块边界。
5. PR-00完成前不启动PR-01及业务代码；PR-01A设计工作可并行。
6. 后续若需求变化，先更新需求基线和本路线图，再安排施工。
