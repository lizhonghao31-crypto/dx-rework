## 实现与验证要点

- 订单、轮次、执行人员段、节点时间、制作资料绑定分别记录；当前轮次外键、单一当前工人、单一未结束节点约束保证结构一致。
- 普通账号业务开关保持关闭，Root 可验收。测试仅在隔离数据库显式打开正常角色流程，不修改正式配置。
- 唯一一次 Codex Review 指出的两处 P1 已纳入修复：待办 HTTP 模块参数复用共享枚举，覆盖 `pattern_room`；业务尚未开放时，Root 操作保留业务记录和审计，但不向真实员工投递待办/通知，也不把真实主管记为验收单负责人。正常角色隔离测试仍验证真实通知链路。
- 创建必须款号/品类/整数数量/制作资料；当前价格锁定并校验版本，保存单位、单价及总额快照。历史款号独立可选，旧报价冲突不会自动按新价提交。
- 幂等、版本和轮次检查覆盖创建、派工、资料变更、完工及交接。操作、审计、待办与时间记录同事务完成。
- 资料绑定仅允许就绪的原始 PDF/图片；禁止挪用其他人的未绑定文件、其他订单或其他业务附件。旧制作文件保留，下载对绑定订单重新鉴权；原上传者也不能绕过当前业务范围。
- 工人只看自己的费用段；设计师只能访问自己的订单，后台列表、详情和附件均独立限制。工人完工关闭执行待办、创建设计师交接待办、给主管信息通知。交接才取得计薪资格，不新增工资审批。
- 创建页集成新建与可筛选订单列表，预计金额采用精确十进制只读计算；详情返回保留列表筛选与页码，待办入口保留原待办查询。详情提供资料查看/打印、派工、完工、交接、更新资料及自然节点时间。历史轮次链接只读。遵守现有业务手动刷新政策。

## 证据与限制

当前 schema 的 PostgreSQL 集成用例覆盖价格准备、首次打板正常角色流、Root 无普通角色验收及原 N01–N11 金额回归；HTTP 直接调用覆盖本人/越权详情、工人费用裁剪、越权交接及无效筛选。首次打板覆盖重复操作、冲突、资料保留、待办唯一性、未交接不计薪、交接后唯一资格、非法附件绑定及硬删保护。

本地数据库补充验证使用 PGlite，不能替代远端 PostgreSQL 16 Full Gate。本地 Node 24/npm 11 与 CI Node 22/npm 10 不同；依赖使用原锁定版本。浏览器预览仍受会话既有访问阻断，未声称完成视觉或钉钉现场验收。最终数量与 Head/Gate/Review/合并证据记于 PR 时间线。
