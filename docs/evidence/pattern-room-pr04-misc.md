## 实现

- 设计师和跟单发起本人杂事，任务名称必填，款号和原始附件可选；发起人不能录入或覆盖小时价。未配置小时价时正式提交返回明确提示，绝不以零替代缺失值。
- 保存小时价和版本快照；后续调价、资料补充均不重算旧单。主管派工、当前工人报完工、原发起人确认完成；跟单的确认待办按其实际创建职责投递。
- 主管独立填写正数工时，精确到 0.1 小时。数据库约束也拒绝 1.25 等输入，不依赖 numeric scale 静默舍入。节点经过时间始终只是流转用时。
- 工时和工人完工可按两种顺序到达，具备全部事实才一次取得计薪资格；发起人可以在工时缺失时关闭任务，主管补工时待办继续保留。完工与工时均已确定后不能直接覆盖工资依据。明确零价可完成任务，但不产生应付资格。
- 3 位小时价乘 1 位工时可能产生 4 位小数，因此轮次及执行段中间金额精确保存至 8 位，与现有工资引擎来源精度一致。最终金额沿用原有按分及最大余数分配规则，由 PR06 接入；本 PR 不自创 3 位舍入规则。
- 创建页加入“新建杂事”和类型筛选，名称/款号统一搜索，筛选及返回位置保留。详情沿用紧凑流程、原始资料、轮次和历史；主管工时区独立，工人只读取自己的执行段工时与金额。
- 所有写操作保持有效身份复核、本人范围、当前轮次/版本、事务和幂等；Root 关闭期验收保留实际操作审计，不投递真实员工待办。
