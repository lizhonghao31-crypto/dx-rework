# Q01：会计常驻返工查询

## 预检与边界

- repository: lizhonghao31-crypto/dx-rework
- base branch: main；H01 合并 0312bad40e6f16b1bafaf3837063bbc8ed34d332，依赖 H02 审批后入账改动。
- working branch: fix/0915-q01-finance-orders
- task scope: 会计从既有返工入口查询全部基础订单，财务明细继续按岗位范围隔离。
- allowed files: 返工导航、基础查询、原单读取、外部台账读取、对应契约、0186 迁移及行为回归。
- forbidden files: 工资算法、其他模块写权限、老板成员策略、历史迁移和生产数据。
- gate class: FULL。

## 交付行为

加工厂、印绣花洗水、面料应付会计、工资会计、财务总监及财务全局查看获得独立 `rework:finance_orders:read`。复用返工单看板和基础卡片，查询不依赖待办、经办人或已存在台账；没有本类责任时显示“无本类扣款事项”。管理层原查询页面保持原有能力分支。

列表仅返回基础资料、状态和照片；原单链接由服务端明确授予。财务台账的项目、申请、凭证及历史继续由数据库责任类型校验。岗位范围读者不返回共享快照中的整单工资/责任总额，原单结算状态也按相同范围计算。无工资读取能力不返回工资期间；岗位会计不读取全单审计备注，其扣款历史从获准台账查看。

新增迁移只增加模块基础读取能力；不授予通用管理报表、派工、审批或其他写权。当前数据库角色、在职与启用状态仍决定访问；接岗可以查询既有历史，撤销后持有旧页面能力也不能继续读取。混合业务角色保留原有合法动作。

## 验证与验收

- 修改前，真实业务链测试在六类角色缺少固定查询能力处失败。
- 修改后覆盖六种独立角色：未生成台账时查询、已完成原单回看、响应财务字段范围、无关角色伪造读取能力拒绝。
- 覆盖临时接岗读取历史与角色撤销后旧会话列表/详情/台账拒绝；原链路继续验证跨责任凭证、历史重判和审批。
- 本地完整测试、类型检查、lint、构建及 PGlite 业务链；合并证据以当前 Head Full Gate 的原生 PostgreSQL 结果为准。
- 尚未生产部署。普通会计桌面/手机固定入口、双入口同单、真实附件和历史回看留待负责人部署验收。

## 收尾范围核对

混合角色只有在保留原业务关联时才能读取完整工作流备注；兼任工人不会把会计的基础全单查询升级为全单审计读取。失效的财务能力不得依靠旧会话中残留的其他财务角色回退放行。增加真实岗位交接后的混合角色读取/撤销回归，原已关联业务操作保持。

## Review 修复

独立 Review 指出基础详情仍含整单单价及过程记录，以及混合角色备注越界。基础访问现在明确返回受限字段：不返回整单总价、IE 明细、整查追加历史、完整验货报告或工序创建详情；无业务明细资格的基础附件仅开放照片，本责任凭证仍按责任范围校验。页面通过明确能力隐藏总价，不把无权读取伪装成待核价。两项均加入纯角色和混合角色的真实数据库回归；不追加 Review 轮次。
