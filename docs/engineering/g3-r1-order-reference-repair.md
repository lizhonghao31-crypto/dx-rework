外发当前和历史详情：完整保留原核心字段及各自的响应投影，改为标签与值同行的两排摘要；图片为左侧独立卡，右侧为独立主工作卡。按真实内容宽度响应：超过 1040px 保留原 240px 左图结构；中等桌面图片改为紧凑可展开辅助区，将主工作卡放满内容宽度，确保 1180 核价列默认可直接比较。财务节点优先展示其自身批准逐款明细与核对动作，订单原报价／预算／PO 资料保留在可展开上下文内，避免两张重复明细及办理区双边框。六款色老板审批合成场景与原样板同宽对照，生产页面额外保留既有预算与 PO 日期列；窄屏保留手机款式卡。主工作区依真实选中节点展示原表单和动作，老板标题只出现在老板节点。流程与原审批／选厂摘要默认折叠，工艺及说明仍在明细后可见。原退回跟单、转厂、批准和驳回处理函数及授权判断未变。

返工及本厂做尾：恢复图片／流程并排在上、办理区全宽在下，分别覆盖当前和历史页；没有给返工套用外发图片侧栏。文件名改为单行省略，悬停或键盘聚焦可在图片栏内读全名，点击／触摸仍打开原图片对话框。外发文件名使用原生 disclosure，可通过悬停、键盘及触摸读取并预览完整附件。

流程根因包含公共 rail 伪元素规则与局部行首规则的优先级，以及九节点排版依赖链接类型：历史页会混合可用链接及未来不可用 div，不能按第九个链接判定。当前及历史 rail 显式带真实节点总数，九节点使用五加四两行，六节点使用五加一；第六节点的左侧线从圆点中心开始，保留第五到第六步的换行桥及方向，未删除换行桥来掩盖问题。

验证脚本 `tests/acceptance/g3-order-reference-browser.mjs` 在隔离合成数据和拦截 fetch 下，对固定 release 源码与候选应用组件构建真实浏览器页面；1440、1180、1024、390、375 宽度覆盖外发老板／只读／历史、返工九节点及做尾六节点当前／历史。它检查字段与链接保留、审批按钮允许与拒绝、默认收起、全名键盘操作、主次顺序、五加四／五加一排列及第六节点连线。原始 PNG 的视觉匹配仍由人工审阅，不以这些断言代替。
