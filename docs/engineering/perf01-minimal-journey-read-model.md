## 本次范围

- `DigitalJourneyQuery.buildFactsWithClient` 每次只选择一个明确母单；独立开发来源用 source 身份，有关联订单后按 order 身份构建，旧 source 身份不生成第二份母单。它复用原节点、适用性、继承、原生实绩、计划采用和时效计算，没有构造 Root 或其他虚拟用户。
- 原有 `read`、`list` 和办理服务仍走原认证、对象、节点、字段、历史和附件权限。内部事实入口没有 HTTP 路由。原服务的显式内部事实适配不作为用户调用的授权回退。
- `minimalJourneyFacts` 明确选取节点实例、当前轮次、源资料/制单版本、真实起点和实绩质量、日期/瞬时精度、排他边界、有效任务、前驱、原生需求/有效数量、冻结原计划及评价输入。继承成果的原完成时间与本轮真实采用时间仍分开；未知不补零、日期不补造午夜。
- 已有编号、客户、PO 名称、交期等轻量字段继续留在原表。本模型不存完整单据、用户身份或授权结论、办理能力、敏感价格工资、附件地址、单据 URL、显示名称、历史日志或当前风险/百分比。
- `0278_journey_fact_read_model` 是可重建的派生数据。源版本、已应用源版本、计算规则版本、事实摘要与业务时钟/真实构建时间分别保存；payload 限 2 MiB。版本落后、计算版本不符、测试时钟变化均不返回旧 payload 作为当前事实；摘要完整性另核验。
- `JourneyFactRepository.buildOne` 在一个明确的 RR 事务内构建/保存一单；不存在或构建失败不留下半条结果，串行版本检查保留并发冲突。提交后复用原业务时钟检查，避免 RR 内检查看不到外部已提交变更。没有普通 GET 自动回填，没有新增中间件或全库循环。

## 后续依赖与边界

本 PR **不接通增量登记、不启动后台构建、不切换页面读取**。`source_version` 初始为 1；PERF02 负责真实业务写入同事务登记、旧新关联、批量/并发/回滚、失败重试和增量覆盖。当前内部读取方法不代表用户页面已经具备修改后可见性。PERF03 必须在 01/02 和已合并时效修复基础上，先按当前权限做全范围轻量筛选/排序/KPI，再取 15 条；不得读取全部 payload 并重新逐单执行完整时效计算来冒充按页架构。详情继续按需。

节点及原生时效输入从 Final10 已修复的接口接入；计算规则版本 `JOURNEY_FACT_CALCULATION_VERSION` 必须随映射/适用性/期限语义的变化更新，受影响对象须重建后才切换。默认设置发布不回写冻结单。时间跨界的风险和自然时间进度留在读取时依原算法判断，不能把构建时风险或百分比当实时值。

回退时保持原读取即不启用派生模型，表可保留。不删除业务事实，不回退已确认时间修复。PERF02/03 启用后如切回原读取须保留待更新登记；整版旧代码漏登记后重新启用前必须重新核对或回填。
