# R3 DEF001、DEF004、DEF005：授权任务和历史页面读取

依据第二阶段报告 `R3-stage2-report.md`（Library `libfile_924498ea575c8191928ef76431e25dbb`，版本 1）。三个缺陷均为读取投影，不新增业务事实或迁移。

- DEF001：通过精确开发任务权限校验后，摘要显示该任务来源的款号和客户代码。保留订单摘要原权限；不开放来源列表、预算、同来源未授权任务或其他来源。
- DEF004：历史 DTO 保留本厂做尾类型，读取做尾完整审计快照和六节点流程。来源回货图片要求在所选历史提交前已有绑定审计；来源款图采用该时间点的外发明细。后续上传、绑定、图片替换不混入旧版本。没有历史证据时保留空值，不用当前字段补齐。
- DEF005：裁床单按原生外发行位置找到自己的母单 PO，显示自身有效工厂交期。没有 PO 映射时保持原单日期读取；整单最早工厂交期预警与合同、客户仓日期规则未改。

一次 Review 的两项发现已核验并修正：已映射 PO 的缺失日期保持空值，不能借用兄弟 PO；历史款图下载要求具体做尾单、当时来源行与可读历史节点的审计绑定，并继续执行原订单访问校验，不授予外发浏览能力。定向回归 11 项通过，含隔离原生三 PO 缺日期读取、做尾/QC 闭环、附件历史绑定 PostgreSQL SQL 允许/无关行或图片拒绝、原订单访问拒绝。缺日期夹具在隔离事务中回滚，不持久化无效业务事实。

隔离原生 PostgreSQL 回归覆盖已授权任务身份及同源未授权/其他人拒绝、三 PO 独立日期及后续原入口改期、QC/做尾完结与历史报数、历史来源图片及后上传图片排除。HTML 回归核六节点和只读内容。

本 PR 不部署、不改实际订单。上述代码与云端隔离验证不代表部署后的浏览器 UAT；实机复验由原验收主体在用户部署后继续。
