# Q02：工资源单回查与板房财务只读

## 预检

- repository: lizhonghao31-crypto/dx-rework
- base branch: main；H02 合并 59dceca57eb14ff0867db52b4bc69150dde8b5de，依赖 Q01 财务返工查询。
- working branch: fix/0915-q02-wage-sources
- scope: 从现有工资订单号定位原返工单或板房轮次/执行段，纯财务可查询板房订单。
- allowed files: 工资响应与列表链接/返回状态、板房读取权限/展示、0187 迁移、对应测试。
- forbidden files: 工资计算、工资发放标记语义、板房写动作白名单、价格管控权限、生产数据。
- gate class: FULL。

## 实现与权限

工资响应复用真实 `sourceOrderId`、`roundId`、`segmentId`，仅补充后端关联有效性。首次打板、打板返工和杂事链接原板房订单的相应轮次与执行段，返工工资链接原返工订单。不以款号、订单显示号或姓名匹配。无真实关联或关联不可用时显示不可回查并保留已返回的工资快照，不猜测跳转。

通过现有 `pattern_room:orders:view` 向工资会计、财务总监、财务全局查看授予基础和费用核对读取；列表、详情、当前角色数据库校验一致。只读身份没有任何板房写动作。原价格权限不变；工资查看能力不开放品类价格管控。

读取费用与读取制作资料分别控制。纯财务响应不包含制作文件，不允许下载，不返回技术任务说明；能核对人员、数量、工时、费用快照和完成/取消记录。混合业务角色保留原有制作资料范围和业务动作。历史轮次链接保持只读。

返回工资页面使用原筛选、人员汇总页码和明细页码；返回路径白名单限制在工资列表。Q02 仍沿用原前 500 行预览，完整服务端分页由 Q03 独立交付。现行 Root 删除测试订单后的工资清理规则保持，不将被明确作废的测试工资重新纳入财务集合。

## 验证与部署验收

修改前真实 HTTP 场景重现纯财务查看板房 403；修改后核验三类纯财务列表与详情允许、所有写能力数据库拒绝、派工 HTTP 拒绝及制作资料下载拒绝。业务链覆盖首次打板、返工、杂事、换人、历史轮次和取消费用来源匹配。工资链接测试覆盖往返筛选/页码、错误来源和外部返回地址拒绝。

本地执行完整测试、类型检查、lint、前端构建及 PGlite 业务链；原生 PostgreSQL 以当前 Head Full Gate 为合并依据。尚未生产部署，真人工资链接、手机定位及返回页面状态待负责人验收。

## 独立审查修复

本 PR 一次 Review 指出混合财务身份可能获得无关订单的制作说明，以及验收实验室尚未同步读取预期。修复按原创建人/管理范围与工人当前派工范围控制备注、返工原因和制作附件；不会因兼任财务而扩大技术内容范围。新增回归比较角色获授财务查看前后的实际订单范围，覆盖已转出的工人、当前工人、原设计师和无关设计师，保留合法动作。验收矩阵同步三种纯财务的订单读取与模块入口，仍拒绝写动作，并保留工资会计无价格管控读取权。

门禁另发现旧工资结算的隔离测试缺少板房来源表，已补齐最小建表和来源可用断言；未变更工资结算实现。完整业务迁移场景和旧独立结算场景分别验证。
