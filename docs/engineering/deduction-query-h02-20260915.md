## 行为

普通按钮按当前累计加本次金额是否超过拟扣真正禁用，上传中禁止提交。后端拒绝普通超额及旧页面携带 specialApprovalReason 的旁路；允许原有合法负数调整降低历史超扣，不允许借调整新增超扣。正常部分扣款继续跟进，恰好足额沿用正常结案。

有新金额时由独立特批入口保存 proposed_entry，冻结原累计、本次申请、日期、原因与凭证；无新金额时按 existing_ledger 处理原账本。前端不展示或要求业务员选择这两个内部兼容标识。未决申请阻止继续记账，退回后可以修改再申请。

总监通过时重核真实当前身份、台账及申请版本和账本基线，在同一事务内写入决定、唯一关联流水、异常结案及待办处理。退回新申请不入账。已有旧申请默认 existing_ledger，批准/退回均不重新生成已经存在的流水，不删除或改写旧历史。

总监专门批准该笔申请，无需获得应付会计角色。Root 原有能力保留；全局查看不获得特批。请求无有效唯一总监接收人时完整回滚；外部钉钉投递仍使用既有 outbox，不把外部失败当成再次申请理由。

本地覆盖精确累计边界、空/零/负数/精度错误、普通接口及直接 SQL 拒绝超额、旧参数拒绝、申请不入账、纯角色审批拒绝、总监合法读取、退回重提、并发审批、唯一入账、补待办幂等、申请与审批故障回滚。完整迁移后的 N01–N11 订单在返工完成后仍成功办理特批。

新迁移仅增加兼容字段与受限数据库守卫，不修改已执行迁移或历史财务事实。H02 产生新模式申请后，不应直接回退到不了解这些字段的旧服务，应使用兼容版本或向前修复。

生产真实问题单、真人双入口、钉钉收件和手机显示由用户最终部署验收；此处本地测试及 CI 不能替代生产结果。
