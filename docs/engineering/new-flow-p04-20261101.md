# PR04 — 销售系列倒排与短交期正式单

基线：`release/digital-production-v1` / `b7d3f8858dff49dab8058e26ec6bc557d0677e37`。当前授权沿已批准8PR计划连续施工、审查、验证、逐个合release；不合main、不部署。三纪要及后续决定的解释以 `new-flow-20261031-approved-plan.md` 及末尾修订为准。

## 日期与算法

- C是设计录入的客户约定出货日期，沿原逐PO日期链保存；P是独立、需明确采用的系统计划出货日期；原实际事件和SLA责任时钟另存。预览、改系列、改默认值均不写C或原实际事实。
- 系列年月先做历法月份偏移，再取合法日号。未发布具体日号时，前两个月15日仅给建议，单单采用须明确确认。全局/客户默认按版本发布，只影响之后候选；历史年份不被当前选项吞掉。
- A路线：资料交接/投料P−95，面料P−54，对色P−42；B：交接/投料P−64、面料P−33。共同客户最终批复P−44，辅料及实物款号唛P−33，发加工P−28。均为固定自然日；闰年日期平移是间隔不变的结果，不改成固定月日。
- 计划目标与模板截止分别展示。已开始/已完成节点保留此前采用目标；以前未建目标不补造。每次应用追加版本、原因、采用节点、源版本指纹；旧版保留。
- 关键路径按资料/物料并行汇合及逐PO批次估算，默认SLA只作估算依据；用户确认的本单工期独立保存。工厂生产工期、预缩或大货工艺路线未知时明确显示不完整；不按所有SLA串行求和、不推断产能、不自动压缩或移动C/P。日期型估算统一以北京时间当天结束为边界，不是实际发生时刻或开工许可。
- C早于P提示冲突；有权人员可以调整P或另走原客户改期链。改C不会回写P；改P不改C。原合同回传48h北京时间周日暂停业务时钟、船样非门禁、返工/装箱等未改。

## 短交期

正式下单以服务器/所属业务时钟的日期计算整30自然日。少于30日仅老板或Root特批；供应链总监的普通计划调整权限不等于短交期批准权限，也不改变板房加急批准链。

申请冻结客户、款号、PO、数量、C、系列及承诺基准日；批准绑定该事实摘要及开发资料版本，正式创建时重新核验并一次消耗。日期、数量或来源不匹配、场景不匹配、开发资料变版、申请已使用均拒绝。确认重试使用原幂等标识；角色失效后不能读旧写回执绕过权限。Root原生自执行例外保留。

开发创建/发布尺码选填保持不变；正式配码仍要求真实正数量。预下单仍只存草稿。已经发布但原订购信息未满足正式确认条件的档案，可以在原确认入口补齐并申请特批，不要求覆盖不可修改的开发历史；原已有效确认的完整订购依据继续保护。

## API与数据

0269为增量迁移：系列默认版本、系列上下文变更、计划版本、计划申请/决定、原业务事件引用，及短交期申请/决定/消耗。所有证据表禁止改写、删除、截断；原订单仅在显式设计资料更改时更新系列/路线及订单版本。无旧日期推断回填、无批量“历史已确认”。

HTTP入口（均在原会话、业务角色和no-store边界内）：

|入口|用途与权限|
|---|---|
|GET `series-candidate`|设计创建时只读候选，不写C/P|
|GET `orders/:id/series-plan`|完整订单读范围内的状态/历史；单一任务权限不扩为整单读权限|
|POST `…/preview`|纯预览；令牌绑定订单/计划/源资料/实际事实/配置/业务日期版本|
|PUT `…/context`|原创建设计/Root明确改年份、系列、对色分类；不自动改P|
|POST `…/requests`|设计、主跟单或原管理岗位提出计划申请|
|POST `…/apply` / `…/requests/:requestId/reject`|供应链总监、老板、Root按现有权限确认；申请人不自行审批自己的申请，保留Root例外|
|GET/PUT `series-profiles`|原时效管理岗位读取/发布新默认；不追改在途|
|GET/POST `sources/:id/short-lead-requests`|设计办理本来源的正式短交期申请与记录|
|POST `…/:requestId/decision`|仅老板/Root；原会话/来源/业务场景再次校验|
|`short-lead-requests`|无来源正式单的同一契约；管理设置内老板/Root集中处理可见申请|

所有变更沿原命令表幂等；同key不同内容拒绝，回执重放前重新核权限。预览过期/源变版返回409，需要重新读取并预览；服务端不从客户端接受自由依赖图、源事实或全局生效指令。

## PR05真实事件交接（无依赖循环）

PR04拥有 `SeriesSourceEvent` 和事务内 `appendSeriesSourceEvent`；PR05接原授权办理命令，在同一业务事务追加引用。没有通用HTTP事实填写接口。`sourceRecordId`应使用该节点的稳定原记录/聚合头，`sourceVersion`为真实原版本；后续订正须指向当前同节点/同范围头、相同来源域/记录且版本递增。不能用新的任意文件或另一个记录冒充订正。

未接新生产者时，已核原验布到仓、当前轮最终客户评语、仓库实际发厂为只读回退；其余新实际节点显示未记录。一个节点/范围接入版本化事件后，以该事件头为准，包括撤回/未知时间；不继续叠加旧回退记录形成两套真源。部分发厂不推成整单发齐；工厂到料/清点不是本PR实际依赖，也不因此恢复即将退役的F02/F03。

只有日期就保存日期精度，时间未知不拿`recorded_at`补；SQL审计时间保留真实录入时间。实际事实或原技术有效依据变化会使旧预览失效。Journey仅作只读计划节点投影，排除执行完成分母和原放行门禁；已结案保留历史，不新添未完成阻断。
