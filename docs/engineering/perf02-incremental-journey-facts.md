# PERF02 事务内增量登记与单对象构建

批准来源为已恢复的 PERF01–09 最终修订施工单，01→02→03 为硬依赖。实际基线为 PERF01 合并 `7ed45f6507907c59e120330efcac384bc4acd219`，本分支 `perf/02-incremental-journey-facts`。本 PR 只接通更新可靠性，不切换正式列表、不部署、不操作现场业务数据。

## 更新机制与边界

0279 在实际原生写表登记变更，使用同一业务事务、同一对象及事务 ID 去重。原生写入只追加独立登记，不锁共享摘要或 worker 行；回滚同时撤销登记。关联变更分别解析 OLD、NEW 的原生父对象。映射是迁移中明确列出的静态关系，运行时不扫描 schema、不按款号猜关联。没有把角色授权结果、金额、完整单据保存在模型中。关联反查复用原 `(module,child_id)` 主键；任务前驱、指派人员及继承附件的反查补必要索引，不在每次业务写入时扫描全部关联。

处理器最多选择 16 个对象、2 个构建并发。每单独立 repeatable-read 事务和事务级 advisory lock；业务写入不使用这个锁。90 秒单条 SQL、100 秒构建连接上限保留终止与回滚。失败只对该对象退避重试，登记不丢，其他对象继续。错误只保存固定错误码，不记录业务 payload 或异常秘密。

完成时只删除本次快照实际看到的登记，不使用自增号或最大事务号作为“之前都已处理”的水位。较早分配事务号的事务可以较晚提交；构建期间新提交的变更继续处于 pending。sourceVersion 表示已发布构建代次，pending 的精确依据是尚未确认的事务登记；重复无变更构建不增加代次。相同对象的构建互斥，没有可过期租约及旧持有者覆盖新结果的问题。

读模型状态在原有版本、计算版本、时钟版本、内容摘要之外核对 pending 登记；存在登记时不返回旧 payload。正式页面仍走原读取；下一项 PERF03 再接通页面的真实“更新中”状态、全局轻量筛选、统计和按页读取。

初始化登记与计算分离。迁移只登记已有对象，后台分批构建。日常真实业务变更优先于初始化回填，避免大批回填阻塞刚修改的订单。启动时游标批次最多 200 个，只补缺失模型或计算版本不符的对象；普通 GET 不登记、不构建全库。整版回退若漏登记，重新启用前需要显式 `registerBackfill(cursor,200,true)` 完整登记核对，不能假定一个计算版本相同的旧摘要仍新鲜。

当前时间自然推进不反复构建所有对象；沿 PERF01 保留的权威期限、原生窗口及冻结输入交由 PERF03 按原算法评价。Acceptance 显式时钟修订只登记场景关联对象。全局默认标准发布没有回写冻结单；显式采用、更正、路线变化由原生写入登记。已经完成的时间事实修复和原业务权限保持。

测试进入原 canonical plan，沿既有 100 秒 correctness 预算。普通 SQL 迁移不增加历史备份恢复演练。验证日志、实际通过范围、正式 Review 和最终 Gate 在本 PR evidence/正文记录；不把本地测试当现场或 1000/5000 性能验收。

## 最终 Full 暴露的实际兼容问题与集中修复

首次 Full 42463338818 对 fc81d4b7：非数据库分支成功；数据库在原完整业务链路有7项失败。首个失败是成员分权真实绑定的审计对象键 `0915` 被新 trigger 强转 UUID，绑定事务回滚后，后续权限断言连带失败；空文本对象键也受影响。这是实际写入兼容错误，没有改断言或放宽权限来迎合它。

修复只对通用审计/待办的文本对象键使用严格 UUID 解析函数：合法原生 UUID 继续解析，其它文本返回无关联。不能只靠 SQL WHERE 保证转换安全，规划阶段可能先折叠转换。原通用审计对象键、合法审批及成员分权保持原样。新增原 OperationEventRepository 回归保存 `0915`、空文本、角色键和非法36字符，确保不误登记其它订单。原完整60项链路须以最终修复候选再次验证，不能把首次失败或旧 head 的结果称为通过。

同批审计身份变更链：只在 enabled、manual_access_disabled、active、employed、用户或有效角色变化时失效；姓名、验证心跳及未变 eligibility 的刷新不重建全部指派订单。原生撤销岗位仍精确登记，元数据刷新不产生 pending，二者由同一个原生场景验证。

正式 Review 覆盖 fc81d4b7、回执6719257385/6719279927，无发现；上述后续修复由执行者定点复核及原生回归覆盖，不能称为旧回执已重审修复提交。最终新 head 的必要 Light/Full 另行绑定；无部署或现场操作。
