# 本人授权工作区的必要读取修复（2026-10-12）

## 问题与行为

普通 IE 在 N05 已获准读取本单执行事实、记录返工工序预核，但办理区先读取只向尾部主管或有效代理开放的正式数量确认摘要。摘要返回 403 后，预核入口也被挡住。前次浏览器夹具把这一步错误模拟成 200，因此只验证了后续整查读取的隔离。

本次保留正式确认服务的阶段、角色、capability 和代理判定。IE 已成功读取本单执行事实，且仅在 N05 正式摘要返回 403 时，办理区使用既有工序进度和 IE 预核控件。稳定拒绝回调从首个渲染提供，即使 403 先于执行事实返回也先记住拒绝结果，再按当前订单及 N05 授权事实选择视图。切换订单后忽略旧事实、旧摘要或旧拒绝响应；不同订单的摘要请求不会被旧请求阻塞。预核仍受模块可写和服务 `canRecord` 限制，沿用追加记录 API；整查工序无预核写入口，不产生正式数量修改、任务报数、人员调整或流程推进。Root、合法混合角色及有效代理读取摘要成功时继续使用正式办理区。N06 及历史预核保持只读。摘要 404/500、执行事实读取失败及后续整查错误仍显示真实错误。

普通纸样师、仓库人员已经可以读取本人产前任务及大货产前聚合，但聚合页另外请求带开发轮次的完整 Journey。显式历史轮次要求开发来源权限，普通执行人员缺少该权限，导致必要款式资料区域失败。

本次聚合服务在原 `order/technical` 授权后返回固定的小型 `reference`：款号、客户代码、款图链接、制单版本和来源轮次。图片与快照来自本单当前已发布制单，且发布来源轮次必须与当前来源轮次匹配；没有匹配制单或该版无款图时不给其他版本、开发来源或其他图片作为替代。无匹配制单时仅保留已授权本单的最小款号/客户字段。前端再次核对引用版本与聚合版本、轮次一致后显示图片，不再请求完整 Journey。图像链接仍使用原制单附件端点，保留订单技术权限和发布图片成员校验。数量沿用原裁床条目；不返回整个订单快照、预算、商业资料或其他任务。

## 保留的边界

- 不改正式数量确认、任务读取、任务历史、开发来源、Journey、制单附件或预算权限策略。
- 不通过去掉轮次参数读取其他轮资料，不恢复同单其他人的任务读取。
- 原派工、完成、制单发布、预核审计和业务状态机保持。
- 本次目标分支为 `release/digital-production-v1`，部署由业务负责人执行。
