## 实现及必要修复

- 新增 0182 迁移，按明确列举的业务读取能力授权，更新实际白名单。未复制财务总监角色或写入能力。
- 每笔实际扣款及每次特批请求按各自附件编号显示图片/文件；复用现有图片查看器和鉴权预览/下载。描述信息批量查询，不按 UUID 逐个查询。
- 原总监特批请求携带新附件时，会被旧的附件绑定动作白名单拒绝。0182 仅加入既有 `rework.external_deduction.special.request` 动作，保持一次绑定、本人上传、ready 状态、订单及审计事件校验与绑定后不可修改。
- 订单通用附件列表和直接下载均校验 `external_responsibility_can_view_case`，应付会计不能利用同一订单的读取权限访问其他责任类型凭证；上传人也不能绕过绑定后的业务鉴权。
- 返回历史批次和各次特批的只读记录，复用生产继承链的数量快照规范化与重判关联补充；历史批次不能重新出现操作按钮。当前版本中沿用的原扣款保留原凭证归属和审计事实。
- 缺少凭证元数据或图片加载失败时显示明确错误，不把异常显示成“无凭证”。不修造、不重绑历史附件。

## 验证与交付边界

本地检查包括 TypeScript、ESLint、迁移校验、现有单元回归及新增读写权限测试。隔离 PGlite 回归使用完整迁移、真实 N01–N11 业务链和 Fastify HTTP：合法读取/下载、跨责任拒绝、纯 finance_read 特批拒绝、工资标记授权保留，以及历史批次和多次特批凭证回看。PGlite 不替代原生 PostgreSQL 的 Full Gate。

真实生产版本、具体问题订单/附件对象及手机表现没有在本 PR 中操作或宣称验收。生产历史缺失附件只做定位后按对象处理，不进行全量回填。Root 和混合角色的其他合法操作保持。
