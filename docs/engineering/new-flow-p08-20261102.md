## 实现与真源

- `GET /digital-production/journeys/:id/node-materials?instanceId=…&round=…` 先走原 Journey 身份、订单/轮次/实例可见性，再在同一个 `REPEATABLE READ READ ONLY` 事务中读取原领域。未知/外单/不可见实例不枚举原件；接口 `no-store`，没有清单写接口。
- 输入、产出、参考，是否适用、资料状态、责任岗位/人、时点与动作影响分别返回。只有原节点 blocker 被解释为原门槛；资料列表不反向改变能否办理。
- 制单复用 `productionReadiness`、`instructionTechnicalCurrent` 和原制单版本；预算不是制单额外前提。技术使用 `effective.artifactRef` 及对应最终评语/复核，不取最新上传代替采用版。纸样完成的 PLT/结构用量/基码与客户最终批复区分。
- 款号唛逐 PO/颜色复用 `styleLabelCuttingReason`，局部纸样/唛架引用当前 preparation 范围；不把局部完成说成整单可开裁。到仓未知/撤回和失效凭证头不回落旧 ready。
- QC 逐厂单和 PO 读取原窗口、正式进度、关联照片，沿原角色办理；照片、比例与实际产量均不冒充成衣质检。仓库实收、质检、装箱/差异引用原收货模块；不列财务或责任签字为装箱前提。船样及退役工厂到料/清点没有混入当前必填材料。
- 已结束任务/旧轮次只显示原节点留存的版本链接。无冻结版本的历史明确待核，不借当前新版本变绿。未专门展开字段的旧节点保留原 blocker 与原记录，明确链接不证明原件完整有效；不猜造要求。

## 页面与交互

原导航、款图、七阶段、三栏、办理按钮和原字段保留。当前节点下显示精确名称“该节点所需材料一览”，首次默认折叠；折叠不读取材料元数据，也没有隐藏可 Tab 控件。展开可筛全部/待处理/已有效/我的；主办理始终沿原入口，不藏到二级窗口。缺项行打开原资料，物料链接可定位原表单对应办理项；不重复上传、手工勾齐或新增待办。

UI 偏好按身份、订单、轮次及具体节点分开，只保存展开/筛选/滚动/焦点。切 B 首次折叠、回 A 恢复 A。返回原办理上下文通过既有 returnTo 校验链；URL 本地字段不进入后端列表过滤。首次登录核验完成只接管原 UI 偏好；真正身份切换清空，不复用元数据。展开、重开、原保存返回和原刷新重新读原权限；晚到的旧节点/身份响应丢弃。读取错误单列失败，不显示成资料缺失。局部 CSS 沿原配色、字级和间距，不改全局样式或组件库。
