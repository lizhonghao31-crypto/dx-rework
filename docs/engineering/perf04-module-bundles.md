# PERF04 业务模块与页面样式按需加载

批准来源为全系统性能最终修订施工单（PERF04），与 PERF01→02→03 读取主链隔离准备。此分支最初从 `acc029d6f580f7d471dc3343db9b1235bd926e4a` 准备；提交前必须接入前三项实际合并基线，不能以准备版本的结果冒充最终版本通过。不部署、不修改现场 Nginx、进程或业务数据。

## 范围与实际行为

外壳、身份、导航和权限判断仍走原 App。52 个业务页面、表单及工作区改为类型保持的动态入口，Acceptance Lab 独立加载。只有原有权限与路由选中页面后才请求模块；没有为所有页面预取代码。Vite 根据真实模块依赖拆 JS/CSS，公共组件及共享样式继续复用。加载完模块后恢复原主入口公共样式顺序，避免异步 CSS 把原全局基础规则移到错误优先级。

草稿及组件 key 沿用原逻辑；lazy 组件身份在工厂创建时固定，普通父组件重绘不卸载表单。模块下载失败局限在原外壳内，只提供用户主动刷新。浏览器会缓存同 URL 的失败模块读取；重新创建 React.lazy 不能可靠重试，因此没有误导性的“重新打开”或自动刷新。普通业务渲染异常不会伪装为网络加载失败。

## 更新后的已打开页面

仅在当前哈希资源未找到时，Nginx 示例配置尝试 `frontend/previous-assets` 的上一代资源；未知文件仍为 404，不返回 SPA HTML，也不读取附件、API 或业务数据。该位置内部使用，禁用请求行日志并保留静态资源安全头。它不新增跨用户业务缓存。

激活前，部署库从**当前实际对外服务的前端目录**选上一代，而不盲信可能遗留的 active/generations。只接受固定根内、40 位 SHA、manifest/checksum 验证过的 `frontend/releases/<SHA>/assets` 或 `frontend/source-releases/<SHA>/assets`；通过单个原子软链接保留，不复制文件，不改写不可变发布包。安装 inactive 包本身不切换兼容指针。原允许自动恢复的 activation 失败会同时恢复原兼容指针；原数据库兼容性、维护闸门和人工恢复边界保持不变。

源码布局的后续正式构建为新前端生成 checksum。既有旧源码前端没有 checksum 时，首次转换不补造验证记录、不修改旧树，其旧页面依靠主动刷新恢复；之后保留一代已校验资源。超过一代的旧页面同样需要主动刷新，不无界保存或复制全部历史资源。

Nginx 模板变更不会由业务更新自动安装或 reload。真正启用上一代资源回退前，需要用户在现有基础设施窗口按原手册备份并同步当前实际使用的 vhost/标记块，执行 `nginx -t` 后批准 graceful reload；routine 更新仍只切换自身前端指针。未同步模板的环境，旧页面仍可以主动刷新恢复，不能宣称现场已有兼容回退。

真实浏览器用例进入原 canonical plan，沿原 correctness 预算和精确资源清理；没有另建一套验收平台。部署执行器变化按仓库规则做相关生命周期与恢复验证，不以“业务 PR”豁免。1000/5000 座舱规模不在本 PR 重跑；与图片优化相关的正式首次、缓存及模块切换比较集中在代表集成版进行。

本地准备中曾实测原正式构建与拆包构建的实际首次资源量，但仅为隔离 loopback、未压缩单次观测，不是现场延迟、P95 或稳定收益承诺。原始日志和精确版本留执行记录；最终提交的结果另行绑定 evidence 和 PR。

## 回退

可恢复原页面导入方式，业务事实、附件及时间修复不变。兼容软链接只指向保留的上一代，不删除资产树。撤销 Nginx 模板须走原基础设施窗口；代码合并不执行该操作。模块资源失败只在真实发生时提示，正常页面不增加技术说明或已删除的“依据/采用版本”入口。
