- base branch: main；依赖 Q01 财务返工查询和 Q02 工资源单链接。
- working branch: fix/0915-q03-wage-pagination
- scope: 网页可翻查完整工资明细，保持原汇总、导出和结清确认范围。
- allowed files: 工资查询契约、服务端分页、工资列表、共享现有分页条数、相关行为测试和交付文档。
- forbidden files: 工资算法、月结状态机、新付款/调账动作、其他模块重构或生产数据。
- gate class: FULL；本 PR 无新迁移。

## 行为

工资列表通过原报表读取接口带独立页码。每页沿用现有 `LIST_PAGE_SIZE=15`，常量由契约包和原分页组件共同使用。数据库按完成日期、姓名、唯一明细 ID 稳定排序；读取当前页、全量汇总和总数在同一查询快照完成。超出末页的请求返回真实末页；空集合返回第 1 页和 0 条。

页码不进入业务筛选。人数、订单数、轮次、来源构成和工资总额始终按完整筛选集合计算。导出仍独立鉴权并使用原全量范围；结清仍使用原筛选与用户确认的具体明细 ID，确认之后新产生的明细不会被自动包含。结清接口拒绝夹带分页字段，防止将页码误解为结清范围。

没有页码的旧读取请求保留原预览兼容；新工资网页使用服务端分页并移除前 500 条提示。其他报表继续原分页/预览行为。Q02 的源单返回筛选和页码保持可用。

## 验证

修改前真实 HTTP 请求携带页码返回 400。修改后使用真实打板创建、完工、交接的隔离测试单及 501 段历史测试数据，遍历全部 34 页：501 个唯一 ID，无重复/遗漏；末页 6 条，越界返回第 34 页；各页金额 560.00、人数 2、总明细 501 始终一致。

同一筛选在第 1/34 页取得相同的结清确认 ID 集合。导出仍包含 501 条；后续新增的返工明细保持未结算，原确认 ID 不自动扩张。测试数据不是生产订单或真实工资。

执行本地完整测试、类型检查、lint、前端构建、PGlite 26 项业务链；Full Gate 使用原生 PostgreSQL 执行原有外发、样衣、回货、生产等业务回归及对应权限测试。对未出现断点的模块没有改动或新增财务权限。

## 最终部署验收

1. H01：同一普通会计从返工原单和钉钉深链打开同一台账，核对历史、附件、金额和权限；没有原始校验 JSON。
2. H02：普通超额不能提交；填写金额/原因/凭证后申请特批，纯会计无法审批；总监批准采用该金额，退回不增加新申报扣款。原已完成返工单的有效未结案台账继续处理。
3. Q01：各会计无需待办即可从固定返工入口查单；无本类责任、混合责任、已完成及历史重判分别核对；另一责任方凭证无法读取。
4. Q02：工资明细的返工/首次打板/返工打板/杂事链接到真实原单与轮次，手机能定位执行段，返回保留筛选和页码；纯财务无制作原文件或写动作。
5. Q03：大于 500 条的真实筛选可到达末页；换页不改变总额/人数，导出和结清确认仍按全量筛选。
6. 已正常模块：外发核对后历史回查、样衣借还/处置历史、回货跨日期、供应商资料和生产关联按原权限核对。
