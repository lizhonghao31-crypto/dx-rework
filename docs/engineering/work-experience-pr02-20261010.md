# PR02 母单创建与开发单编辑

创建页原来把每次数量输入立即转为数字，清空后会回到 `0`；创单没有款图入口，尺寸表只能新增。本次让订购数量一直保留可编辑字符串，提交时才转为原契约要求的正整数；通过现有数字开发上传、finalize 和草稿保存接口把创单款图绑定到同一个 source。订购保存失败重试沿用 source 和已上传附件，不二次上传。

## 实际行为

母单设计款号与代用号录入一次；PO 代用号为可选独立覆盖，未填时沿用母单代用号，正式 PO 始终是独立字段。每 PO 的颜色、日期和尺码订购数量用表格编辑。移除 PO 或已填尺码会确认；取消离开会保留当前输入和选图。创单图片选择后可预览和移除，保存时上传；失败保留其它资料，成功的图片在同一个开发草稿复开查看。

创单明确选择上衣/裤子模板，不从男装/女装等产品分组猜服装类型，不把订购数量带成打板数量。开发单与打印显示本轮打板数量、本轮打样尺码和预计样板完成日期，仍用原字段。

尺寸行列可以删除，删除列同时移除所有对应数值，删除已填内容需确认，旧版本对象不被修改。新增列以空名称等待录入；草稿允许空尺码名，发布时定位未填列，原重复尺码和矩阵校验继续有效。尺寸原始字符串、分数、单位和精度保持原值。

窄屏附件选择器限制在父列内，避免原生文件输入框把 390px 页面扩到 504px；技术表格仍在本身的容器内横向滚动。

新增可选 `washingMethod` 与 `ironing` 技术说明；免洗时隐藏洗水详情，整烫独立可填。既有 `washingIroning` 原文保留并单独展示，不猜测拆分历史文案，也不覆盖历史版本。旧 JSON 不需要新字段。草稿没有办理记录入口，已发布单据的历史与实际办理仍可达。

附件沿用原服务端 source/设计师/Root 授权、用途、归属、版本与发布校验；款图/局部图仅图片，菲林/工艺开发板沿用 PDF 范围。上传复用字节类型识别及原有完整分辨率失败恢复，服务端真实内容验证不被替代。
