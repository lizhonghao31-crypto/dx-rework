# PR04 原打板准备与数字开发办理接续

原流程允许先核配、纸样、裁板，直到车板完工才发现原执行单或主管工资派工尚未建立；关联车板完工又提前生成无法办理的旧收板待办。本次在开发正式发布时复用原单同一事务建立执行准备，并把主管正式派工作为新车板任务的独立启动条件。

## 范围

目标 `release/digital-production-v1`，继承 PR03 同页办理；FULL，核心状态流转与原工资归属需要一次 GitHub Codex Review。无 migration、工资新表、部署、重启或真实数据操作。施工图片只作结构参考，示例值和旧文案不覆盖 MD 正文及原业务来源。

## 行为

- 草稿发布前显示有效品类及原执行价格；发布携带读取到的价格版本。正式发布、文员核配任务和原打板执行单处于同一事务。缺少准备、停用品类或过期价格均回滚，不留下已发布单或孤立任务。沿用原设计师/Root 创单权限及原价快照，提交幂等键在同一 source 上去重。
- 执行区显示原品类/价快照是否保存以及主管已确认的执行师傅，不向文员或普通任务办理人下发工资金额。主管同页派工沿用文员预派人作为可修改建议，只有原 assign 成功才确定原工资归属；清空或另选不会被建议值反复覆盖。
- 新车板任务必须同时满足真实料齐、交接及 `pattern_assignment_ready`。主管先派工不会替代缺料，料齐也不会替代主管派工；全部满足才进入 ready 和开始 SLA。原历史任务及计时不回填。
- 数字关联车板完成只记原工作完成，保留实际执行人和原工资归属人；后续洗水、尾查、设计最终确认继续沿用数字链。关联单不提前创建原收板 actionable 待办，最终确认仍调用原 handoff，原工资资格只释放一次。独立原打板及杂事沿用原处理。
- 尾查合格时隐藏并禁用退回节点/问题；退回时才显示具体节点及分类并要求原因，切换结果保留人工选择。
- 关联原单返工要求明确受影响节点及问题分类；同一事务创建原返工工作轮和局部数字复版，保留前轮完成证据，只重走必要工序。原主管仍明确核定返工金额，数字轮次不自动复制工资。过期轮次、暂停/取消来源或不适用洗水节点失败时整体回滚；开裁冻结边界和独立旧单不变。
