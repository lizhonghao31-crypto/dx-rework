## 最新执行决定

用户随后明确要求“以后所有这种场景的时间都调高一点，例如100秒”。因此后续同类重型/原生浏览器正确性test与hook共用100000ms；PG测试显式15/20/30/45/60秒包装同步引用该权威值，既有120/240秒等更大预算不降低。普通/性能Vitest默认、页面单操作等待、业务SLA/性能断言及外层终止/清理分别保留；不能把提高正确性超时当产品性能达标。P06已通过的拆分不重做。

## 接入与最终请求前，一次集中收齐

1. 从实际 base→candidate diff 列出所有新增/修改测试、最外层 test/it、CLI、父runner和被调用矩阵；查全调用方和旧消费者。记录外层预算、内部场景数/依赖及每层超时，不能只看 Playwright 某次点击的预算。
2. 分开记录 fixture/迁移、构建、服务启动、场景、完成检查和清理的实际成本；保留逐项耗时及失败日志。慢段归因不明时做最小同版本对照，不能把整组预算、单操作等待、锁争用、终止或清理混成一次偶发超时。
3. 对照锁文件与 CI 的 Node/npm、Playwright/Chromium 精确版本、原 Vitest 配置、解析后的 worker 上限、实际有界并发、CPU 及数据库资源。记录实际使用值和日志/报告来源；没有同版就明确未验证，不能用本机新版通过替代 CI 同版反例。
4. 多场景总成本有超过外层单场景预算的风险时，按真实依赖拆成可定位的有限场景。共享 fixture 的连续流程可用原迭代器顺序驱动；场景顺序/对象、完整列表、末尾完整性必须校验。独立场景不强加串行依赖，不重复初始化重型 fixture。单项卡住仍须有限边界，整组成本仍须可见。
5. 保留全部业务与反例：保存成功/失败、实际权限允许拒绝、原认证同有效会话撤权、同/异 key 并发、事务回滚、已知和未知结果恢复及导航/迟回隔离等本 PR 相关范围。不得用删场景、强制点击或放宽业务守卫换取通过。
6. 核创建、登记、正常/失败/未完成迭代的收尾。完成检查须在原 finally 真正收尾后才通过；不把资源交回当删除。父runner按原manifest及已核库身份清理，worker未退出或归属不明时保留证据，不扫描猜归属清库。
7. 在本 PR 的实际合并基线与最终组装源码下，用仓库原 canonical 入口、同版浏览器、原超时和有界 worker，对受影响新旧组合做接近 CI 的预验。能共享一次组合就不重复 mapped/chain；无关有效结果按原明确输入协议复用，禁止跨 Head 拼接 GitHub Gate。
8. 汇总命令、实际 testedHead/source、原报告及摘要、通过/失败/跳过、逐场景和整组耗时、资源清理及尚未等效条件。检查全 diff 和全部已知发现，冻结候选、fresh 检出、light及原最终请求协议通过后再申请 Full；已知未完成的候选不发 Full 调试。

## 环境边界必须明确

同版浏览器、命令、配置、worker上限和有限超时可以逐项核等效。给 Node 及继承的浏览器进程设置两个 CPU 的 affinity，不等于限制 PostgreSQL、宿主内存/IO，也不等于 GitHub 整机硬件。隔离 schema 不表示数据库实例级资源没有竞争。前述不足应记录为实际限制，不能用一段说明代替同版原入口预验，也不能宣称本清单保证所有未知问题为零。
