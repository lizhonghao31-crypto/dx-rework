## 范围与确认口径

所有订单跟单可在现有看板处理两类差异；仓管取消差异处理权限。差异处理只保存处理结果与凭证，不修改数量。仓管首次录入装箱数，所有已录数量只允许 Root 修正。未改变收货新增、再次收货、补录及 Root 收货修正流程。发现旧装箱接口将录入、改数与差异处理合并授权，本次按用户澄清拆开这三个边界。

允许修改：回货 UI 权限、HTTP/Service/SQL 鉴权、0190 迁移和 manifest、验收权限矩阵及对应回归。禁止：金额、返工/外发状态机、无关 UI、通知配置、生产记录和真人角色。

## 实现

复用 `receiving:resolve_difference` 授予订单跟单，收货及装箱差异统一使用此权限。保留单一差异处理弹窗与两本现有不可变流水；无订单归属限制。`receiving:packing_manage` 只承担装箱数量录入，首次给仓管；重复改数同时在前端、服务端和数据库检查 Root。数据库重核当前有效身份，失效/伪造角色和旧会话不能沿用已撤权动作。幂等、版本与当前数量快照校验保留。

## 验证与部署验收

定向覆盖两位不同订单跟单的两类处理成功；仓管、尾部主管及无关角色拒绝；普通角色不能通过数量接口改数；Root 可以修正并继续处理；处理前后原数量不变；历史与重复提交保留。完整迁移与业务链、原收货回归、类型/lint/build 及 Full Gate 后合并。权限 PR 仅一次独立 Review。

本地验证：完整测试 1579 通过、269 环境相关跳过；PGlite 收货及完整业务链 64 通过。PGlite 单连接不能模拟主线已有的板房删除/工资标记并发测试，仅本地临时配置排除该项，仓库未增加跳过；由 Full Gate 原生 PostgreSQL 完整验证。类型检查、lint、前端构建、迁移清单校验均通过。
