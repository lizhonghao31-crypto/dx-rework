# 影响范围影子清单：第一阶段

本阶段的验收目标是为“无关改动带出大量测试”建立可核对的候选清单与反例。清单不参与任何测试命令、风险等级、原 Gate 校验或最终批准。PR #899 保持原候选与 Full 记录，本实现从实际 release 基线单独施工，不把其拆分结果或旧 Full 计为本提交验证。

## 当前执行边界

release 的风险映射已经决定 mapped PG、固定业务 chain、迁移、Journey PG13、Root 及部署/恢复等检查。Full 的非 DB lane 仍执行配置中全部非 DB 文件；PG 仍使用原 canonical union、角色、版本、历史及恢复上下文。#899 的离线部署 22 场景条件化属于另一候选，本分支未引入它，也未引入其 91/50 数据库拆分。

## 有限试点

只接受单个已知纯格式入口 `apps/api/src/production-platform/development-document-format.ts` 的 M 状态差异作为候选分析。它是现有 Full 适用的 API 入口，避免为影子另触发 Full。五个直接服务消费者（开发单、复版、执行、纸样订单、资料补正）、两个旧单元测试文件、已知补正 PG 消费者、锁文件、配置和 workspace export 定义固定在策略中；任一漂移需人工复核，否则回退。独立的 18 项应测目录来自逐源码读取既有业务用例，不从收集结果或绿色报告反推。6 个原收货参数行仅补稳定 `caseId`，全部原输入、断言和顺序保留。

图扫描识别静态导入、workspace source alias 和字面量源码读取。文件读取器、子进程调用和无法静态识别的加载器连同其消费者保守纳入。已人工核对的必要边另列在策略中；它们缺失时，即使遍历碰巧仍选中测试也回退。入口新增 import、运行时 loader/global、语法错误、不支持的参数声明和工具版本均回退。策略还绑定本次审阅的 release base；base 前进即回退，复核依赖后才能更新绑定，不能悄悄继承旧映射。

任何其他路径、共享依赖、A/D/R/T、空或异常差异，以及参数行缺失、重名、相同数量替换、固定输入漂移均输出原完整清单。即使产生候选，PG 清单仍逐字保留原计划。候选只为后续审阅提供拟排除文件，不能证明没有隐式依赖。

## 证据流

prepare 在现有完整输入包内记录影子清单，沿原包摘要、准确 head/base、run/attempt 和构建凭证传输。non-DB lane 完成原完整运行后，对照原生 JSON：核准确原文件集合、独立目录每项唯一且通过，记录“拟排除文件中实际失败”的漏选反例。报告缺失、上下文漂移、未知状态、失败、取消或原生报告不完整均不能形成已观察对照。

`impact-shadow-plan.json` 和 `impact-shadow-observation.json` 随现有 artifact 上传。分析器异常记 unverified；原 Gate 的失败、缺阶段、资源清理、环境及回执检查保持原行为。影子状态无权将失败变绿，fallback 也不等于已验证候选。

核旧消费者发现：`development-amendment-service.ts` 调用入口的 `legacyAmendmentPublicationOptions`；`development-amendment-postgres.test.ts` 有旧快照补正等实际消费者回归，但原规则对只改该入口的差异未包含此文件。策略单独列这个已知 PG 文件义务，和图推导分开；候选与原计划对照时输出 `knownPlanGaps`，即使非 DB 完整且全绿也不能掩盖缺口。该文件级义务不是完整 PG 用例目录，计划包含也不代表已实际执行。

此缺口经后续必要纠偏补齐：风险映射的 `DEVELOPMENT_AMENDMENT_INPUTS` 列出 22 个已核对的格式、补正、HTTP 转发、有效资料读取、退回补料、路线/复版、权限策略、纸样数量及相关契约入口；源码单改即映射到原补正 PG 文件，并和原 chain 去重。新增直接补正领域依赖有静态漏边回归，未知其他领域/共享配置仍保留原 chain，不宣称该 chain 覆盖所有 PG。未将该套件永久加入所有 chain，也未用影子清单控制执行。根入口候选的 PG 计划因此从 21 增至 22 文件，独立义务检查不再报告这个已知计划缺口；回退/缺边/缺项告警继续保留。25 项业务用例体、权限/回滚/幂等断言和执行配置/worker 未改。

补正 PG 首次定向执行实际为 4 通过、21 失败，集中在旧公共 `prepare` 夹具发布前：空尺码列对应了两项数量，辅料类型也使用过期值。仅修正夹具的两列尺码/尺寸矩阵和现行枚举，增加 schema 合法性前置断言，并把原始 schema DDL 改为既有受管创建/交回 API。未更改业务实现或放宽校验。修后使用新鲜、带标记的低权限 PG16.15 实际执行原全部 25 项，逐项与原声明和用例体对照；父 runner 验证受管 schema 精确清理，一次性容器已删除。原失败日志保留，未用首次运行的 4 项与修后结果拼接。

正式收口前另补齐继承的解析阻断：仅纳入 #899 的 `f7507d80` 中 `final-closeout.mjs` 与对应回归文件，逐字一致。完整 JSON 报告仍按原生结果校验；混合日志先扫描全部独立 JSON 行，再选择文本/TAP 汇总。合法初始化元数据可和横幅交错，失败/截断 JSON 即使出现在横幅后、摘要后或 TAP 前也不能被掩盖。原始日志摘要、结构化报告摘要绑定、用例身份和精确数量要求保持。该纠偏不依赖 #899 的 sourcing 拆分或离线部署条件化；后续两 PR 如整合，须核共享文件并重绑准确 base/head，不能复用旧 Gate。

## 负控和后续收口

本地负控覆盖独立必要边缺失、参数缺行/重复/同数量替换、空参数族、删除/重命名、未知/共享路径、非法 NUL 输入、版本与来源漂移、混合 head/run/attempt、原生用例跳过或替换、拟排除文件实际失败。现有 Full 非 DB 校验同时确认该失败仍会拒绝。源参数声明与独立目录分开读取，原六行去除身份元数据后与基线逐字比较。

下一次本来必要的 Full 才采集远端对照，不为影子额外启动 Full。本分支自身包含共享 CI 差异，预期输出 fallback，不能拿它的绿色结果宣称根入口选测安全；根入口候选路径先用明确标注的本地合成差异验证。映射纠偏另做本地定向及必要隔离 PG 验证，不借用旧 Head 的 Full。若未来要激活减少执行，必须另行审阅真实差异覆盖、历史缺陷/变异负控、隐式依赖、参数实例及其他上下文的独立应测范围。

当前原生 JSON 只能观察声明用例的运行状态，不能证明回调内循环、每个断言或任意动态生成用例已完整执行。本阶段没有独立的全仓 D 收集器，也没有证明全仓 E/D/R 完整或未来零漏测；保留原 11 项接受套件跳过的原状与未验证边界，不将它们转成新豁免。影子阶段不会直接缩短 Full 时长。可量化收益先看自然 Full 中拟排除文件、其实际耗时和关键路径，不能把累计耗时当作墙钟收益。
