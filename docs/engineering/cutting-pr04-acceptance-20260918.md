# PR04 订单回货看板实裁联动验收清单

**日期：2026-09-18**  
**范围：** 订单开裁与实裁收货联动 PR04，仅看板展示与端到端收口。

## 1. 数据事实

- 新链路行按 `cutting_order_id` 独立聚合；历史无关联行仍按款号读取。
- 实裁数来自 `current_cutting_records.actual_cut_count`，Root修正后显示当前有效值。
- 裁床登记人/时间来自最初 `cutting_records.recorded_by / recorded_at`，修正后不变化。
- 历史无实裁显示“—”；真实0显示“0件”。
- 实裁不进入收货差异、装箱差异、KPI、责任或扣款计算。

## 2. 卡片布局

宽卡数量顺序必须为：实裁数、送货单数量、实收、次品、收货差异、装箱数量、装箱差异。

人员层必须保持原卡片，不新增大框；顺序为：款号/状态、裁床登记人·时间、收货人·时间、装箱确认人·时间、原操作区。

卡片可用宽度低于840px时数量区改为4+3：第一行4项，第二行收货差异、装箱数量、装箱差异；装箱差异跨剩余两列。

## 3. 固定视觉验收尺寸

部署后按以下尺寸逐一浏览器验收并保留证据：1440×1024、1280×800、768×1024、390×844、360×800。

每个尺寸核验：
- 大款号、长人员姓名、四至五位数量不重叠；
- “查看附件”“去处理/已处理”“录入/修改”不挤压数量；
- 多次收货展开只展开当前行；
- 390/360宽度无横向溢出；
- 返回、筛选、分页和原操作按钮位置不回归。

## 4. 端到端验收

- 单次收货：实裁与收货事实同屏。
- 嘉顺多次收货：实裁保持一份，不累计。
- 其他工厂多次收货：实裁保持一份，送货单按原规则累计。
- Root修正实裁：数量更新，最初裁床登记人/时间保持。
- Root修正收货：原收货规则保持，不改变实裁。
- 同款号两条裁床任务：看板显示两行，各自实裁和收货历史不串。
- 历史旧单：实裁显示“—”，其它数据和操作保持。
- 日期筛选与全时间款号搜索均能返回正确实裁事实。

## 5. 部署边界

本PR不补历史实裁、不批量写生产数据、不赋予真人角色。部署前按既有流程备份并执行当前main全部迁移；本PR本身不新增迁移。测试数据清理仅允许删除明确标记的测试记录。
