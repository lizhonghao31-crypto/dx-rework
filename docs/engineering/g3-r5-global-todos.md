# G3 R5 全部授权待办搜索

用户已批准在“这里只显示现在轮到你处理的事项。”旁提供一个全局搜索。非空查询跨当前用户既有授权的可办理模块；空查询继续原模块列表，明确点击模块时清除查询并回第一页。手机自然换行，返回地址保留查询、页码及原模块上下文。

服务端复用原待办上下文及生产／数字生产授权提供器。数据库部分仍限制 recipient_user_id 为当前 actor，排除信息通知、非待办状态、月结及已删除关联事实；提供器复用原业务权限计算，再校验接收人为当前 actor。Root 继续使用原接收人规则，不新增全组织待办特权。

全局查询将匹配的数据库候选和服务端提供器结果在 PostgreSQL 内合并，按 todo_id 去重、按状态／截止时间／创建时间／ID 稳定排序，以同一候选集计数并裁定页码。每页最多 15 条。业务文案仅作搜索映射，路由和可办理判定沿用原实现，不在前端下载全部待办过滤。

性能边界：原服务为计算模块数量，已有数据库计数后串行取得 production.todos(actor)、digital.todos(actor) 的完整授权数组。新全局查询复用这两份数组，匹配后传给一次 SQL 合并／计数／分页；仍存在原提供器完整读取及串行调用。本包未开展专项性能改造，也未测量或声称线上延迟。

定向单元回归已通过 8 项。全新隔离 PostgreSQL 的 7 项测试包含 SQL 跨五个数据库模块与两类提供器合并、外部接收人排除、15／15／6 分页、去重／页码夹取／参数绑定，以及既有数字生产角色与委派权限。SQL 合并用自有 fixture 表验证；真实业务提供器权限另由现有数字业务测试验证。浏览器以实际 App 加合成分页 API 验证 Root／工人、桌面／手机共 4 例。最终组合检查及 Head 见交付记录。
