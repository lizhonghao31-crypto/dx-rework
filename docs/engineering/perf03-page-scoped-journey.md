## 读取和更新边界

正式服务通过 `DIGITAL_JOURNEY_LIST_READ_MODE=indexed` 默认启用管理座舱新读取。先按当前身份获得原生范围，批量读取原权限、业务时钟、轻量身份/PO信息和有效选择摘要，使用原筛选与中文排序完成全范围统计，再按原投影装配当前15条。原详情、完整导出、内部工作区 `selectPage` 与 `details:false` 消费者保留原生路径；它们不能借此声称已经完成后续 PERF07/08。

共享表保存原生节点事实，不保存身份、授权结果、完整用户DTO、价格、附件地址或可办理结论。完整权限、无节点过滤的请求只读 `selection_full_json` 中的小型时序布尔摘要；是否可使用它，每次按真实 source/order、时效、预算及关联模块范围重新判定。局部岗位、字段限制或节点筛选继续在 PostgreSQL 中按有效节点精确归约。时间跨界来自原 SLA 引擎、日期精度和冻结窗口，不在 GET 中重建所有订单。真实未来事件只登记重新读取边界，不通过时间经过创造实绩。

原事实与两类选择摘要在同一单对象事务内发布，共用源版本、计算版本、时钟修订及完整性校验。计算版本为 `journey-facts-final10-v2-selectors-v3`。新版本由原有有界后台回填，普通业务修改仍由 PERF02 原生事务登记；正常读取不回填整库。后台构建失败只影响该对象，实际失败与正常等待分别显示；未知的全局数字及分页不冒充最新，已可靠的匹配订单仍可查看。

`POST journeys/:id/refresh` 仍经过原认证和对象权限，最多为明确授权对象登记派生更新并清除其退避；不改业务事实，不在请求中构建资料。页面对最多15个失败对象做有界独立重试，某单失败不阻止其他单；已发出的幂等排队请求不因导航而中断为未知结果，旧页面不接收过时回执。正常页面没有新增技术说明区。

## 必要验证及实测边界

使用原 `configForSuite`、受管命令、真实 AuthService 与标记的低权限隔离 PostgreSQL16.15，Node22.22.2/npm10.9.9、锁定 Chromium141。Node限CPU2/3、PG限CPU0/1和2GiB；这不等同 GitHub CI 硬件，更不等同现场网络、压缩、生产包或业务数据。

已验证当前15/15/1对象装配、全 PO 与原总数/KPI/次序对照、原生更正后拒绝旧数字、构建并发/回滚/失败隔离、真实首构建失败及精确重试，以及同一有效会话撤权。浏览器实际确认 URL 与页面第二页订单ID，再检查原详情，不以额外 API 查询冒充页面已经翻页。自然期限、未来事实重新读取、节点级权限和不同角色走原生反例。

规模样本为原生创建的订单，每单2个PO、首单3个PO，另含3个真实开发/采购/备料工艺母单及查询范围外的原生收货样本。其余为较早阶段订单，不能称为5000张完整生产历史单或最坏情况。对照使用相同源、数据、身份、时钟及请求，比较完整规范化响应；仅忽略观察用 `asOf`，不忽略业务日期、状态、顺序或数量。原生事实数组本身有确定ID排序，未通过放宽对照隐藏差异。

代表性规模测量执行于保留的源指纹 `525817b1`，在下述两项审查修复之前。1000单测试通过3项浏览器检查：旧路径一次约21.56秒/27714次实际SQL，新路径7次中位数约0.531秒、最大约0.536秒，每次735次SQL，完整结果一致。昂贵旧路径只测一次，这不是可靠延迟分位数；7次中的最大值不是P95。5000单测试也通过3项浏览器检查：旧路径一次约118.94秒/136964次SQL，新路径7次中位数约1.009秒、最大约1.084秒，每次735次SQL，完整结果一致。此前约7.54秒且翻页用例失败的是早期版本，不计为通过。上述保留测量不冒充修复后版本的新执行结果。

正式 Review 核实并修正开发来源尚无生产单时的预算节点筛选：先采用“不适用”规则，再判断字段权限，不再误作“不可用”。同类生产后续节点一并与原生投影对照，覆盖 Root 和真实设计师的总数、KPI 与 ID。另保留未设置 `deadlineExclusive` 的原生任务默认语义：截止点即逾期；缺省、true、false 均验证截止前一毫秒、截止点和后一毫秒。修复后的256项单元、31项真实PG模型/更新及3项完整应用浏览器验证通过；规模测量保留原结果，不为这两个局部边界重跑整个规模矩阵。

初始执行计划中1000单选择查询约1.52秒、时序提取约1.39秒，说明在大JSON里反复提取状态仍有实际成本。当前小摘要版本的同条件样本把该查询降到约56毫秒；没有减少权限、全局统计、排序或 SLA 来计入提速。SQL耗时累加和连接等待可能重叠，不能当请求墙钟；本地结果不是现场收益承诺。

## 回退

官方环境白名单保留 `DIGITAL_JOURNEY_LIST_READ_MODE`。由部署者设置 `legacy` 可恢复原座舱读取；保留已确认时间修复、原生变更登记、新表和待更新记录，不回退业务数据，不停止更新后继续返回“最新”旧摘要。若整版程序回退而漏登业务变化，再启用前使用原显式回填/核对入口，不能直接相信旧摘要。没有执行现场配置、部署、重启或真实数据操作。

实际检查的来源指纹、命令、结果和日志绑定在本批 construction-evidence 及外置收口包；本说明不替代最终准确 head/base 的CI批准。部署和现场体验由用户安排。
