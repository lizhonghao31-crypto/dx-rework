## 当前合同映射

当前详情仅在最新合同关联当前有效选厂决定且人工内容满足既有合同 schema 时读取映射。未修改的旧合同继续沿用订单展示。已有有效人工内容在读取时立即生效，不需要用户再次保存，不执行数据库回填。

| 合同内容 | 当前订单详情 |
| --- | --- |
| gender / styleName | 性别 / 款式 |
| partyBName | 当前合同承包主体（加工厂展示；supplierId 不改变） |
| estimatedCutPieceSendDate / deliveryDate | 预计裁片发出 / 交期；无法解析真实日历日期时沿用业务日期 |
| processes | 工艺及承包范围 |
| lines.position | 唯一映射当前款色行；位置集合必须完整一致 |
| lines.styleNo / alternateStyleNo / color / imageAttachmentId | 款号 / 代用号 / 颜色 / 款图（图片仍遵守合同资料读取权限） |
| lines.quantity / unitPrice / totalAmount | 当前展示数量 / 生产单价 / 行金额 |
| totalQuantity / totalAmount | 当前展示合计 |

模板固定文字、甲方地址、签署条款和收款账户没有订单业务字段，不推断映射。预算价、IE 价、原决定、批准快照、派单与裁床事实仍是其实际版本事实。人工合同展示数值不成为操作 API 的审批、数量、转厂价格基准或生产上报限额。

重复位置、缺行、多行时不猜测款色关系，明细及价格保留订单记录并提示 Root 核对。最新合同属于其它决定时不映射。旧合同、旧 PDF、回签绑定、时效、历史节点均保留；财务实际核对后的永久 Root 编辑锁保持不变。

## 转厂工艺

所有现有合法发起者在原转厂表单勾选“修改工艺”，从工艺目录按顺序选择。目录新增权限保持既有规则。未勾选时完全继承旧决定；新请求的工艺 ID 必须非空、唯一、最多 20 个且目录当时有效。

请求在原订单锁和幂等事务中冻结目录版本、名称、顺序及当前合同 ID，保存于不可变 `operation_events.after_state`。沿原跟单→生产管理、涨价→老板、老板直接生效路径审批；不改变价格阈值、审批角色或财务约束。审批通过时在同一事务追加带新工艺的选厂决定和批准/合同来源；后续目录改名不改变申请。合同 ID 变化时拒绝审批生效，仍可驳回并重新申请。

旧请求缺少 `crafts` / `baseContractDocumentId` 时继承其旧决定工艺；不回写旧事件，不制造旧审批。现有退回使旧基准失效、重复申请、审批越权、驳回、重试及财务阻断继续使用既有约束。取消尚未提交的表单没有数据写入。
