# Native drafts and original command receipts

Approved BA100/PR-E and the independently reviewed PO customer-decision supplement (Library55db9bd20f8481919bb984a22b3d0027). This candidate is explicitly stacked on the washing-navigation candidate be2cf05d, which includes cancellation1025 consumer repair de42e6f0 and actual1022/1024 integration. Its final comparison base must become the predecessors' actual merge before publication/Gate; earlier reports keep their real source identities. No deployment or live order repair is authorized here.

The original designer workspace preserves its parent intent and the raw creation form/document in the same browser tab, separated by freshly authenticated actor and environment. Incomplete values and local row/attachment identities survive a real reload. A pure draft gains no source ID, idempotency key, receipt lookup, automatic save or submit. File contents that the browser cannot retain are explicitly reselected. An acknowledged original source is reused only after that exact acknowledgement; an unknown source creation keeps its original identity and blocks duplicate creation because no supported terminal-read API exists for that step.

The original instruction form preserves the raw draft and independent immutable envelopes for save and PO customer decision. Storage must succeed before the original command starts. Restore checks current read authority and original versions/round; a stale or unreadable/future draft does not silently become empty or autosave. Source/order/actor/environment/key/body hash/generation and decision direction remain distinct. A later draft and another pending command cannot be cleared by an older receipt.

New receipt endpoints are read-only transactions over the original actor's fixed command namespace. Save returns only the original minimal acknowledged versions; the separate `po-customer:{orderId}:decision` receipt also checks original request, direction, key and normalized hash. Current object read permission is required; current write/approval permission is not a receipt requirement. No historical document body or role/credential is returned. Missing, inaccessible or unreadable receipt remains unconfirmed, never proof of failure and never authority to resend a POST.

A committed acknowledgement is durably recorded before an optional current-sheet read. Subsequent projection failure does not reverse success or clear a later draft. Recovery is explicit GET only; no effect/timer replays a command. The original approval transaction, business versions, audit and permissions remain intact.

Validation uses marked disposable low-privilege PostgreSQL16 and the original authenticated App, actual browser reload and original service transactions. It covers pure and unknown creation, save/decision response loss, later draft preservation, read failure after known success, approval revocation versus object-read revocation in the same session, cross-object/actor/key/hash denial and zero duplicate business writes. These engineering fixtures do not determine the terminal state of historical C/D/E/F/PACKSTOP requests whose original keys were never retained. Production/Acceptance writes, historical command replay, deployment and extra performance experiments remain outside scope.
