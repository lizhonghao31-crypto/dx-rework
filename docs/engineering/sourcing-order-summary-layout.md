# 外发订单摘要定稿排版修复

基于已部署release `55be413d72be1e99b5ef0a311dedd5e6a14b80c5`，修复顶部摘要未按已确认定稿分组的问题。首行保留跟单、方案工厂、订单数量、方案生产总额四组；次行为IE总额、变化、预计裁片发出、PO客户日期、加工厂日期五组。两行用细线分开，组间短竖线，标签弱化、数值突出。所有样式限定外发详情的`sourcing-module-layout`，不改变照片/流程、选厂或审批摘要及其它模块。

当前和历史详情复用外发专用日期分组，继续使用原`poDateSummary`及客户日期名称；不拿提议的工厂日期充当生效日期。没有完整逐PO身份的旧单保留未知客户日期与原“要求交货日期”。历史只读取服务器返回的所选历史item；原要求交货日期与逐PO生效日不同时也保留，不从当前单补历史空值。日期不截断，长文本换行，单个日期保持完整。窄屏重排为两列及独立日期行。

本地验证包含五节点的当前/历史、普通/Root/只读/无权、旧版本、部分数量、长附件名及手机操作，另增加部署截图中同款同老板身份的可见摘要事实，覆盖1357/1180/1165/500/390。截图由真实组件在隔离loopback浏览器生成；已知值来自用户给定截图，未公开的背景字段和图片仍为合成TEST，不冒充在线新版本。逐项对照与PNG在本轮交接报告中，工程检查和无溢出不等于最终视觉验收。

唯一Review指出真实历史API保留逐PO身份但未提供客户日期，原夹具不应人工填入该字段掩盖边界。现历史缺字段显示“当时日期不详”，不声称PO需补日期；已有可用历史值仍保留，当前缺日期继续原汇总规则。夹具改为真实省略字段形态，并在单测和所有历史浏览器场景核验。未重建历史客户日期或扩展API，不请求第二次常规Review；修后新Head重新Gate。

仅展示结构/局部CSS及验证，无金额/数量计算、日期业务规则、接口、权限、状态、迁移或部署改动，按QUICK Gate；最终冻结Head进行一次Codex Review。本修复独立PR，与G4依赖包保留独立合并，最终同一候选由用户一次更新后联合验收。
