# PR05：预算来源外发补填草稿与直接发布

从已发布预算进入外发创建，先重新读取当前预算和母单版本，再准备原外发表单。客户、款色、数量、预算价和预算明细来自服务；本地草稿只留人工补填，不存这些来源值。草稿按当前账号、母单、预算版本隔离，严格校验作用域和字段；另一账号不恢复原账号的补填。来源换版后先展示新版本并要求核对，核对后只沿用当前 PO 中仍有效的人工补填。旧 PO、无效交期、未知图片不会猜测映射到新 PO。

补填在空闲时保存，也提供显式保存。储存失败提示未保存，输入仍保留；未保存离开有提醒，正式提交成功才清除该作用域草稿。正式提交继续使用原外发创建接口和数字预算版本验证，同一内容失败重试保留同一请求键。原 IE、选厂、老板审批、转厂、合同、第二跟单及财务只读能力沿用原链路。

预算正文合法且有修改时，直接发布内部先保存草稿，再发布保存后的版本。保存已成功而发布失败时保留该草稿版本及发布请求键，重试只重试发布，不重复保存。

验证：本地完整测试 2190 通过、525 跳过；lint、typecheck、工作区构建、迁移静态检查、工作区秘密扫描通过。新增草稿隔离、作用域篡改、来源换版、旧 PO/图片、储存失败测试。实际 React 组件与完整样式的本地 Chromium 模拟 API 验证覆盖同账号恢复、另一账号隔离、来源换版核对、来源字段保留、正式提交失败重试同键同内容、保存后发布失败重试；1440、1280、768、390、360 宽度无页面横向溢出，无脚本异常。证据在 `/workspace/pr05-evidence`，此证据不是线上 Acceptance 业务验收。

本地无 PostgreSQL，相关数据库用例跳过；最终 Head 的 Full Gate 真实数据库业务链结果以 GitHub 检查为准。没有迁移，没有 ECS 部署或重启，没有操作真实业务数据。MD 为业务施工约束，原图仅作结构参考，不将示例值、旧文案作为业务正文。
