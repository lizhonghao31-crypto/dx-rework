# R3：差异处理拒绝旧弹窗覆盖

来源：本轮实机验收追加复现。送货单 10、实收 11 的同一快照，两个跟单弹窗先后提交均返回 201，后提交的处理结果替换当前显示；底层数量未重复累计。

沿用 ADR-0022 第 4、6 条：已处理的非零差异只读，底层数量变化后才能重新处理。沿用现有按收货订单/款号分组的事务锁，在写入处理记录前检查当前数量事实是否已有处理；重复的新请求返回 409，原幂等键仍重放原结果。收货与装箱差异分别判断。

数量事实修订由不可变收货事实及实际改变数量的纠错事件计算，写入处理审计快照。数量先变化再返回原值仍是新的修订，避免永久唯一数值约束误阻断。旧处理记录通过既有审计时间兼容读取。看板、状态筛选和分析使用相同修订口径；只改变送货单数量不会重新开放未变的装箱差异。

隔离 PostgreSQL 回归：PG13 收货原生 35 项通过；PG16 全业务链 50 项通过。覆盖同快照并发一次成功一次 409、原键重放、处理不增订单版本、两类差异独立、数量改回原值后的新处理、旧历史保留及允许/拒绝权限。移除本修复的写前检查时，定向并发用例复现两个成功并失败。

无迁移、全局版本提升、权限变更、部署或实际业务数据修改。实机复验待用户部署，由唯一浏览器验收主体执行。

唯一 Review 的删除批次发现已修复：分组修订保留已删除批次的删除审计事实，防止数量先增加再删除恢复原值时旧处理再次成为当前结果；装箱修订仅因实收变化失效。新增真实多批次创建、Root 删除与两类重新处理回归，旧处理历史保持。
