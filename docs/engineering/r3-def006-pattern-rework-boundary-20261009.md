# R3 DEF006：开裁后的原单返工边界

来源：第二阶段报告 `R3-stage2-report.md`（Library `libfile_924498ea575c8191928ef76431e25dbb`，版本 1）。

此修复把正式施工计划 V1.1 R33 的既有开裁后实质修改冻结边界前置到关联原单返工入口，并同步[打板财务需求 §6.1](../requirements/pattern-room-finance-v1.0.md#61-原单返工)，没有另行扩大禁止范围或把工作稿当作新增授权。

关联数字开发单任一母单已有实裁记录时，原打板订单不再开放需要新开发轮最终确认的返工入口。API 在创建轮次、待办、审计及工资段之前返回 409；详情说明阻断原因。检查与开裁、开发轮发布共用生命周期事务锁，并在原单行锁之前获取，避免竞态及锁顺序倒置。

未关联、关联但未开裁的订单保持原流程。大货冻结和最终设计确认的工资放行条件未变。隔离 PostgreSQL 原生服务回归覆盖开裁后的 Root/原设计师拒绝及无副作用，以及未开裁返工的新轮发布、尾查、最终确认和独立工资段。旧轮工资保持。

完整外发原生回归 77 项通过；测试复用当前 fixture 中已核验的 Root 及其真实审计角色，避免独立用例改变后续用例的 bootstrap 身份。

本 PR 仅改代码，不部署、不修改实际业务数据。实机复验需用户部署后由原浏览器验收主体执行，云端隔离测试不计入线上验收结果。
