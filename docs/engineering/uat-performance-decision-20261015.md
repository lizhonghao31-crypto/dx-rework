# 本轮定向性能诊断与PR09判断

状态更新：管理座舱已按用户追加授权单独测量并形成PR09。PR05的604→244次SQL仅是板房路径证据。座舱同一TEST负载、15条分页、真实Fastify路由测得Root首页1491→715、跟单首页1801→636次SQL；两轮每版本10个样本，Root首页p50 536.349→386.269ms、跟单首页547.392→294.341ms。仅在原单次只读RR快照内复用重复读取，14组响应除时刻字段外一致，下一请求重新读实时权限。详情SQL减少但耗时接近，不宣称显著提速；前端快/慢输入均不逐字请求，保留原查询提交。原始样本、范围和限制见`uat-pr09-cockpit-performance-20261015.md`及同名JSON。缺少线上指标只限制线上收益和ECS扩容判断。

PR05对照使用相同隔离PostgreSQL、24个已发布TEST来源/24项真实物料任务，同一授权读取、一次预热后五次顺序样本：SQL从604降至244（减少59.60%），本机p50从151.387529ms降至116.24345ms、p95从219.702768ms降至129.457097ms；返回总数仍24，列表默认页20改15。原始样本与精确范围见`uat-pr05-pattern-performance-20261015.json`。并发本地测试时采到的受竞争样本不作为改善证据，不能与顺序样本混比。

优化保留任务点击时原权限复核和完整详情，仅列表预览避免加载执行DTO。根角色、设计师、文员、工人、陌生账号/撤权及富投影对照有PG证据；分页和摘要不改变工资/状态机。后续PR08统一列表15和节点服务端分页解决不可达数据，也不能当作新的线上性能实测。

ECS是否扩容：证据不足。当前任务禁止生产服务、真实数据和部署操作，未采集生产CPU/内存/磁盘IO/PG慢查询/连接池队列、访问网络及HAR。用户部署后如仍慢，应在相同业务路径分别记录首屏/列表/详情、TTFB/请求数量、SQL耗时、CPU/内存/IO及连接池等待，再判断网络、查询或资源瓶颈；不能用主观“页面慢”推断需要扩容。管理座舱已按独立本地证据形成PR09；没有线上指标仍不能推断扩容，实例保持由用户决定。
