2. 桌面保留流程状态与节点，手机采用紧凑信息网格、默认折叠流程、可展开纵向节点和响应式明细。长款号与文字在单元内展示，页面不使用横滑桌面表替代手机明细。
3. 工序分工和报工已有弹窗补齐 Escape 取消、提交中禁止关闭及弹窗内反馈，不改写请求、幂等键、合法状态和业务验证。
4. 已完成主节点进入独立历史页面，仅装载只读字段、逐行明细、验货报告及图片预览，不挂载当前办理表单。支持发起、工序分配、IE 核价、分工、报工、最终数量确认/复核、数量调整、责任判定和老板签字的历史读取。
5. 责任台账和扣款跟进仍使用原有持续办理/分域读取路径。发起后可撤回等现有操作移到当前办理区，避免只读历史页承担写操作。

## 数据与权限

- 新增 `GET /rework-orders/:reworkOrderId/history/:node?entryId=...`，先复用订单授权，再检查节点读取能力；版本必须属于本单、本节点。
- 只读事务以选定审计事件时间为截止，使用历史配置、报数/修订、数量确认、责任版本和供应商版本；时间比较保留数据库微秒精度。
- 工人报数保留本人及获授权代报临时工范围。图片只返回历史清单和既有附件授权的交集。
- 人员显示名称仍取现有人员目录；不宣称保存了当时 HTML 或每次人员改名记录。
- 早期缺少快照或对应明细的记录显示缺失提示，不用当前业务数据冒充。早期独立整查/旧分工资料并非所有版本均能完整还原。
- 不新增 migration，不修改业务写服务、金额计算、角色/capability 配置和状态流转。
