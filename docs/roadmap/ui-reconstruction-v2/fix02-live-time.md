# FIX-02 现场时间来源

依据：2026-10-06 补充验收报告 D02；第一阶段 FIX-02。集成基线为 FIX-01 合并后的 release/digital-production-v1，FULL。

现场核配、纸样派交等服务先生成服务器当前日期，再通过显式日期参数登记条件；原任务服务把所有显式日期都标为补报未核实。因此正常 NS／PS 路线也被排除出可计时及 SLA 分母。

条件服务现在以未提供日期表示服务器现场动作；显式日期继续表示补报，null 继续表示时间缺失。客户端不能提供可信标记。激活时同时读取全部有效激活条件及前置任务完成事实的时间质量，任何未知／未核实来源都不能因另一个现场条件而洗成可信。

固定服务的现场激活调用保留服务器取时；用户输入的工艺、到厂和补交接日期仍保留原补报性质。进入时间仍取完整真实前置的最大时间，SLA／期限版本、阻断与解除阻断的起点、数量和状态规则不变。没有历史批量回填，没有把 PostgreSQL 事务起始时间改成新的全局 recorded_at 规则。事务起始时间可以比现场动作早几十毫秒；统计按真实时间来源判断，不能据此判成补报。

定向验证覆盖：普通设计师／文员／板房工人的核配→纸样→裁板，现场阻断解除后原进入时间和期限不重置，现场完成计时和 SLA 纳入；PS 纸样 48 小时及预缩 36 小时，先后和并行开裁原门禁；显式补报、未知时间及前置任务来源继续排除／保留未知。原非 Root 办理权限、拒绝路径和幂等性沿用原回归。

只写本地新 TEST 案例，旧样例时间不改写。最终 Head 的本地测试、CI 和一次 GitHub Codex Review 记录于 PR。上线 UAT 仍需部署后复验，不能用源码门禁替代；不进入单据重构、线上 SQL 或部署。

Codex Review P1 修复：复版尾查引用前轮洗水完成事实时，服务器读取同来源、已完成洗水任务的原 completed_at／completed_quality，作为该条件的原时间来源并记录继承任务引用。旧补报和缺失不会被重登成现场事实；可信旧事实也保留原质量。没有新增客户端可信标记，没有改写旧完成事实。
