# 数字生产平台｜新旧流程隔离根记录

## 已确认业务边界

- 上线前已存在的订单继续按旧流程运行。
- 上线后真正“新创建”的数字生产订单才进入新版全链路。
- 旧订单上线后新增收货、返工、装箱、工资等后续记录，仍属于旧订单，不因为写入时间较新而被切到新版。
- 历史款式未来收到一笔新的客户订单，可以创建新的数字生产母单；是否引用历史款式资料属于后续业务功能，不改变原历史订单。

## 本PR的实现

新增独立表 `production_order_roots`，只存三个稳定事实：

1. 新母单唯一ID；
2. 不可变的 `digital_production_v1` 流程代际；
3. 创建人和创建时间。

本PR不存客户、款号、颜色、PO、货期、开发单类型或工艺等业务字段，因为这些内容仍在问卷确认中。

### 为什么不用日期判断

不采用“某天以后创建/写入的记录都算新版”。日期无法区分：

- 旧订单在上线后发生的再次收货；
- 旧订单上线后产生的返工；
- 新订单引用历史款式资料；
- 补录和更正。

新版身份必须来自明确创建的数字生产母单，而不是推测时间。

### 为什么不回填旧订单

迁移只创建空表，不从 sourcing/cutting/receiving/rework/pattern-room 等历史表执行任何 INSERT...SELECT。
因此旧订单数据库事实保持原样；未来只有显式创建母单时才会生成新版根记录。

## 后续挂接原则

开发单、客户确认下单、预算、制单、开裁、发厂、回货和返工后续都通过稳定 `production_order_id` 关联到该母单。
具体子表和节点字段等问卷结论确认后再建设，本PR不提前猜测。
