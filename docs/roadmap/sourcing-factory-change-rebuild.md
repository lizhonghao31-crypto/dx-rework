# 报价选厂订单转厂辅助流程（冻结契约）

## 主流程边界

主流程固定为五个节点：跟单创建订单、IE 报价、生产管理调价选厂、老板审批、财务核对。订单转厂是辅助流程，不新增主节点，也不为主状态未变化的转厂写入主流程 transition。

## 解锁与权限

生产管理首次提交加工厂和单价后，跟单、生产管理、老板才可以发起订单转厂。财务只读核对，不得发起或审批转厂。

- 跟单发起：生产管理审批；新单价不高于审批时基线则生效，高于基线则转老板审批。
- 生产管理发起：新单价不高于审批时基线则直接生效，高于基线则转老板审批。
- 老板发起：无需审批，直接生效。
- Root 仅沿用现有超级用户授权旁路，不新增普通岗位权限。

价格阈值必须在最终批准时相对最新可比较决定重新核验，过期申请不得生效。

## 生效与财务

每次生效转厂生成新的不可变选厂决定版本，并成为下一次转厂的比较基线。不得覆盖 `0126_sourcing_finance_readonly_reconciliation.sql`：财务核对继续复制当前决定事实，只能确认一致或标记差异项和说明。

如果订单已经关闭或处于差异核实，转厂生效后重新进入财务核对；如果主流程状态无需变化，不写入同状态 transition。旧财务待办失效，并按新决定版本生成新待办。

## 界面

仅修改电脑端。在跟单、生产管理、老板各自节点页面底部显示“订单转厂”；首次生产管理决定前禁用。移动端继续使用现有禁用入口，不新增或调整移动布局。

## 合并前行为矩阵

必须以 PostgreSQL 集成测试覆盖：三类发起人、低价/同价/高价、批准/驳回、老板直接生效、首次决定前锁定、老板驳回后仍可转厂、财务无权限、旧基线拒绝、并发申请、幂等、财务待办刷新、关闭订单重新核对、五节点数量与顺序不变。
