## 1. 本轮目标与边界

目标顺序：业务链路跑通 → 样板确认 → UI与图标、动效落地 → 可信数据分析 → 分阶段验收。

### 1.1 纳入

- 修复样衣采购小票上传阻断，补验全部样衣业务闭环。
- 修复供应商切换对象期间的误写风险、导入预检与部分成功反馈。
- 新模块金额最多两位小数、千分位、非转厂外发多款价摘要和必填提示。
- 精确处理本轮测试生产记录的经营统计污染，保留业务与审计历史。
- 一级、二级导航入口及对应页面标题的统一图标。
- 供应商、样衣、实时生产模块的布局重构；基础配色、字体字号、控件参数不另造一套。
- 实时看板真实事件动态带、生产条缓慢纹理、刷新反馈、一次性变化高亮、准确相对时间。
- 样衣采购、品牌、人员、类别、金额区间、当前持有与处置分析。
- 送货—实收—装箱差异分析。
- 供应商交付与数量质量分析，不含返工成本。
- 预警与后续生产、发货、回货事实关联。
- 本公司在外未完订单的交期和供应商集中分析。
- 流程等待、反复退回、普通报价阶段事实对照。
- 利用字段修订和失败日志定位系统体验问题，不进行员工绩效排名。

### 1.2 明确暂缓或不做

- 设计师ROI、成果归因、销售成本接入、为ROI预埋额外业务录入。
- 重复样衣识别、跨部门复用推荐或新工作流。
- 返工成本、工序成本、扣款兑现专项、员工效率/薪酬排名。
- 转厂相关的新功能、逐款价改造、UI重构与分析；包括本报告UAT-03。
- 供应商评分、红黑榜、自动选厂、自动排产、产能预测、自动判责。
- ERP数据迁移或同步、供应商对外账号、外部BI平台、大屏模式。
- 未经新增明确授权的自动刷新、服务端推送或钉钉推送。

### 1.3 不能被旧规则覆盖的本轮决定

- 节点一订单图片必须上传；样衣采购小票也必须上传。修上传与提示，不取消必填。
- 参数对齐约束基础尺寸、颜色、字体字号等，不要求各模块照搬返工的布局。
- 已验收返工页面不重排；本轮涉及它的视觉修改仅限已授权的导航/标题图标。
- 财务在后续付款、对账时核对，不作为正式派单或生产前置条件。
- Root、老板及既有普通角色的业务权限不借机重定义。
- 达兴价格不得进入供应商合同或无权岗位界面；分析接口、排行和导出同样遵守金额权限。

## 3. UI样板与图标

### 3.1 布局方向

|模块|参考方向|落地形式|
|---|---|---|
|供应商中心|[shadcn紧凑数据列表](https://ui.shadcn.com/examples/tasks)|搜索/筛选、供应商表格、详情及维护；手机列表进入详情|
|样衣管理|[TailAdmin商品目录](https://demo.tailadmin.com/products-list)|小图与名称、品牌类别、采购/持有人、日期金额、状态与当前操作；手机紧凑图文行|
|实时生产|[Tabler行内进度表](https://preview.tabler.io/datatables.html)|紧凑态势栏、真实动态带、筛选、订单行内双进度、异常原因、详情|
|样衣经营分析|[TailAdmin Analytics](https://demo.tailadmin.com/analytics)|统一筛选、少量指标、趋势、分项排行、可追溯明细|
|非转厂报价页面|现有核价和业务单据结构|只修必填、逐款价格、汇总、删除说明；不扩大为全流程重排|

借鉴结构，不复制模板整套CSS，不引入新的UI组件库或调色盘。详情、编辑、批量操作、确认弹窗一起设计，不能只做列表首屏。

### 3.2 图标范围

一级入口、二级入口、对应页面标题使用同一套线性SVG图标。不得用一组彩色emoji替代系统图标。

建议语义：我的待办为清单勾选；实时生产为活动/进度；订单回货为收货箱；返工为维修/工具；外发定价为报价单；供应商为工厂；样衣为衣架/衣服；报表为图表；系统管理为设置。

二级按实际功能区分资料、编辑、生产填报、借还、处置、待确认、分析等；同一路由在导航与标题使用相同映射。只给已存在且有权限显示的页面加图标，不创建新的业务模块。

初稿规格：一级导航20px、二级18px、页面标题24px；同一线宽和视框，颜色继承现有文字/选中态。样板确认后锁定规格；图标不得反向撑高按钮、导航或输入框。不改变既有菜单顺序、路由、可见性和文字标签。图标不替代文字；装饰图标从辅助技术阅读顺序中排除，图标按钮仍需可读名称。

### 3.3 样板交付

样板是每个UI PR的前置交付，不另造第二套系统，不另开包揽全模块的大PR。使用最终准备复用的组件/CSS及隔离的合成数据；不得用真实业务数据作样板写入。

每模块提供可打开的中文交互样板，覆盖列表/详情/编辑或关键弹窗；生产看板提供可运行动态样板及录屏，静态截图不算动效验收。

固定尺寸：1440×1024、1280×800、768×1024、390×844、360×800。

必须加入长名称、多款色、四位以上数量、大金额、无图、空结果、加载失败、无权金额、选中及未选中等状态。批准后冻结组件版本、截图与动效参数，接真实API而不是重写一套近似页面。

## 4. 实时看板动效专项

已核验：旧规则第11节已经包含动态带、进度纹理、状态过渡、相对时间等；目前读取的实现中已有动态滚动、刷新旋转、变化高亮和部分进度过渡。生产条缓慢纹理及本地相对时间应作为本轮明确补齐项，不能将整套动效说成从零建设。

|组件|行为与初稿参数|停止/保护条件|
|---|---|---|
|真实生产动态带|展示上报、修正、完工、发货及可证实的风险发现；至少3条且实际溢出才缓慢横移|暂停按钮、悬停、聚焦、触摸阅读、减少动态、后台页面时停止；不足3条静态|
|生产进度纹理|在已上报、仍生产中订单的已完成区域内显示极浅缓慢纹理，初稿8秒一周期；不改变填充宽度或数量|待首次上报、完成、已发货、未更新预警、加载失败、后台/不可见或减少动态时静止|
|进度和状态变更|收到新数据后旧值到新值约250ms过渡；最终数字立即准确显示|无数据变化不重复播放；减少动态时直接显示最终状态|
|变化订单高亮|真实新增/变化订单一次约1.6秒高亮|不整页闪烁，不使排序/点击目标突然跳动|
|刷新反馈|仅请求期间刷新图标旋转，旧数据保持可读|请求结束立即停止；失败保留上次成功数据和真实截至时间|
|相对更新时间|在当前页本地按分钟更新“距上次上报多久”“距数据读取多久”，提供准确绝对时间|不产生后台轮询，不在前端另算业务风险，不把显示时间更新伪装成新数据|

页面设置一个明确“暂停动效/继续动效”控制，统一管理非必要持续动画。遵循系统prefers-reduced-motion。动态图标/纹理表示系统记录的生产阶段，不证明工厂机器实时运行。

维持进入页面、筛选、翻页、主动刷新时读数据的现行机制。本轮不增加定时轮询或WebSocket。固定展示数据截至时间；无新事件时不造事件、不造数字增长。禁止霓虹、粒子背景、发光大卡、持续闪烁LIVE及多处跑马灯。

## 5. 数据分析第一版

### 5.1 样衣经营分析

保留现有入口与权限，升级页面而不另建一级模块。支持采购日期、采购人、当前持有人、部门、品牌、类别、采购单价区间、状态等明确口径筛选。

交付采购金额/件数/人数/均价、采购趋势、人员/品牌/类别排行、人员品牌交叉明细、当前持有数量与原值、持有时长、借还与处置事实、出售与已确认赔偿分项。

采购人和持有人分开；采购金额不是品牌受欢迎程度的唯一指标；默认首次领用不算独立开发成果；长期持有只提示核查，不评价浪费。每项统计可进入对应样衣明细。权限禁止时，接口、排行、金额区间筛选和导出均不能泄漏金额。

时间口径明确：采购趋势取采购日期；当前状态指标表示所选样衣集合的当前状态，不假称历史某日库存。处置与回款的期间口径另行标识。正常历史归档与测试/误建作废分开，归档不能让真实采购历史凭空消失；旧金额对账口径在未授权时不静默改变。

### 5.2 回货与装箱差异分析

展示批次、供应商、款色、送货单数量、实收、装箱、修订版本及差异处理记录，支持从汇总进入原单据。复用现行业务方向，不在分析端重写反向公式。已读取0140迁移中新记录方向为实收减送货单、装箱减实收；开工继续以当前有效服务和契约核对，历史版本不重算。

分批收货与未完成装箱不自动算最终损耗；“已处理”不等于数量已归零。缺失装箱值不是0。

### 5.3 供应商交付与数量质量

展示约定交期、发货事实、首次回货、累计回货及收齐情况；区分发货和到仓。返工只做涉及订单/数量等质量事实，不计算费用、工资、扣款、工序成本或综合评分。

比例指标上线前须锁定分母、成熟观察范围和明确的原订单关联。同一件衣服多道返工工序不能加成多件不良衣服。关联不完整时显示覆盖范围/未关联数量，只做事实计数，不输出全局准时率或返工率。

### 5.4 预警与结果复盘

将真实预警记录/首次观察时间与后续上报、恢复、完工、发货、回货关联。已读不等于解决，后来准时不等于曾经误报。仅能证明“刷新时发现”的，保留首次发现口径，不冒充精确发生时刻；未记录干预原因时，不推断因果。

### 5.5 在外订单集中分析

按本公司供应商、交期区间、状态统计有效未完订单数与剩余数量，显示逾期、即将到期、缺交期等分组并进入订单。完成、已发货、排除对象按口径处理。未完数量按有效事实计算，不用累计工序数。

该视图只表示本公司在外业务，不推断供应商总产能、空闲产能或其他客户负荷。

### 5.6 普通报价、流程等待与操作诊断

普通报价只对照初价、IE价、最终批准价及数量/范围变化，排除转厂事件，不把价差命名为利润或节约。

利用节点进入、离开、驳回、补充和修订记录分析当前等待与历史往返。财务后置核对独立显示，不算阻断生产。节点停留时长不等于劳动工时，不做员工效率排名。

操作诊断聚合本轮相关页面的字段修订、失败阶段、错误码、重试结果。优先复用既有日志；缺失时只加最小必要记录。区分正常业务校验、无权限拒绝和技术故障。不记录采购小票内容、用户完整输入、银行账号、身份证、cookie/token，不做屏幕回放或员工行为监控。

### 5.7 页面归属与权限

样衣分析沿用原库存金额入口；回货差异分析放在现有订单回货的只读分析入口；供应商履约放在供应商总览/详情的事实分析区；订单集中与预警复盘放在实时生产的分析视图；流程等待利用现有管理工作台/报表；操作诊断仅向已有系统管理/审计权限开放。分析不得成为一线提交、派单或生产的必经步骤，不另建一个新的一级“BI系统”，也不因为能看汇总就扩大其明细和金额权限。

## 6. 共享数据底线

- 同一分析内筛选、指标、图表、排行、明细使用同一口径与权限范围；聚合基于全部符合条件的数据，不是当前分页。
- 必要时使用只读一致性快照或统一asOf；提供数据截至时间、筛选范围及未关联/缺失情况。
- 所有金额格式化在展示边界进行；API传输和计算保留规范数字/十进制字符串；标识编号不加千分位。
- 新非转厂报价按两位有效精度收口；不静默截断历史报价，不修改批准金额、旧合同或返工计价。公共schema变化不得使延期转厂入口或历史读取失效；需要拆开新写入验证与历史读取/计算兼容。
- 对关联采用订单ID、行ID、批次ID等稳定键；名称或款号相似不能自动跨单拼接。历史歧义列入核查清单，不为完成看板强行回填。
- 保留批准交期与后续变更事实、业务日期与录入日期；已有直接复用，确缺才增量补齐，不新增无必要审批。
- 品牌/部门别名保留原文和映射版本；人员使用稳定ID，不凭同名合并。
- 异常原因复用现有说明，仅在本来就要执行的异常动作中做最小结构化，不另填日报。
- 测试/误建排除、普通历史归档、正式业务分别处理；测试排除条件跨列表/动态/预警/统计一致，不能将真实已归档业务全部剔除。
- 不改旧迁移，不为分析重写业务状态机；新增数据库对象必须有权限、兼容、索引和查询性能测试。

## 8. 验收、门禁与部署

### 8.1 视觉与交互

同一合成数据、浏览器环境、字体和尺寸下提供批准稿、实现截图及差异结果。不得只更新基线图/放宽阈值让测试通过。重要动效另有录屏或真实操作证据，静态截图不代替动画行为。

验收至少覆盖：列顺序和操作位置、无溢出遮挡、手机可点击、长文本与大数、无权角色、弹窗、错误恢复、筛选分页、返回保留上下文。

### 8.2 业务

- 样衣：上传两类图片、移除重传、单件/批量创建、借出、归还、确认/拒绝/撤销、二维码、出售/赠送/报废/遗失、赔付、资料与金额修正、归档和统计。
- 非转厂外发：图片必填、逐款价、合法核价/驳回/批准、合同内容与下载、财务未核对先派单及财务差异后置处理。
- 生产：多款数量、超量、Root追加修正、满量、完工、发货、双进度、跨工作日与未更新、动态暂停和减弱动态。
- 回货：多次/分批、送货单与实收、装箱、差异处理、修订后统计、明确ID关联。
- 分析：全量不局限一页；筛选/指标/排行/明细一致；测试排除；正常历史记录保留；跨角色授权、低样本/未关联/缺失状态。
- 测试不依靠改单据数据库或生产时钟模拟；需要受控时钟的自动测试与真实环境测试分开标识。
- Root单人不能代表多角色审批/金额隔离或真实扫码。未获得对应证据的保留未验证，不伪造覆盖。

### 8.3 门禁与施工流程

遵循仓库现行Work施工与CI治理，不自行改成Codex Cloud，不改CI工作流来迁就本轮。

当前Head完成适用lint/typecheck/build/定向测试；权限、金额、数量、状态、迁移、审计、共享壳及P1修复按现行规则走Full Gate。必要Codex Review在最终预期Head门禁全绿后执行，默认最多一次，触发/合并权限沿用当前有效规则和实际授权。旧Head绿、skip、cancelled均不是本次通过。

生产如果必须先合并才可部署，按实际流程执行：代码门禁/合并、部署、业务视觉验收分开。未部署时不拿旧版本验新功能，合并后未部署验收不能标记业务通过。失败先读精确日志、集中修复，不盲等或反复重跑。

## 9. 风险、优势与置信度

- 先修业务阻断再UI：优势是能用完整真实链验收；风险是隐藏样衣问题可能在补测时暴露，届时只做根因对应的最小修复并登记范围。
- 样板代码复用与图像对照：优势是降低设计到实现偏差；风险是审美和复杂状态仍需实际确认。样板前不能保证一次满意。
- 动效不改变数据读取机制：优势是有生产运行感且不额外压服务器；风险是用户误认实时推送，因此保留截至时间、状态含义和暂停。
- 现有事实增量分析：优势是减少新录入并联动多个模块；风险是历史关联与分类完整性未知，缺失必须明示，不能制造精确排名。
- 暂缓转厂：优势是遵守优先级、控制规模；风险是已知多款价转厂P1仍在，必须在发布/验收结论中明确排除，不能承诺全部场景无缺陷。

需求边界与已读代码动效事实：置信度高。视觉最终效果：样板确认与五尺寸实测前为中。跨模块历史数据完整性：尚无足够实库核查证据，不给虚构覆盖比例或完成时间。
