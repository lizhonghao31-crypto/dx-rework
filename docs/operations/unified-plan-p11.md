# P11 实物、数量及样衣办理的具体拒绝说明

本增量承接旧PR3功能范围，逐块复用f27e7037的单个有效差异，未合入旧分支父链。裁床、工艺收发/QC/发厂、工厂到料/清点、生产新增实绩、收货/装箱差异、样衣借还与处置各沿原业务拒绝事实说明缺项、原岗位及本单位置。原schema/数量与金额算法、状态/角色/capability、Root特殊能力、事务/幂等、审计及待办保持，不新增工序、审批、实际时间或默认数量。

## 同源及边界

- 工艺任务不可办理复用原task.read的unmetConditions，前端逐条展示既有负责岗位与动作，不另建资格公式。实际发厂前逐PO列未检/问题待复查；没有本轮回仓时先指明原工艺物流的实际回仓。已发厂与等待回仓分别说明，未知真实原因仍标未知。缺失任务取受控说明而非访问不存在对象。
- 裁床来源/批准款色/PO关联、上传图片资格及原Root数量订正沿原事务拒绝，不建议重复批准/裁单或全部重传。照片上传与正式实裁仍是两种事实。
- 生产填报明确新增量与原累计量；权限外订单不回显详情，Root原订正及版本限制保持。
- 收货各原版本拒绝指向实际收货/送货单/装箱记录；没有装箱或真实差异时不能造处理记录。原收货订正仍仅Root，提示不授予一般收货员修改权。
- 样衣既有状态转业务名称，未知状态不回显内部值；schema错误按字段/批量第N项定位，不回显输入值、金额、员工ID或交接码。旧借用资料缺错不能从不存在的编辑入口补正，沿原发起人/行政/Root撤销待处理申请后重提；未改变撤销权限。交接码失效仍在同申请重生成，不重建借还事实。原样衣财务与处置审批规则保持。

## 收货弹窗的实际请求宿主

计划所指receiving-dialog.tsx仅是原生dialog外壳，实际五条写请求在order-board-page.tsx：装箱POST、差异POST、收货订正POST、批次订正PATCH、删除DELETE。已在实际宿主消费P10反馈工具，外壳/CSS/原布局不改，避免把改了一个无请求的文件当作覆盖。

receiving-board-request仅服务这五个原命令及原看板GET，逐命令校验实际JSON回执；未新增端点/HTTP方法/业务payload/幂等键。装箱和差异保留原key；Root三条原无key命令仍无key、沿原expectedVersion守卫。HTTP错误保留code/status/安全原因，坏200或已发送断网/中止属于未知，不能关闭弹窗或宣称未写入。

仅此组件保留原命令的路由、body、headers、原key和开始时间。未知时关闭普通保存入口，不能编辑后用原key发另一笔操作，也不重新上传已成功的凭证；只有明确点击原内容核对才使用冻结命令，恢复期限沿P10现有23小时，不延长服务器保留期、不自动重试。后续403/409等拒绝不能否定先前未知提交。Root原无幂等接口若前次已写入，旧版本核对可能被原守卫拒绝，此时仍说明结果未知，用户在原收货/装箱历史核对，仍不明确交管理员核查；不伪造可重放成功回执。

取得可信回执才关闭相应弹窗，随后GET失败仍保留“已保存”，只重读看板。GET失败有原页仅重读入口；合法空集合与错误分开。单独GET成功也不当成原命令回执，不自动解除未知状态。关闭弹窗不等于撤销已经发送的提交。新开另一笔修改在原未知命令确认前被本组件阻止；未扩大成全系统命令平台。

上传意图/对象/最终确认各自恢复归P14；本PR只保留已有可用附件及原业务提交协议，不用文件上传成功冒充收货/工艺合格。
