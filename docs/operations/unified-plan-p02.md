# P02 同轮资料补正与文员复核

候选实现，尚未合并或部署。业务依据为用户已批准的统一方案 V4、逐 PR 计划 V2（Library `libfile_bc5f5162101081918ab2e4d207c64352`），主覆盖 D07/D08/D09；D04/D05 贡献退回与复提协议，B11 可见材料标签主验收仍归 P03，D04 整页动作与四项全选主验收仍归 P04。

## 用户行为与边界

- 不完整资料仍可存草稿。正式发布不再受设计师旧 `requiredThisRound` 默认值影响：实际填写材料须有品名，实际主布须有规格，未到的辅料沿原规则填写预计日期。空模板不代表本轮不用，不把克重、幅宽、供应商等都改为必填。前端字段定位和 API 使用 contracts 同一规则。
- 文员退回时指出材料或资料区域、问题字段、原因，并区分“资料需要修改 / 澄清”与“实物需要补齐 / 更换”；可同时列多项。已有“开发缺料补齐 / 开发缺项复核”节点沿用，仅改可读标签，不增加节点、审批或主管常规审核。
- 四项全勾仍可退回其他明确资料问题；同一项又勾相符又称不符时拒绝，不代用户改勾选。实物颜色不符需补换时保持正确的预期颜色，不能强迫设计师改错资料来迎合实物；这种补换须有退回后的到货 / 原规则允许的代用记录，随后仍由文员复核。
- 原实际材料不通过删除或清空代表本轮不用；保留给文员复核并记录不用确认，尚未发布的新增草稿行仍可移除。原设计师在原补正 / 补料待办办理，Root 保留既有权。问题链接定位材料 / 字段；“打开本单物料记录”复用同工作台的“本单资料 → 开发单 → 轮次与记录”原入口，未新增到货 API。返回当前办理重读原任务，补正草稿自行维护 dirty guard，不让宿主把已保存草稿误报为未保存。保存补正草稿不改正式资料；提交验证任务、同一制作轮次、正式资料与草稿版本，并追加资料修订、完成原任务、创建唯一文员复核，处于同一幂等事务。原设计师停用不能继续写，Root 按既有权处理且不改历史归属。
- 补正只允许材料资料、附件引用与制作说明；制作数量、尺码、模板 / 尺寸、工艺、洗水、订单草稿和价格依据保持冻结。实际改样走既有复版。后续工序已实际激活或完成时，有实质资料变化的补正被拒绝，不覆盖执行段、时钟或工资。单纯补实物可直接登记后提交，不强迫另存资料草稿，也不凭空增加一份资料修订。
- 材料身份变化通过既有 basis 对比失效本轮使用及四项；数量 / 颜色 / 规格变化失效对应项。无可证明的历史核验基础时重核，不能让旧核验或到料记录自动认证替换后的材料。旧发布快照与新修订分开可查，任务 / 打印读取有效资料。

## 写入结果未知与回执

每个新写请求保留原幂等键与冻结内容。网络丢失、5xx 或无法解析写回执时锁住另存 / 另提，保留输入，并允许只读核对原操作回执。读不到回执仍表示结果未知，不能推断撤销或未落库；用户可明确选择用原键重试同一请求。收到已提交回执后，刷新失败只重读，不再提交。

回执读取仍核当前身份、来源归属、原补正任务和操作者；已结束任务可核本人原回执，不能读别人的命令。命令回执带原任务身份，不能把同一单另一个任务的回执串用。GET 查询不产生修订或待办。

## 数据与接口

迁移 `0248_development_document_amendments` 新增可更新补正草稿、不可变修订账本、核料退回问题草稿字段及有效资料只读视图。0222 / 0225 不可变触发器、原发布记录、轮次及历史材料事实均不修改。原 current view 保留；新有效视图给兼容应用读取，不修改全局默认权限。Acceptance 应用只获得新视图 SELECT，复用已有窄授权方式；新表按校验和绑定的迁移清单处理。

接口均位于原 `/digital-production/sources/:sourceId/development` 下：

|接口|作用|
|---|---|
|GET /amendment?taskId=…|读取当前有效退回任务、正式依据、退回问题及本人可处理的草稿|
|PUT /amendment|有版本的草稿保存，带原幂等键|
|POST /amendment/submit|同事务追加修订并交文员复核；纯补料不伪造资料修订|
|GET /amendment/receipt?taskId=…&operation=save或submit&key=…|当前操作者的原命令回执，只读|
|GET /amendment/history?round=…|原快照及本轮修订记录；延续技术资料读权限，隐藏原先权限外的订单草稿|

## 回归与后续验收

- 新专项真实 PostgreSQL 测试覆盖：草稿不生效、同轮追加、幂等并发、唯一复核与待办归属、非法身份 / 版本 / 轮次、Root 正规停用与恢复、纯补料 / 混合补正、事务失败原键重试、身份变化失效、原始快照不可变、纸样通过真实委派激活后的拒绝覆盖、实际 AuthService + 独立 TEST 会话的 HTTP 允许 / 拒绝。
- 外部身份提供者使用本地 TEST 替身，实际 AuthService、PostgresAuthStore、角色 / capability、businessActor、API 与数据库均执行；不声称钉钉外部集成通过。
- 组件浏览器覆盖桌面 / 窄屏、409 保留输入、原键 / 原内容重试、结果未知锁编辑、只读回执、回执暂缺不当未提交、已提交后刷新失败不重提。使用合成 TEST 响应，不能代替真实 API 页面或现场验收。
- 同类实库回归包含原开发、核料、Journey、完整业务链及原打板工资 / 最终确认；合法夹具补上主布规格与具体退回位置，不删除原断言或放宽业务校验。
- 现场待验：原设计师 → 文员 → 同轮补正 / 补料 → 唯一复核 → 总委派的真实角色页面链、现存旧单与当前部署版本。不得以本地 / CI 通过冒称 ECS 人工验收。
