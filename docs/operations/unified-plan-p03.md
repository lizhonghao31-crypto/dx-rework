# P03 创建资料及逐码制作数量

基线：release/digital-production-v1@7abe0545f43fda60dbe8bf403e76259e0ac29424。
本 PR 独立增量基于 P02 `74183ddf84696b4c29805a0f2ae813a6684f86ad`，堆叠 base 为 unified-p02-amendments。P01 新浮层只在总委派启用，创建页未启用其可选模式。管理座舱 UI 不改。

## 结果与边界

新建、草稿续填及实际复版在同一尺寸表填写每码制作数量。新增 JSON 字段 `documentFormatVersion: 2`、`sizeQuantities: (number|null)[]`；对应原 sizes 的每一列。草稿允许 null；发布必须全为 0—100000 整数、至少一个正数、总和等于本轮 quantity（1—100000）。0 保留技术尺寸但本轮不做。PO 订购数量独立，不借用或回写。

创建页按认可首批视觉样板（Library libfile_df52d24e255c8191bb8754a54d7d3f03）和原系统字段整理为 5/4 大区：基本资料、可选订单明细、款图/制作说明/打板信息/唛类、尺寸表/面辅料、工艺要求。桌面基本资料两行，一套 DocumentToolbar 随实际滚动可达。材料品名与规格有常驻标签，原 label 低频称为材料标记。字段、技术参数及原报价校验未删减。PO首行尺码与订购数量同行，其余PO沿同一列只读显示尺码；改名同步全部行、保留各自数量。多列只在表内横滚，资料长表自然增高。旧草稿各PO原尺码不同的，按原行编辑/补项，避免共享改名覆盖另一PO的尺码或数量；不自动合并或回填历史订单。仅创建与开发文档宿主样式，无全局 input 或座舱布局规则。

尺码列会话标识独立于名称；重排、删除、增加、改名、模板替换和撤回同时维护尺寸值、制作数量及原始输入缓冲。非法原始数量不被悄悄保存为 null。摘要、核料依据、打印、板房办理、归档与首次原生执行统一使用共享的制作数量表达；0 列仍在打印矩阵中。

开发日期由来源 created_at 的北京时间日期固定；客户日期独立。已有保存日期保留，旧空日期草稿只在明确保存时规范。服务端拒绝改写，前端只读。新建页面尚未保存时使用服务器日期预览，首次保存取得同单日期。实际复版沿原首次日期；旧冻结资料缺失日期仍为未知，不用今天补造。

## 历史与写入

唯一一次 Codex Review 的两项发现已落实修复：旧资料从尾查退回或关联原执行返工建立新轮时，在原操作页逐码填写制作数量，携资料版本与数量数组提交；总量、尺码列、原技术资料不能借此改写。缺填、合计不符、分数或过期资料拒绝且整笔回滚，合法输入仅升级新轮，冻结旧轮与未知首次日期不变；新格式已有有效数量时不能用该兼容输入改制作分配。沿原尾查/返工权限，不新增审批、节点或通用编辑权。关联原执行详情仅向本来可见技术资料且有合法返工动作的当前读取提供所需制作依据；历史节点不带入当前依据。

系统生成的长制作摘要在关联执行单更新附件、日期、备注时原样保留，编辑页以只读全文表达，不再受旧 200 字输入框阻断。更新传输兼容 2400 字，服务端只允许本来关联且与原长摘要完全相同；替换、缩短或清空拒绝，不扩大独立自由文本的创建/编辑限制。品类、执行价、数量、工资和附件原权限均保持。

无 SQL migration、无批量回填。原 sampleSize 仅保留历史读取。新建、旧草稿首次发布及实际新轮发布均强制新制作协议；省略/降级版本不能跳过发布校验。

同轮补正的历史兼容资格只从服务端已读取的正式冻结资料取得；必须原技术版本与制作数量字段都缺失，且原尺码、总量和旧尺码文字不变。P02 不可变字段守卫仍拒绝制作事实改变。新格式不能伪装旧格式；旧快照补正不自动推算逐码数量或补历史日期。

所有保存、发布和实际复版沿原设计师本单所有权、Root、expectedVersion、幂等键、附件绑定、报价和事务。普通角色/错误总量/假日期拒绝后无部分待办或执行单。首次原生执行由私有开发适配器容纳最多 20 个完整尺码名称，公共旧打板自由文本接口仍保留原 200 字上限，价格、计件和工资规则不变。

回退不能直接降至不识别新 JSON 字段的旧 API/Web；可以撤视觉层，保留双格式 reader 向前修复。不得删除新文档、补正账本或历史快照。未合并、未部署；未来组候选与重定向 release 后须按新 HEAD 重验，现有结果不是 ECS 验收。
