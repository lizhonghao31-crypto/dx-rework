# P06 共享辅料目录与可搜索弹窗

基线 release/digital-production-v1@7abe0545f43fda60dbe8bf403e76259e0ac29424，堆叠 P05@e2dd464a22558d84625df1abe5c0df577b942ebb。对应 B13/B14，保持 B15 的明确分类规则。所有 PR 为 draft，未合并或部署；不改变管理座舱 UI。

## 已确认规则与用户结果

订单跟单、设计师、供应链总监、老板、经 RootAuthority 验证的 Root 可以直接新增、改名、合并重复辅料与停用。不增申请、审批或待办，不授予恢复启用、供应商维护、采购、库存、金额、工资、人员或其他订单权限。

材料行使用共享搜索弹窗选择，标题和选中行清楚显示完整品名、分类及规格；B13 按创建页选中扁机后文字不可见处理，不假定丢数据。搜索覆盖全目录后分页，可看停用/已合并记录，不能把它们当新选择。不存在时直接新增；目录保存后明确提示订单尚未保存，用户再选入本行。弹窗在 body 的 portal 中，提交阻止 React 冒泡，不会连带提交外层创建/资料表单。

仅选择时写入本行名称、规格、供应方、明确分类和可追溯目录 ID/版本；保留本行 materialId、用量、实物及原文员使用事实。手工修改引用字段会解除引用，避免把自由文本伪装成目录快照。名称叫“拉链”的普通辅料仍是普通辅料；例外由既有 auxiliaryKind 判断，目录选择不使文员自动确认使用或到货。

## 数据与权限边界

0249 新建 auxiliary_catalog_items 当前目录、auxiliary_catalog_versions 追加版本、auxiliary_catalog_merges 不可变合并边。目录新增/改名按规范化品名＋规格＋供应方组合去重，同名不同规格/供应方可共存，空供应方不是通配符。新增遇停用的同组合提示核实旧项，不借新增恢复启用。改名保持 active 状态，停用后改名也不恢复。

合并须保留目标有效、双方明确分类/规格/供应方一致并提供原因；源可为已停用的重复项，合并仍不恢复它。按固定顺序锁定双方，拒绝自合并、已合并来源/目标、版本冲突和无法确认同一组合。原名不同的重复项由有权岗位明确确认；不做模糊自动合并。A→B→C 保留原边和版本，通过递归检索旧名找到当前有效 C，不改历史订单引用。不能合回已合并项形成环。

仅新增 auxiliary_catalog:read/write 两项专属 capability，普通四岗位各得两项，Root 沿既有可信特例；没有 master_data:manage 扩权。所有写事务重核有效账号、在职映射、当前任职及该 role capability，并锁住资格；HTTP businessActor 及服务层同验，旧会话声明或伪造 Root 标记不能代替真实身份。读返回自身可维护标志。文员继续读本单快照，不能维护目录。

## 接口及保存恢复

- GET `/master-data/auxiliaries?q=&page=&includeInactive=`：搜索所有合法候选后分页，旧名可追溯。
- POST 同路径新增；POST `/:id/versions` 仅改名；POST `/:id/disable` 仅停用；POST `/:id/merge` 指定保留目标与双方预期版本。
- 没有 enable/restore 接口。严格 Schema 拒绝 enabled、active 或修改分类/规格/供应方等越界参数。
- GET `/receipt?action=&key=` 只读本账号、对应目录操作幂等账本；未知键不等于操作失败。

四操作共用原 IdempotencyService、OperationEventRepository 和短事务目录锁，同键同体只写一次，同键异体拒绝；审计/版本中途失败回滚当前目录与版本。响应丢失、5xx 或不合法回执保留冻结体与原键，锁定编辑；先核原回执，明确同键重试先核后写，不换内容另发。关闭未知操作明确提示不会撤销且会丢失本页核对记录，不承诺跨刷新持久化。

## 订单快照与历史

新可选 auxiliaryCatalog 引用与完整本行快照并存，旧自由文本材料无需回填。目录操作不写任何订单、核验、任务或工资表；旧单读当时快照。服务端在原权限内核对新引用存在、版本和名称/规格/供应方/分类一致，新的选择必须为当前有效版本。已保存旧引用不因目录改名、合并或停用失效，继续修改其余草稿字段保留原资料；明确重选才用新版本。补正/复版草稿也验证新引用，正式资料改动继续 P02/P04 的失效复核规则。原冻结资料不回填、不跟随目录更新。

## 部署与回退边界

需前端/API/0249 schema 同源。迁移只建立目录、版本/合并引用及上述八条岗位 capability 关联，不分派真人角色、不导入历史材料。沿既有迁移模式，仅在迁移事务内打开 capability_catalog/role_capabilities 的 insert 保护以添加本次声明，随后恢复，普通运行期仍不可改目录授权。manifest 和 checksum 绑定的 Acceptance 低权限要求一起更新；代码施工不等于已经执行现场迁移。

回退优先撤新入口或回退前端并保留目录表、已写版本/引用/审计。旧客户端严格材料 Schema 不认识新增引用，不能直接让旧客户端覆盖已有引用资料；需保持兼容 API/新版读写或只读，不能删除字段/版本或降库来掩盖兼容问题。

## 验证与未测

本地真实 PostgreSQL 覆盖五身份四操作、文员/工人/伪 Root 及停用身份拒绝、同组合并发去重、同键复用/异体冲突、规格供应方差异、版本冲突、链式合并及禁止环、版本不可改、审计失败回滚、真实开发保存/发布快照保护、旧草稿继续保存、目录权限不扩订单权限、全目录分页、真实 Fastify 路由严格校验与无恢复命令。普通运行期 capability catalog insert 保护另验。

浏览器测试运行实际材料宿主和弹窗，两宽度共 10 场景，HTTP 为明确合成 TEST 响应，本地浏览器草稿重开不冒称实库端到端；真实服务保存/发布、权限和事务由 PostgreSQL 测试另验。常规套件、开发/补正组合回归、迁移/低权限兼容、构建、FULL 及唯一 Review 结果按最终 HEAD 记录。ECS/现场账号、真实移动触摸与部署验收尚未执行；D08 已在 P04 按用户选 B 实现文员主动接回核料，沿用其权限／事实保护，设计师全单可见与时间设置专项延期。

前后端路由通过真实 Fastify 注入与 createWebUrls/rewriteApiProxyPath 一起校验：根路径和 /acceptance/ 的浏览器 /api 前缀经既有代理剥离，后端注册 /master-data/auxiliaries，不重复注册 /api。此为施工自查修正，不是现场部署结论。

## 唯一 Review 并发补修

Root 目录写入沿原 RootAuthority 的 bootstrap/钉钉企业与身份判断，但在该目录命令连接内重核并以 FOR SHARE 锁定 bootstrap、app_users、identity_mappings；不新增 Root 岗位要求或改变其它调用方默认行为。人员同步先锁并停用时，命令等待后拒绝且不写目录/审计；命令先持有资格时，同步须等其事务提交，随后下一命令拒绝。两种交错分别覆盖身份 active 与 employed；另用合法用户资料更新证明 app_users 行锁，并断言 Root 的受保护 enabled 停用继续被原数据库守卫拒绝，不为夹具伪造停用状态。最初 enabled=false 夹具被原守卫拒绝，失败保留后改用合法身份场景；测试仅在独立 TEST schema 初始化身份，实际目录动作走原服务。没有用事务外连接的旧结论替代事务内资格。
