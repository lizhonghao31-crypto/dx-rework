## 部署交接

按项目现有发布流程使用固定 commit 的前后端产物，并应用 manifest 中新增迁移。PR08 的 `0170_order_responsibility_revision.sql` 是重判及历史已扣衔接的必要迁移，不能只更新前端。数据库升级、Root 边界及原生 PostgreSQL 业务链以 PR08 当前 Head Full Gate 证据为准。不要在低配置 ECS 上重新运行 CI/Full Gate。

代码合并和自动测试不代表生产已部署；本文件不记录尚未进行的业务验收为通过。浏览器策略未允许本地实际预览，手机与桌面的真实视觉结果在本次部署后核验。

## 日常场景验收

| 场景 | 预期结果 |
|---|---|
| 回货差异、装箱差异 | 从原卡片“去处理”上传并回看图片；筛选当前差异、缺装箱单、已处理或历史处理失效，统计和列表范围一致 |
| 供应商目录与资料维护 | 目录只读查选、资料页按原权限维护；上传已有但缺资料的供应商时识别并补空，新资料不会重复建档；有值差异明确选择 |
| 流程等待 | 搜索款号/单号等，节点筛选联动；能看到真实上一提交人、当前处理人/多人工序及往返记录，点击进入原单办理 |
| 实时生产 | 原列表中查看剩余量、工作日、日需求及近3个有效生产日均量；压力/未更新筛选可追到订单；Root 行内删除沿用预览确认 |
| 样衣分析 | 所有原筛选直接可见；采购与处置日期仍按各自原口径，原借还/处置动作可正常进入 |
| 返工返回 | 从有搜索、状态、日期和页码的列表进入详情，左上返回后条件和页码保留；直接打开详情可返回返工看板 |
| 重新判责 | 正式角色或 Root 填原因创建新责任版本，原处理人收到待办；全本厂也能操作；重新提交老板确认，驳回可再调整 |
| 重判与金额 | 原责任、签字、工资及实际已扣记录可查；新台账只处理余款；员工工资不重算；新增展示最多2位。退款/抵账/冲销的新流程不在本轮范围 |
| 手机 320/375/430px | 搜索单独一行，更多筛选可开合；当前办理优先，照片/流程/历史折叠；工人位于工序组，判责点编辑展开；按钮、软键盘及底部导航不相互遮挡 |
| 桌面与原工作区 | 收货、报数、IE、责任、扣款、样衣和外发原表单可继续办理；分析读取失败时原办理入口仍可用 |

长期规则见 `docs/requirements/business-analysis-limited-ui-golden-source-v1.0.md`，逐页收口结论见 `docs/engineering/b-plan-pr10-system-ui-audit.md`。
