# P05 总委派与原执行特殊办理

基线 release/digital-production-v1@7abe0545f43fda60dbe8bf403e76259e0ac29424；堆叠 P04@6c65a0b326e972c5872e86f15db4244ac700c709。对应 B19、E04—E08，继承 P01 浮层和 P02—P04 协议。所有 PR 保持 draft、未合并；不涉及部署或真实订单。管理座舱 UI 不改。

## 用户结果与兼容

设计师列表每行只有明确的“打开开发单”链接，复用原打开地址及来源。总安排显示工序状态和真实阻断，小返回保留来源；不另开条件页面。核料通过跳同单同轮继续沿 P04 协议，不重复提交核料。

总委派的受权详情复用原板房 React 办理组件及后端 actions，提供返工金额、已有执行段换人、原资料与取消等原有操作。首次正常车板不重新出现主管常规派工；返工轮提供原人员及明确金额输入，0 元可提交，空白不可。文员不因新宿主获得价格、工时或特殊办理权限，原 native API 及旧独立打板、杂事、历史办理入口保留。

人员安排未保存时不同时开启原执行特殊办理。接管不兼改人；已结束、旧轮、停用身份、资料/安排/任务冲突继续由原服务守卫，输入与失败恢复沿既有协议。不改变工资算法、冻结价格、实际执行段历史或工时。

## 原子换人与返工金额

新增开发关联换人适配 POST `/digital-production/sources/:sourceId/execution/transfer-execution`，共享 `DevelopmentExecutionTransferSchema`；验证 source/order、轮次、原执行版本/segment、资料/安排版本及任务快照。沿既有 lifecycle 锁和 commands 幂等账本，在同一事务调用原 native transfer，再同步本轮人员安排、当前数字任务与待办。原 native transfer 也调用同一同步函数，不能经旧入口形成两套归属。

原段金额由主管明确填写，余款仍由原 native 算法分给新段，历史段保留。当前数字任务是关联新流程的待办来源，不额外派发重复的 native 执行待办；原旧待办正常结束。同步/审计中途失败整笔回滚。原执行尚早于总安排、无当前数字车板任务的历史兼容路径不伪造任务、核料或新计划。

返工核定沿原 assign 权限和接口。普通主管须沿已保存的本轮人员安排，若要改已有安排，应先明确改派及原因；Root 原有特权保留。金额核定和数字前置不是同一个事实：核定不跳过核料、裁板或材料/质量条件，不更改冻结资料。

## 换人结果未知

新增仅限本账号、本 source、本命令键的只读 receipt，原 native reader 继续负责可见字段与 actions；无权限不得读价格/人员，未知键不代表失败。读取在同一只读可重复读快照取得当前原执行和原命令回执，附原提交版本，以区分本次已完成和后续又有人办理。

发送后网络、服务异常或无有效回执保留冻结请求体及同一幂等键，锁定编辑，不声称未写入或撤销。核对只发 GET；明确沿原标识重试时先查回执，未查到再发完全相同请求。确认回执后显示当前执行；若已有后续变更，明确提示本次已有回执、当前是最新记录。页面内关闭需确认且保留核对卡片；离页明确提示会丢失本页重试记录，不承诺跨刷新持久化。这是本换人操作的有界恢复，不重造 P10 全局请求框架。

## 导航

原板房返回白名单接受经 `digitalDetailReturnUrl` 严格验证的新开发/总委派来源，支持 basePath 与有限嵌套，拒绝跨域、反斜杠、重复字段及超深嵌套。保留旧待办、工资、历史列表来源。内联特殊办理忽略页面数字 round 参数，不能把它当作 native round UUID；提交后不改写总委派 URL。原筛选和滚动仍通过既有来源状态恢复。

## 验证与边界

证据绑定 PR 最终 HEAD：常规单元/集成、完整业务及补正 PostgreSQL、金额/工资相关原回归、10 个真实 React 特殊办理浏览器场景（两宽度，合成 HTTP）、原核料/委派/逐码数量组件回归、lint/type/build、FULL 和唯一 Review。浏览器合成响应不冒称实库端到端，实库事务和角色另行验证；超时、跳过和未测如实记录。

实库重点包括文员越权零写入、错误 source/轮次/资料/安排/任务快照、非法金额、审计中途失败回滚、128 字符键并发去重、原段金额守恒、旧人不可读新任务、新人唯一待办、原入口同步；主管返工明确 0 元、空白拒绝、越权及擅改已安排人员拒绝。原独立打板、杂事工时、取消费用、工资和历史由原业务套件回归。

## 唯一 Review P1 修订

原 native 有权换人与日常安排编辑权分开。同步不再调用 management=keep 的日常保存命令，而是重新验证原 native assign/transfer 权限及已写入的真实当前执行段，在同一事务只同步该车板人、保留 manager 和其余工序，记录计划/任务/原生审计。普通安排的接管、原因、候选和终态守卫不放宽。

Root 原有无工人角色执行特例以 access_is_root_actor 和当前原执行段、有效人员映射为证，限定开发车板同步及实际已归属人员的有效性/前置恢复；不授予工人角色，也不把 Root 加入普通总安排候选。原 native 对可选接手人的判断保持原 SQL。新增独立实库授权场景验证另一合法安排管理人在场时主管仍可换人、管理人/其余行不变、Root 无工人角色转自己、无权拒绝、普通安排不能借此挑选无角色 Root；原快照并发/同键/中途失败回滚回归保留。未提高超时，授权兼容与原子性分为独立测试。

P08 扩大回归补出的旧单兼容：只有开发关联 link、没有开发资料且没有任何数字任务/安排/派工/轮次/执行事实的历史原生单，继续原 native 换人/返工核价授权，不补造流程。判定在原 native 权限和生命周期锁内完成；已有任一数字流程事实却缺资料仍明确拒绝并整笔回滚，不以“缺资料”当通用豁免。原 misc/关联历史集成回归扩展 Root 及主管合法换人、普通工人拒绝、零数字事实未新增。
