## 已实现的业务闭环

首次打板保存品类价快照、原 PDF/图片与本次款号，主管派给现有正式工，工人完工后由原设计师交接放行。杂事保存创建时小时价，主管填写实际工时；完工和工时齐备即计薪，不等待发起人确认。

返工留在原单中，派工时明确金额后才增加次数；零元留流程记录不产生待结清工资。多次换人保留各段真实劳动，金额守恒。取消保留真实停止、部分费用和历史，打板费用由设计师单独确认，不伪造样板交接。

所有有效工资进入同一工资管理。工资月份按劳动完成日；跨月交接可给历史月新增未结算行。结清仅标记本次预览 ID，原金额、责任、扣款和流转不变。按真实人员 ID、来源+订单 ID 汇总，轮次和条数单列。501 条验收中，500 条仅限制预览，汇总、导出、结清全部覆盖。

## 上线前准备与权限

| 操作 | 可执行角色 |
|---|---|
| 配置唯一板房主管 | Root，为现有员工赋予 `pattern_room_supervisor`；不新建另一个员工档案 |
| 查看/调整品类价格 | 查看：Root、老板、生产管理、财务总监、板房主管；调整：Root、老板、生产管理 |
| 配置杂事小时价 | Root、老板；初值未配置，不能编造为零 |
| 首次打板创建/交接 | 设计师本人；Root 保留调试特权 |
| 杂事创建/资料/完成确认 | 设计师、订单跟单，仅本人任务 |
| 派工/换人/实际工时 | 板房主管；唯一现行主管约束由数据库执行 |
| 工人执行与费用 | 当前工人执行，费用只看本人执行段；不能进入工资管理 |
| 工资查看/导出 | Root、老板、生产管理、财务总监、工资月结会计、财务全局查看 |
| 工资已结清 | Root、财务总监、工资月结会计、财务全局查看；老板/生产管理只读 |

普通业务角色及 Root 的 HTTP 允许/拒绝、伪造权限拒绝、最小财务字段均有自动化证据。普通主管没有全员工资查看或标准价格修改权。设计师只取得选定报价；财务工资入口不自动获得板房原文件权限。

19 个初始化品类及逐项工价见需求第 7.2 节和 0175；已对照提供的原图复核。两项套装按套，其余按件。初始化重复执行不能覆盖后来调价。小时价保持 NULL 直到实际维护；任何明确零价必须是授权管理人主动配置并有原因与版本记录。无主管或小时价未配置的业务错误会明确提示，施工没有代业务负责人选择人员或价格。

## 部署、现场验收与恢复

1. 部署由业务负责人按现有运行手册执行。选择本阶段最终合并后的 main 版本，核实备份及当前迁移版本，使用已验证发布包；不要在低配 ECS 重跑 Full Gate。
2. 应用与 0174–0179 配套发布；只补缺失迁移，前后端和版本标识一致。若曾单独发布 PR01/02，继续执行后续追加迁移，不重复覆盖历史。备份、migration、重启等多步命令按既有独立脚本执行，不粘进当前登录 shell 或 source。
3. PR06 配套代码打开共享订单开关。正式使用前完成唯一主管及实际小时价配置，核对 19 项价格；使用不同角色核对菜单、创建/派工/完工/交接、PDF 下载、工资与结清范围。
4. 现场验收重点：钉钉真实待办收取及深链、长名称/大量明细、五种尺寸、真实 PDF、窄屏表单和错误提示。浏览器会话目前为 ERR_BLOCKED_BY_CLIENT，未提供视觉或钉钉现场完成结论。
5. 如需恢复，先暂停新板房业务入口并保持财务数据可核对。没有新数据时可按既有流程回退配套应用；已经生成劳动/工资时保留新增表、工资 ID、结清和审计。不得删除源执行段、强行反迁移或把已结清工资重算覆盖。只回退到不理解新工资来源的旧应用会遗漏财务展示，不能将其当作已完成恢复。

已知限制：页面工资预览最多 500 条，汇总/结清完整；既有单次 XLSX 导出硬上限 50,000 条，超过会明确拒绝，需缩小筛选。已计薪业务事实不允许普通编辑覆盖，本轮没有新增调账或审批系统。跨月新增未结算是按真实完工日期的预期行为，结清一次不表示月份永久封账。
