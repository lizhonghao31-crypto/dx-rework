# P07 本人事项阅读与列表确认

本增量对应 C01—C05，基于 P06；未合并、未部署。分类为“开发与大货”，内部模块 key 保持 digital_production，原“数字生产”保留为搜索兼容词。搜索靠左，标题与徽章使用 10px 列间距、8px 行间距；品牌 12px 间距仅在已认可页面宿主启用，管理座舱不启用。未改变其布局或业务状态算法。

## 阅读事实与权限

0250 新建按本人、事项 ID、稳定内容 token 唯一的追加回执，首次时间不因重试改变；总委派和面料报告是派生事项，故不对 todo_id 加任务外键。回执有本人 app_users 外键与不可更新/删除保护。任务 token 使用任务、轮次、状态、受办人及持久化事件数；总委派使用单轮、资料、核配通过事实、安排管理人及尚未安排的适用行；面料用不可变报告及当前轮次。无关工序优先级不把已读总委派或报告重置。实际新内容、改派和新轮重新未读，不按查询时间或固定 DTO version 猜测。

POST /todos/mine/:todoId/read 沿原 todo:view 鉴权，拒绝客户端 recipient 字段；服务重查本人当前收件、完整路由、实体和轮次。数字回执在原任务生命周期锁内重核本人 provider；失效/旧 token 不写。Root 只能写自身真实收件，未因为 Root 浏览其它人的事项制造回执；原岗位收件规则不扩展。生产风险适配原 ProductionClosure.markRead 与 0151 阅读记录，不另写 0250 竞争记录。旧普通待办不伪造 token 或历史时间，继续显示“待处理”。

pendingCount 继续原混合兼容口径，没有改成未读数；新增可选 unreadCount 明确仅包含当前本人、有阅读协议的开发与大货/生产风险事项。生产原 pendingCount 中的未读风险计数仍保持旧义；数字读过事项仍在数字待办件数内。普通已读显示“已读”，生产风险显示“已读 · 风险仍在”，并不表示风险解除或任务完成。

## 真实内容成功展示后回写

个人深链先核本人事项 metadata，随后挂载原业务读取，避免在旧正文之后取得新 token。实际总委派、开发任务、核料、资料补正、开发资料/问题面料、大货及生产风险主体成功并可见才调用阅读；目录、读取失败、错误实体/轮次、未展示的报告不调用。辅助候选错误不否定已经可见的正文。旧链接或 metadata 403/404 仍让原内容按原权限读取，但不标读；metadata 服务异常允许明确选择继续查看，本次不标读。

发送阅读写入后不取消或暗示撤销；无效/丢失回执保留原 token 和路由，正文继续显示，只提供“仅重试已读同步”。自然唯一键保证相同内容重试不改首读时间，不重发核料/委派等业务命令。后台/隐藏正文不标读；账号切换卸载原正文并丢弃旧回包。本人列表保留原强制会话核验；核验完成后按本人身份重新挂载壳，避免旧会话请求被作废后壳永久停在无身份状态。指标回包再核会话代次、当前本人及取消状态，首次计数事件也按已验证本人保存。跨标签只广播当前 actor ID 与失效信号，接收方核对自己的会话，重读本人列表和指标，不传业务正文。

## 验证与限制

真实 PostgreSQL 验证任务首次/并发/重试、旧 token、改派、权限与伪造收件人拒绝、总委派部分安排与无关工序变化、问题面料独立收件和实际决定后消失、生产原阅读记录兼容。读操作前后任务与报告事实一致。HTTP 合同测试覆盖允许、403 和严格拒绝 recipient 伪造。

浏览器运行实际阅读边界、成功可见回调、MyTodosPage、Shell，使用明确合成 TEST HTTP 响应；覆盖正文/辅助失败、权限/旧链接、无协议、错实体/轮、隐藏、StrictMode、未知写回执重试、换身份迟到回包、跨标签持久化和过滤他人信号。原全局搜索、分页和返回上下文断言保留。品牌/座舱对照使用 P06 的 Shell/CSS 与本候选在 390/1024/1440 宽比较。不是 ECS 或真实现场全链路验收。

具体最终 HEAD 的常规测试、数据库、浏览器、迁移、FULL 和唯一 Review 证据记录在 PR。D08 用途异议仍待用户选择，未算通过。主管接管/工资等沿前组，不由阅读协议更改。
