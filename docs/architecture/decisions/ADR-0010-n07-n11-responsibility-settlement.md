# ADR-0010：N07–N11 责任判定、老板签字与后续结算闭环

- 状态：已接受
- 日期：2026-08-13
- 决策人：业务负责人（本次书面确认）
- 适用范围：N07–N11 的责任判定、老板签字、责任结算台账、订单完成与后续结算

## 背景

旧流程把供应商选择、老板审批、应付接收和实际扣款混在同一条主订单状态链中。供应商已经由业务资料确定后，仍会出现“锁定供应商”“应付确认”的重复点击；老板还需要为每一张单再次确认供应商，既不符合职责分工，也拖慢订单结束。

同时，责任方可能是本厂、加工厂、印绣花厂、洗水厂或面料商。将这些事实堆在一个区域会让业务人员无法清楚核对每一方的比例、倍率、供应商与金额。

## 决策

1. 主订单链固定为：N07 **责任判定与资料核验** → N08 **老板确认签字** → N09 **责任结算台账**（系统自动、只读）→ N10 **订单完成**。N11 是独立的后续结算，不阻塞 N10。
2. N07 由生产管理负责。每个工序按责任方独立维护工作区域；责任比例必须合计 100%，外部责任方必须绑定匹配类型且启用的供应商。金额公式为：`工序基础金额 × 责任比例 × 责任方倍率`。本厂倍率最低/默认 1.0，外部倍率最低/默认 1.2。
3. N08 仅由老板权限组执行。老板确认的是生产管理提交的一整套责任事实（责任方、比例、倍率和供应商快照），不承担逐张核对供应商的职责。界面只提供“确认同意”和“驳回”；驳回不要求填写理由，直接退回 N07。
4. N08 同意后，系统在同一事务自动生成 N09 的每个外部责任方台账，并立即让主订单进入 N10 完成。没有外部责任方时，N09 仍作为只读系统结果存在，但不产生供应商扣款事项。
5. N11 分为工资结算与供应商实际扣款两条独立后续链。应付只记录真实扣款、凭证和未扣差额处置；不再“确认收到任务”或重新选择供应商。后续扣款未结束不重新打开已完成订单。
6. 已完成订单如需调整责任，走受审计的责任调整路径返回 N07，生成新的责任版本、老板签字和台账版本；订单详情显示“责任调整中”。

## 一致性与权限

- 数据库触发器校验 N07→N08→N10 的合法状态转换、审计事件、版本递增及供应商快照。
- N07 不允许提交比例不满 100%、外部供应商缺失或外部倍率低于 1.2 的版本。
- N09 只能由服务端根据不可变的 N07 正式版本生成，浏览器与应付用户不能篡改责任金额、倍率或供应商。
- N08 和 N11 都使用幂等键与订单版本校验；所有决定保留操作事件和快照。

## 后果与回滚

- 老板只做最终签字，生产管理对资料质量负责；会计只处理真实扣款事实。
- 主订单不会因工资或外部实扣长期悬挂，业务完成状态与财务跟进状态可同时清晰展示。
- 本次不迁移历史测试订单。若需回滚，撤回代码和未应用的迁移；对已经生成的正式责任台账不得直接手工改写，应通过受审计的责任调整流程处理。
