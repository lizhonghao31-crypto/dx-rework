# ADR-0003：稳定身份、角色权限与版本化基础资料

- 状态：已采用
- 日期：2026-08-02
- 适用 PR：PR-04

## 决策

1. 登录身份只使用公司组织内的钉钉稳定身份链：`corp_id + provider_user_id + union_id -> app_user_id`。首次启动将配置的公司 `corp_id` 写入不可变安全策略；此后配置与数据库不一致时服务拒绝启动。已建立映射的用户、组织、钉钉用户 ID 与 union ID 均不可直接改写；同一 `app_user_id` 只能存在一条映射，同 union ID 的新登录入口继续落到原用户而不重写稳定键。姓名和别名均不得参与鉴权。
2. 业务权限由“有效角色能力 + 有效全局代理”计算；`user_capabilities` 仅作为旧版迁移痕迹保留，不再参与鉴权或转授权。全局代理仅在授权人仍属于本公司组织、在职、启用且仍持有被代理能力时生效。带业务范围的代理不进入会话级全局能力，后续业务接口必须用单据或目录范围再次核验。
3. `owner_group` 是李总与伍总共用的同一角色，两人因此取得完全相同的能力集合。
4. `production_management` 具有完整管理事实、责任判定和接管能力，但没有 `own_factory:approve`。
5. `system_admin` 可管理角色、基础资料、代理和审计，但角色本身不含责任判定或本厂承担最终审批；系统禁止管理员给自己授予角色或代理。
6. 本厂承担代理只能由老板权限组成员本人作为实际操作者和授权人发出，并且必须限定到具体返工单和起止时间；系统管理员不得代填老板为授权人，它也不会成为代理人的全局能力。
7. 临时工只有 `business_people` 档案，没有 `app_user_id`，因此没有登录身份，只能由内部人员代录。
8. 有效人员别名全局唯一。业务确认的“李生”只可在受控引导中绑定李总对应的 `person_id`，李同生必须使用另一稳定 `app_user_id/person_id`。建档和别名绑定必须填写原因；误录时只能填写原因撤销旧映射，再向既有正确 `person_id` 新建映射，不能静默改写历史。人员身份字段建档后不可改写；只有临时人员能在撤销全部有效别名后走带原因、操作者与事件的单次停用。管理接口可显式查询已撤销别名；数据库先对显示别名执行 NFKC，再去除完整 Unicode 边界空白及不可见分隔符并转小写生成唯一归一键，不信任调用方传值；同一人员的并发别名新增及新增与停用均由目标人员排他行锁串行化。数据库触发器要求每次新增、撤销和停用在同一事务内生成完整操作事件。
9. 工序与供应商采用稳定主键加追加版本。名称、启用状态等变化新增连续版本，不覆盖历史；数据库锁定稳定目录键，且每个新版本都必须通过数据库实时核验的 `master_data:manage` 授权和同事务事件。稳定目录项的新增还由延迟约束保证同一事务必须存在经过授权、带完整审计的第 1 版，禁止留下无法修订的无版本孤儿。
10. 所有角色、人员、目录和代理写操作都追加 `operation_events`，记录可信用户、由数据库现算的角色快照与授权能力、请求 ID、变更前后值和原因；角色与代理的新增/撤销、人员建档/停用、别名新增/撤销、工序/供应商版本新增均由数据库触发器强制审计，不能用直接 SQL 绕过。角色定义、能力目录及角色到能力的映射是迁移内审核过的不可变策略，运行时不能增删改或停用；未来调整必须使用新的前向迁移。数据库鉴权与会话鉴权同样承认仍有效的全局代理，但不承认带业务范围的代理。角色/代理/别名撤销包含撤销后的状态，初始别名绑定包含稳定 `alias_id` 与原因，工序/供应商修订包含上一版本快照。老板角色新增、撤销和钉钉身份停用共用同一事务锁；撤销时只统计仍启用、在职且位于已绑定公司组织中的可用老板，外部组织身份不能充当保底老板。

## 首次部署引导

代码和迁移不会预填任何真人姓名与钉钉 ID。部署人员必须在业务负责人在场时，从钉钉组织接口核验稳定 ID 后执行一次受控引导：

1. 在安全策略尚未锁定前，由数据库管理员建立首位 `system_admin` 和首位 `owner_group` 角色绑定；这是唯一允许的无应用审计引导窗口；
2. 写入并锁定唯一公司 `corp_id`；应用首次启动会自动执行且会拒绝以后换成其他组织；
3. 核对李总与伍总是两个不同的稳定用户 ID，并绑定同一个 `owner_group`；
4. 绑定张文豪为 `production_management`，确认能力中不存在 `own_factory:approve`；
5. 绑定李同生为 `tail_supervisor`；
6. 创建李总人员档案并添加“李生”别名；不得通过姓名搜索或模糊匹配自动完成；
7. 保存执行人、复核人、时间、稳定 ID 及 SQL/工具输出摘要，且不得把密钥写入仓库。

首次引导是部署操作，不是运行期的姓名授权后门。后续变更必须走服务接口并进入追加审计。

## 与 ERP 的后续接入

`app_user_id`、角色代码、能力代码、`process_id/process_code`、`supplier_id/supplier_code` 均为稳定契约。未来 ERP 节点只传稳定 ID/代码，不复制角色判断或基础资料，不依赖显示名称。

## 后果

- 在未完成真人稳定 ID 引导前，代码可以合并和迁移验证，但不能宣称业务人员已获授权。
- 显示名变化不会改变权限。
- 范围代理需要未来业务接口显式带入作用域校验；仅查询 `AuthUser.capabilities` 不足以批准指定单据代理。\n- 钉钉组织是在职与账号状态的事实源；若最后一名老板被钉钉停用，系统必须拒绝其登录，不能为维持保底人数保留虚假的可用身份。在完成受控恢复前，老板专属操作将暂停。
