# ADR-0008：钉钉主动通知与老板节点任一收口

- 状态：已接受
- 日期：2026-08-12
- 决策人：业务负责人（本次书面确认）
- 适用范围：正式业务待办、高倍率确认、本厂承担审批与首次运行开关

## 背景

钉钉原生待办在创建人与执行人为同一人时不会稳定产生主动提醒，仅创建待办不足以降低漏审风险。现有高倍率规则还会在老板本人提交时排除本人，并在本厂承担处理后另发结果知会，造成老板节点的接收规则不一致和重复消息。

业务已确认：普通节点只路由给一个明确责任人；老板权限组节点必须让每位当前直接有效老板独立收到任务，任意一名老板完成后共同收口。高倍率确认不再排除提交人，但任何非直接老板均不得确认。

## 决策

1. 普通业务节点继续只创建一个责任人待办，不改变既有唯一接收人和转交规则。
2. `owner_group` 共享节点向每位当前直接有效、仍具备目标 capability 的老板分别创建一条内部待办和一条钉钉原生待办；每人再收到一条仅发给本人的工作通知。
3. 同一老板节点使用“业务事实前缀 + 接收人稳定 ID”去重。任意一名有权老板完成业务动作后，同一前缀下其他老板的内部待办和钉钉原生待办全部同步完成或关闭。
4. 不再为本厂承担审批创建并行的旧 pending/result 通知，也不在高倍率草稿创建后向提交人另发“已发起”提示；钉钉原生待办状态即为同节点结果知会，避免重复提醒。
5. 高倍率确认向所有当前直接有效老板投递，包括提交草稿的老板本人。确认权限只属于直接有效 `owner_group`；`system_admin`、Root 或仅伪造 capability 的非老板均不能绕过该边界。
6. 钉钉投递采用“原生待办 + 单人工作通知”组合。原生待办负责可处理状态与完成同步，工作通知负责应用角标和主动提醒；两者使用完整 HTTPS 深链，并以稳定 source key 重试去重。
7. 即时投递/状态同步与定时提醒/升级使用独立开关。首次上线仅启用即时投递和状态同步；历史补发、定时提醒和升级保持关闭。

## 一致性与权限

- 接收人使用内部用户稳定 ID，并通过当前公司钉钉身份、在职状态、直接角色与 capability 共同校验；不使用显示姓名路由。
- 工作通知一次只传一个钉钉 `userid`，不使用广播名单。
- 任一老板收口是同一业务事务内的待办状态变更，后续由 outbox 同步外部待办；失败可重试且不得重复创建任务。
- 历史记录和历史钉钉消息保持不变；首次上线不自动运行历史 backfill。

## 后果

- 每位当前老板都会主动看到可处理任务，但同一节点不会因额外结果知会产生第二条消息。
- 老板本人可以提交并确认高倍率，仍由直接角色数据库校验阻止非老板审批。
- 启用即时投递前必须配置企业内部应用 AgentId 和钉钉可访问的完整 HTTPS 根地址。
- 定时催办、升级与历史补发需要后续单独授权和启用。
