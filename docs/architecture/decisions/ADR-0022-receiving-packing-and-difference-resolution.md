# ADR-0022：订单回货装箱与双差异处理

- 状态：已接受
- 日期：2026-09-04
- 对应范围：订单回货看板、Excel 导出、装箱数量、差异处理

## 决策

1. 订单卡片中的“差异”更名为“收货差异”，计算口径继续为截至查询结束日累计实收减累计送货单数量。
2. 新增“装箱数量”，由尾部主管填写当前累计已装箱数量。每次填写形成不可变修订，最新修订为有效值；不是在旧值上累加。
3. 新增“装箱差异”，计算口径统一为 **装箱数量减累计实收数量**。例如：实收 100、装箱 90 显示 `-10`；实收 100、装箱 110 显示 `+10`。未录入装箱数量时显示 `-`，不把未录入解释为零。数据库约束、API、Excel、前端展示和测试必须使用同一方向。
4. 收货差异和装箱差异分别处理。差异为零时显示“无差异”；非零且当前数值快照未处理时显示“去处理”；提交结果后显示“已处理”。
5. 收货差异由仓管处理；装箱数量和装箱差异由尾部主管处理；Root 保留应急操作能力。前端可见性与后端授权同时校验。
6. 处理结果必填，系统记录处理人、时间以及送货单、实收、装箱和差异快照。底层数量变化后，旧处理记录保留审计，但当前快照自动恢复“去处理”。
7. 订单卡片的“实收”显示截至查询结束日累计实收，与两类差异使用同一数量快照；顶部“期间实收数量”KPI 仍只统计筛选期间，不改变。
8. Excel 导出使用当前日期、款号与状态筛选，导出全部匹配订单，不受页面 15 条分页限制；最多 50,000 单。工作簿包含“订单汇总”和“收货明细”，并记录导出人、时间和筛选范围的审计事件。导出仅授权仓管、尾部主管、生产管理、老板和 Root，不向普通工人或技术管理员开放。
9. 展开的多次收货历史将来源、本次送货单、本次实收拆成独立字段并使用千分位，四位数及以上不得挤压或粘连相邻文字。
10. 历史截止日期看板保持只读：已有差异处理结果可以查看，但不得基于历史快照新增装箱数量或差异处理；款号全时间搜索、截止今天或未来的看板按当前有效快照操作。

## UI

- 导出按钮位于“开始日期”左侧，使用现有中性按钮样式，不改变其余筛选布局。
- 订单核心信息固定使用两层结构，不再使用“主事实区 + 三列操作区”。第一层按顺序展示：**送货单数量｜实收｜次品｜收货差异｜装箱数量｜装箱差异**。
- 第二层仅分为两格：**收货人 & 收货时间**，位置与“实收”信息对应；**装箱确认人 & 装箱确认时间**，位置与“装箱数量”信息对应。不得把人员与时间重新散落到第一层。
- “去处理”为灰底黑字；“已处理”为绿底黑字。两者按钮框和字体相对 PR380 基线同步缩小三个字号级别，保持低视觉权重。点击“已处理”只查看处理结果、处理人和时间。
- 既有款号、返工入口、多次收货展开、附件查看等业务交互保持原行为，不因本次布局调整改变。

## 影响与排除

- 新增装箱修订与差异处理审计表、三项 capability 和收货导出接口。
- 本次 1.5.1 收口只修正订单回货业务口径与卡片信息结构；全系统千分位统一治理由独立后续 PR 执行。
- 不修改返工工序数量上限、返工状态机、报价选厂、合同、跟单财务权限或返工报表状态；这些继续按后续独立 PR 验收。

## 2026-09-10：处理凭证增量

- 两类现有“去处理”弹窗支持选填处理图片，最多3张；复用现有上传校验及图片预览器。
- 图片绑定到具体差异处理记录，与送货单图片隔离；真实处理人、处理时间及图片关联一并保留审计。
- 任一所选图片上传失败时不提交处理；后端绑定失败回滚整次处理。重复提交复用原结果。
- 已处理记录可回看图片；历史无图记录正常显示，后续数量变化不覆盖原记录。
