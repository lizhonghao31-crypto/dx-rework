# ADR-0015：IE 核价前置，工资与外部扣款倍率分层

日期：2026-08-18  
状态：已采纳  
替代：ADR-0013、ADR-0014 中与节点顺序、倍率归属和扣款基数冲突的部分

## 决策

工序、预估数量和单价在 N02 由尾部主管一次提交，并在 N03 由 IE 审核。只有 IE 通过后才允许 N04 分配人员。N05 只记录个人最终数量，N06 只核对数量和临时工实发系数，随后直接进入 N07。

订单级 `pending_ie_review` 只用于 N03 工序/单价审核；N06 后不复用该状态。数量增加申请的子状态独立存在。

N07 每道工序只选择一个责任方。外部责任必须在 N07 选择供应商并确定扣款倍率，默认且最低 1.2。N08 老板只同意或驳回，不修改倍率。

工资与扣款按两层不可混淆的金额来源计算：

- 应付工资 = IE 单价 × 个人有效数量 × 临时工实发系数（正式工系数为 1）。
- 外部扣款 = 已固化应付工资 × N07 外部扣款倍率。

## 原因

分配工人前必须已知并审核单价，现场才能基于确定的计价规则安排工作。完工后再次核价会造成状态复用、工资来源延迟和自动验收中断。

临时工旺季加价属于工资事实，应由尾部主管在核量时确认；外部扣款倍率属于责任追偿事实，应由生产管理在判责时确认。两者可能同时存在，但不能互相替代或回写。

## 后果

- N02 到 N03 重新成为唯一的订单级 IE 核价路径。
- N06 确认会一次性固化临时工系数、个人工资份额和工资项目，并直接流转 N07。
- N07 仍用 10000 bps 保存单一责任方的历史快照，但产品界面和业务规则不再提供比例判断。
- N08 旧的特殊倍率表仅保留历史审计用途，不再写入新数据。
- 旧尾部定价表保留历史数据，但应用层和状态机均不再进入该流程。

## 数据库不变量

- 新工序配置的单价不可为空，配置明细提交后不可修改。
- N06 金额只能由匹配的 `rework.whole_order.approve` 审计事件生成。
- V2 责任工序只能插入一个责任方；本厂倍率为 1，外部倍率不低于 1.2 且必须绑定供应商。
- 老板签字不能创建倍率调整快照。
