# ADR-0007：供应商确定后直接进入应付扣款处理

- 状态：已接受
- 日期：2026-08-10
- 决策人：产品负责人 Eric
- 适用范围：N08-B 外部责任与 N10-B 实际扣款

## 背景

旧流程在供应商已经明确后仍要求业务人员执行“签收提交”，再要求应付执行“接受台账”，之后才能记录实际扣款。正常场景中，这两个点击不产生新的责任金额、供应商或财务事实，却造成重复待办和流程停滞。

责任判定已经固定金额；加工厂供应商来自返工单原始快照，其他供应商由对应业务人员明确选择。供应商确定后，应付可以直接依据不可变责任快照记录扣款，或把资料问题退回业务处理人。

## 决策

1. 新建供应商扣款台账时直接进入应付处理状态，不再创建正常场景的业务签收待办。
2. 原加工厂仍由系统自动建账；其他责任类型仍必须由有权限的业务人员选择一个实际供应商。
3. 应付第一次记录实际扣款时，系统在同一事务内写入既有“应付已接受”审计动作，再写入扣款明细；用户无需单独点击接受。
4. 应付仍可在尚未开始扣款时退回资料问题；退回后业务人员修正并重新提交。
5. 既有历史台账和历史签收/接受记录保持不变，旧状态继续兼容处理。

## 一致性与权限

- 供应商选择、责任金额和原始快照仍由既有不可变表与数据库触发器校验。
- 直接记录扣款同时要求应付处理权限和实际扣款记录权限。
- 隐式接受与扣款明细位于同一幂等事务；任一步失败则整体回滚。
- 订单责任动作完成条件不变：本厂审批完成，且所有外部责任台账至少进入扣款跟进或关闭。

## 后果

- 正常外部责任从“选供应商 → 业务签收 → 应付接受 → 记录扣款”缩短为“选供应商 → 应付记录扣款”。
- 数据异常仍有明确退回路径。
- 历史审计结构与报表合同保持兼容。
