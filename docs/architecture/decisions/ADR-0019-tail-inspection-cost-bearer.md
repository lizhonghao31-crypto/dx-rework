# ADR-0019: 整查费用承担与工资对数职责分离

- 状态：Accepted
- 日期：2026-08-29

## 背景

“是否需要整查”只决定是否进入整查执行，不能推导费用由谁承担。年加工合同未覆盖尾部费用时由本厂支付；回货返工且需要整查时应由加工厂承担。此前判责引擎固定排除整查工序，导致加工厂全责订单的整查工资未进入外部责任金额。

财务只使用工资报表查询、对数和导出，不在系统执行工资核对、月结或会计锁定。

## 决策

1. N01 在选择“需要整查”时，必须同时选择“本厂”或“加工厂”承担整查费用；选择“不需要整查”时不显示该字段并跳过整查流程。
2. N01 的承担方是质检初判。系统同时记录承担方来源（质检初判、历史系统默认、生产主管确认），N07 必须如实展示来源；质检初判由生产主管随责任判定确认，历史系统默认不得冒充质检判断且必须在 N07 重新确认。
3. 本厂承担时，整查工资仍计入工资报表，整查责任按本厂 100%、倍率 1 进入责任总额，不进入外部责任基础。责任基础使用有效工资来源的最终数量 × IE 单价及集体分摊，按既有逐人精度规则计算；临时工工资加成不计入责任。
4. 加工厂承担时，整查工序进入责任基础，并由服务端强制加工厂 100%、倍率 1.2、供应商为订单加工厂。
5. 对没有可证明质检初判来源的历史订单，不再默认本厂承担：尚未完成判责且绑定外发加工厂的订单按“加工厂承担”安全口径预置，并标记为“历史系统默认”；无外发加工厂的订单留空，交由 N07 明确选择。已经完成判责或进入后续财务流程的订单保留既有金额快照，不静默改账。
6. 停止生成工资核对/月结待办；前端不展示月结状态或锁定动作，对外写接口停用。既有历史表和记录只读保留，不得恢复为当前流程。
7. N07 可勾选多道普通工序，将同一组责任方、比例、供应商和倍率批量填入；批量操作只更新页面草稿，仍由既有“提交责任判定”统一校验和保存。整查承担方是订单级事实，不参与工序批量覆盖。

## 结果

费用判定由显式业务事实驱动，不再从“需要整查”或加工厂责任比例间接推断。整查工资进入只读工资资料，外部扣款按独立业务事实执行；工资月结不属于当前系统流程。


## 2026-09-09 历史遗漏修复（业务负责人授权）

审计发现本厂承担的整查被完全排除在责任明细外。经业务负责人明确要求“开 PR 修复并覆盖历史订单”，本次只修复有明确承担方来源的遗漏，不以工资总额覆盖责任金额。

- 新提交：服务端强制本厂整查 100% × 1；兼容旧客户端未提交整查行，自动补入同一审计事务。加工厂承担继续按 100% × 1.2。页面同步显示对应责任行。
- 历史范围：未删除、未取消且仍需整查，承担方明确为本厂、来源为质检初判或生产主管确认的 V2 当前判责版本。包括已完成订单和待确认草稿。已存在整查责任行则跳过；被替代版本、V1、历史系统默认及承担方未明确的订单不推断、不改账。
- 迁移 0165：从有效、未驳回的上数和有效工资快照补入缺失的整查工序、分摊和逐人金额行，同时调整当前版本总额。每个版本记录唯一、不可修改的补齐凭据，保留原总额、新增金额、来源工资 ID、授权依据和新总额。来源不完整则整笔迁移回滚，禁止猜测金额。
- 原判责输入、审批签字、操作事件、工资及外部扣款不修改。原审批记录仍代表当时审批事实，新增金额以补齐凭据解释；不得将历史签字解释为对新增明细的重新审批。这是对第 5 条“保留既有快照”的显式、有限授权例外。
- 示例验收：RW-2026-0826-004 已审计整查 1349 × 0.30 = 404.70；原责任 1551.35 补齐至 1956.05，外部差额仍为 0。迁移不硬编码该单号，按稳定 ID 和来源条件覆盖同类历史订单。
- 部署验收：检查迁移补齐凭据与页面金额；重复执行修复段不得重复入账。金额迁移无自动反向覆盖，若需撤销应另开有审计记录的更正迁移。
