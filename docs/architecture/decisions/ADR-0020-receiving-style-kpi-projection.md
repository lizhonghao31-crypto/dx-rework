# ADR-0020：收货看板按款号归并与KPI口径

- 状态：已接受
- 日期：2026-08-29
- 对应范围：收货看板、日期KPI、款号搜索和状态筛选

## 背景

同一款号可能因分批收货、补录或返工周期形成多个内部收货批次。内部批次用于保留原始收货事实和返工绑定，但管理看板若按批次展示，会重复计算订单数、固定送货单数量和差异。款号搜索同时被日期范围限制，也会漏掉范围外的历史收货。

## 决策

1. 收货事实、补录独立批次和返工绑定保持不变；不批量改写历史数据。
2. 看板新增按标准化款号归并的查询投影。同一款号只显示一张订单，固定送货单数量只取业务时间最早的有效收货批次一次，实收和次品跨有效批次累计。
3. 日期模式先选择日期范围内发生过收货的款号，再计算这些款号截至结束日的累计实收和差异：
   - 期间收货订单数为不同款号数；
   - 期间实收数量只累计日期范围内的有效实收；
   - 异常订单数按截至结束日累计实收与固定送货单数量比较；
   - 绝对差异为逐款号绝对差异之和；
   - 差异率为绝对差异之和除以各款号固定送货单数量之和。
4. 款号搜索为全时间搜索，不受页面已选日期影响；搜索模式下实收、异常和差异均使用全时间有效累计值。
5. 状态筛选在款号归并和差异计算后执行；列表与全部KPI使用同一个筛选后订单集合。
6. 状态固定为：正常（差异等于0）、少收（差异小于0）、多收（差异大于0）。
7. 款号输入、存储匹配、搜索和看板归并统一使用去除首尾空格后的大写形式；不改变中文和数字。
8. 已删除批次排除；Root审计修正按既有事件日期口径应用一次，不重复累计原始值和修正值。

## 兼容与风险控制

- API保留原有看板字段，并增量增加查询模式、累计实收、批次数量和状态筛选，不阻断旧页面。
- 多批次归并行暂不开放Root聚合修改，避免一个批次级修改入口错误覆盖整单累计事实；原始批次和审计记录继续保留。
- 本决策只改变收货看板查询投影与款号标准化，不改变补录期限、图片、返工状态机、权限或数据库结构。

## 验收基准

款号IN20546664的固定送货单数量为4017，两次实收1618和2040时：

- 看板只显示1单、2次收货；
- 全时间累计实收为3658；
- 状态为少收359；
- 异常订单数为1；
- 绝对差异为359；
- 差异率为8.94%。
