# ADR-0016：尾查独立报数与数量交叉核验基础

日期：2026-08-18  
状态：已采纳  
替代：ADR-0015 中“计划数量用于返工执行数量核验”的部分

## 决策

新增业务角色 `tail_inspector`（尾查）。该角色只拥有尾查报数能力，不能配置工序、分配工人、审核整单、判责或查看无关订单。

尾部主管在 N02 配置工序与单价时，可为订单分配一名或多名尾查人员，并为每人填写可选的清点箱数或范围说明。尾查任务的分配、撤销和每次报数均保留不可变审计记录。

每名尾查人员提交一份独立报数：

- 一项去重后的返件总数；
- 每个工序的尾查数量；
- 工序数量初始复制返件总数，但允许逐项修改；
- 每个工序数量不得大于该人员的返件总数。

多人尾查的订单级返件总数和工序数量分别按人员记录求和。工序数量不与返件总数求和比较，因为同一件衣服可同时涉及多个返工工序。

尾查任务在 N02 完成分配后即可启动，不等待 IE 核价、N04 分配返工人员或工人上数。后续流程以“工人完工上数完成且全部尾查报数完成”为 N07 尾部主管整单确认的共同前提。

## 原因

实际返件数量需要来自仓库清点这一独立事实来源。把尾查前置并与工人上数并行，既能在执行早期暴露数量差异，也不会让尾部主管在最后阶段被尚未开始的实物清点阻塞。

工人上数和尾查数量服务不同目的：前者是工资事实，后者是返工业务数量基准。二者只能按同一工序交叉核验，不能让外部扣款倍率、临时工工资系数或旧的计划数量参与数量判断。

## 后果

- 后续流程PR必须删除预计数量、小时单位、数量增加/减少申请和 IE 数量审批路径；IE 保持仅核价职责。
- N07 的确认条件改为每工序“有效工人上数合计不大于尾查数量”；超出时由尾部主管驳回具体工人或尾查记录。
- 工人有效上数低于尾查数量允许确认，但必须展示差额；工资继续只按工人有效上数计算。
- N02 已创建尾查任务后，IE 价格驳回不得重复创建尾查待办或覆盖既有尾查数据。工序变更须显式使受影响尾查记录失效并重新分配。
- 钉钉待办内容和投递体验不属于本决策的施工范围，统一留待后续钉钉专项。
