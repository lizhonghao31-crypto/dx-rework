# ADR-0009：Root 返工单逻辑删除与系统管理导航

- 状态：已接受
- 日期：2026-08-13
- 决策人：业务负责人（本次书面确认）
- 适用范围：返工单删除、关联待办与钉钉终态同步、订单/报表查询、系统管理二级导航

## 背景

业务负责人要求 Root 可以从“全部订单”卡片末端的删除图标删除返工单。确认弹窗只要求取消或确认，不要求再次输入 RW 编号或填写删除理由。同时，人员权限管理与工厂、工序管理必须保留在统一的系统管理二级导航中；工厂与工序合并为一个入口。

返工单关联工资、责任、外部扣款、附件、待办和审计事件。已有数据库守卫禁止物理删除，因此物理清除会破坏不可变证据和历史财务事实。

## 决策

1. 删除定义为 Root-only 的逻辑删除：订单状态变为 `deleted`，记录 `deleted_at` 与 `deleted_by`，禁止再次业务处理；不物理删除订单、工资、责任、附件、操作事件或 OSS 对象。
2. 删除接口仅接受已登录 Root 和幂等键。前端仅在 Root 的“全部订单”卡片上显示低干扰垃圾桶按钮，并在浏览器确认弹窗确认后调用接口。
3. 删除与事件写入、关联开放待办关闭、钉钉外部待办终态投递在同一数据库事务内完成。待办及其投递绑定保留审计历史。
4. 订单详情、业务列表、管理座舱、报表、工资明细、责任/外部扣款明细、异常统计和附件下载授权默认排除已删除订单；审计记录与管理附件事实不删除。
5. 系统管理二级导航抽为共享组件。员工权限管理、工厂&工序管理、审计日志、附件管理、代理授权和系统异常均可从该导航直接切换；工厂与工序不再拆成两个入口。

## 后果与回滚

- 删除对日常业务不可见，但可从审计日志以 `rework.delete` 追溯；这不是数据清除或 OSS 清理功能。
- 已删除订单不再计入实时业务/报表金额和待办异常。不可变工资和责任原始事实仍存在，供审计取证。
- 回滚代码应优先撤回 PR；已发生的逻辑删除不通过数据库手工改写恢复，必须另行设计并批准受审计的恢复流程。
