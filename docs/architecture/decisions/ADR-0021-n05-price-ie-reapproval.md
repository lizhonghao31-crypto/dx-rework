# ADR-0021：N05 价格调整与 N06 IE 重新审核

- 状态：已接受
- 日期：2026-09-01
- 替代：ADR-0015 中“N05/N06 不得调整工序价格”以及“配置明细提交后价格绝对不可修改”的部分
- 对应范围：返工订单 N05 尾部最终确认、N06 IE 复核、工资固化

## 背景

ADR-0015 将首次核价前置到 N03，解决了未定价就分配人员、完工后才首次核价的问题。实际执行中，已核价工序仍可能因现场难度、实际处理方式或数量事实发生变化，需要尾部主管在 N05 提出最终价格调整，并由 IE 对调整重新承担审核责任。

该变化不能退回到“完工后首次定价”：N03 仍必须在分配前给出并批准初始单价；N05 只能提出调整，不能自行让价格生效。

## 决策

1. N03 继续作为分配前首次核价的唯一入口。没有 N03 已批准价格，不得进入 N04 或 N05。
2. N05 尾部主管在提交最终数量版本时，可以为当前生效配置中的返工工人工序提交完整价格快照：
   - 快照同时保存 N03 当前价格和 N05 提议价格；
   - 未调整的工序也保存原价等于提议价的快照；
   - 尾查工序不属于这条调价链路。
3. N05 提交只创建不可变提案和审计事件，不修改当前生效价格，不提前生成工资。
4. N06 IE 对同一份最终数量、临时工系数和价格快照作一次整体决定：
   - 驳回时不修改价格，订单退回 N05；
   - 批准时，在同一数据库事务和同一 IE 审计事件内，将提议价格提升为当前最终价格，然后立即按最终有效数量、最终价格和临时工系数生成工资。
5. N06 不能输入另一套价格，也不能只批准部分工序。任何价格变化必须与 N05 快照完全一致并完整覆盖当前返工工人工序。
6. 在本决策上线前已经处于 N06 的历史待审版本没有价格快照，继续沿用其 N03 已批准价格，避免阻断在途订单。
7. 价格快照、审核决定和工资快照均保留历史，不允许更新、删除或截断。

## 原因

该模型同时保留两个必要控制点：

- 分配人员前已有可执行、经 IE 审核的 N03 初始价格；
- 现场变化导致的价格调整不能由尾部主管单方面生效，必须在 N06 再次由 IE 明确批准。

价格与最终数量在同一版本、同一审核决定中固化，可以避免“数量通过但价格仍待审”或“工资使用了未批准价格”的分裂状态。

## 后果

- ADR-0015 的工资公式保持不变，但其中“IE 单价”解释为：没有 N05 调整时使用 N03 批准价；存在 N05 调整时使用 N06 批准后的最终价。
- N06 批准成为配置价格唯一允许的受控例外更新；除该事件外，已提交配置明细仍不可修改。
- 工资继续只在 N06 批准后生成，责任判定继续消费已固化工资，不改变 N07 之后的状态机。
- 本决策不改变数量修正的追加记录逻辑，不开放 N05 修改计划数量，也不改变“发起返工”入口。

## 数据库不变量

- 新 N05 确认必须标记需要价格快照，并为每个当前生效的返工工人工序保存且只保存一条价格。
- 价格快照中的原价必须等于 N05 提交时的当前生效价格。
- 配置价格只能在匹配的 `rework.final_quantity.ie_review` 批准事件内，从快照原价改为快照提议价。
- 创建订单审核与工资前，当前生效工人工序价格必须与该次批准快照完全一致。
- 价格快照表禁止更新、删除和 `TRUNCATE`。
