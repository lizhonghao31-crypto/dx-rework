# ADR-0006：N08-B 原加工厂标准扣款自动路由

- 状态：已接受
- 日期：2026-08-10
- 对应路线：UAT N08-B 流程瘦身

## 决策

1. N07 正式判责后，只要某个工序存在大于零的 `processing_factory` 责任项，且返工单已记录唯一、有效的原加工厂供应商与订单跟单，系统自动建立该加工厂的 N08-B 拟扣台账。
2. 自动台账直接进入“待应付确认”；不创建订单跟单的“业务签收”待办，也不要求其重复确认已在 N07 锁定的责任类型、金额或原加工厂。
3. 自动路由的金额必须逐项复用 N07 已锁定的 `proposed_amount`，服务端汇总；浏览器不得传入、修改或重新计算拟扣金额。
4. 加工厂、印绣花/洗水厂、面料商属于不同责任类型。每种类型保留独立台账和对应应付角色，不得合并金额或错误路由。
5. 以下情况保持原有人工选择供应商路径：原加工厂未维护、不是有效供应商、订单跟单不具备有效签收身份，或责任类型不是 `processing_factory`。
6. 应付退回、供应商异议、实扣差异和责任变化仍保留既有异常处理及 N07 责任变更路径；本决策不让跟单代替供应商表达是否接受扣款。

## 已知边界

现有 N07 模型可把一个工序分配给不同责任类型（例如加工厂与印绣花厂），并由服务端分别计算金额；但同一责任类型尚不能拆给多家供应商。若业务出现“同一工序由两家加工厂按比例承担”，必须先新增供应商级比例及服务端合计校验，禁止猜测或平均分摊。

## 影响

优势：标准加工厂责任单减少无信息增量的业务签收动作；N07 判责金额、供应商台账、应付待办和审计事件保持可追溯。

风险：原加工厂或订单跟单主数据错误会转入人工选择分支，不自动猜测替代供应商；已经创建的历史台账不回写或重路由。
