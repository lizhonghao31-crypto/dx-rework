# 管理座舱显示口径 V1.0

## 2026-11-05 模块01已授权增量：业务要求与实际采用计划

本轮依据 Library `dx-m01-implement-v1.1.1.md`（版本2）及 M01-OPT1.3，用户明确授权施工、检查、GitHub Codex Review与合并。以下新读契约覆盖本文件旧“七阶段各占七分之一”的新座舱显示；原 `display`/`progress` 字段为旧消费者保留，不把新旧百分比拼接比较。部署由用户执行。

`businessProgress.ruleVersion=journey-business-v1` 按真实适用业务要求列已完成n项/适用m项，附逐项范围、实例与缺件。一个要求涉及多个批次或执行范围时，全部必要范围成立才完成；拆批不加权，取消或退役实例不免除仍有效要求，缺承接保未知。沿用须原完成关联有效。整单终态、实际数量、质量覆盖、计划应完成和时效分别读取，不用收口强制100%，不读工资是否结清决定业务进度。已有原生船样寄出事实可完成对应业务要求，原任务及历史保持。

只从 `digital_series_plans` 正式采用记录取得系列计划ID/版本及冻结日期/依赖计算结果；预览和SLA的`status=planned`不能冒系列计划采用。逐项与实际使用同一集合；完整、部分、未采用、当前权限未包含分别显示。部分覆盖只说明已覆盖k项中应完成x项及其余缺件；完成数相等不代表应完成的具体要求已全部完成。保留的旧采用日期仍标原采用版，缺原版依据不贴新版标签。日期型按北京当天结束，瞬时值保时区，不用浏览器现在替代业务观察时点。

数量只消费原有效累计实收、对应有效质检覆盖与有效装箱，不把订正累计与原receipt相加。批累计2、原质检1、装箱2时保留质检缺口1；未知质检不填0。厂归属只有原精确receipt关联覆盖有效累计时才标可核；批累计与receipt覆盖不一致时继续未知，不按当前厂或份额分摊。本层不修订源质检、结案或归厂写入规则。

未取得正式业务号可信映射时明确说明，外发请求UUID不再冒母单业务号；开发参考款号仍可辨认，原关联及检索保留。原资料/价格/岗位/导出边界、Root例外、历史和原业务状态不变。技术验证不代替M/B/COMPOSITE等原现场逐对象复验，也不关闭I源质量守卫、F源归厂、通知或旧N资料问题。

## 原显示口径与兼容说明

2026-10-19，依据本轮已批准施工计划及主方案 v11。仅新增只读投影，不修改任务、审批、数量、工资或收口写入。

七阶段固定各占七分之一，阶段内适用业务节点等权。同一节点多 PO/任务必须全部有效完成才计一份；材料复核沿用核配份额。生产母单首阶段唯一创建份额为订购信息；合法创建即该阶段 100%，流程是否激活另行判断。未生成的必需节点计未完成；取消不算完成；合法沿用须验证原完成任务与来源、轮次。缺定义、权限或适用性证据时精确百分比不可用。非全完成最多显示 99.9%。进度不触发业务收口。

当前投影尚不能证明的条件分支（例如尚未形成的回货质检/返工事实）返回资料待完善；不把未知当不适用。时间比例本轮一律空值，显示“时间规则待完善”，不建立新时钟。

2026-10-20 A验收修订：七阶段全单比例只用于已有生产母单。纯开发未下单范围明确显示既有开发阶段进度，不将尚不适用的大货阶段作为已完成份额，也不提示母单待结案。生产母单阶段资料未知时继续保留精确总比例为空，页面指出具体待核阶段，并可查看各阶段已有比例与不适用状态；不以结案补成100%。整单已收口仍有原未完成节点时，保留原节点、风险与查看入口，明确标为收口后保留的原节点状态，不改历史任务状态。

整单主状态依次按取消、既有有效收口、全部适用 PO 最早出货日期 H 已过日/当日、真实激活或办理事实、未启动判定。日期以 Asia/Shanghai 自然日为准。节点、工厂及船样风险单独展示，不替代 H；不凭部分装箱或工厂发货剔除 PO。未完成有 H 升序、缺 H 其次、完成最后；完成有可信收口时刻才倒序，否则稳定款号/ID。取消单以独立数量说明，不并入生产有效五类状态。纯开发独立范围。

兼容：原 progress、原无 scope 查询与工作台口径保留。`scope=production|development` 使用互斥主状态统计，在授权全量筛选后排序分页。`display` 等新增字段可选；新 UI 缺匹配 API 时应显示不可用，不回退成旧百分比。

详情 `view=cockpit` 保留办理权限及完成时责任人，使用有界事实摘要而非全量改派日志。`operationLog` 首读 SQL LIMIT 5；`/digital-production/journeys/:id/logs` 每页 20，返回下一游标、固定截止时间与来源范围。游标绑定订单和用户、稳定登记时间加事件 ID；每页重新授权。事件范围取投影前已核权的原始任务集合，不依赖可能被外发单等替换的页面记录；翻页间节点换为原业务单据不丢失范围内旧事件。覆盖数字生产节点事件及未重复登记的节点改派审计，不声称跨模块全系统审计。原业务页历史保留。

2026-10-20 PG13兼容修复：日志SQL全部使用显式别名，以 event_at 作为内部排序列、显式引用 action 标签，避免PG13拒绝 at/action 隐式别名。外部条目 at、原事件ID、截止时刻、游标格式和首读/后续分页上限均不变。PG16原回归不能替代PG13读取验证；本轮使用PG13.23、完整schema与非超级用户验证详情和分页。

可重复门禁：Full Gate的精确diff分类器遇到Journey读取、路由、契约或其回归修改时，保留原PG16检查并执行 `NODE_ENV=test node scripts/ci/journey-pg13-regression.mjs`。脚本使用独立临时PG13.23与标记TEST数据库、非超级用户，断言服务端主版本，实际执行完整Journey PostgreSQL套件并拒绝全部跳过；退出时清理自身容器。不改变Acceptance/生产配置或日志行为。

当前风险始终取当前有效轮，历史选择不改变归属。历史评价仅用原完成事件及其 completion 期限修订；没有原始期限或可信完成时间则为“历史评价资料不足”，不用新策略倒推。

当前页面、提示和校验统一“出货日期”；技术字段和日期值不变。固定历史 PDF、审批快照、制单历史版保留原显示词。没有新迁移或回填。
