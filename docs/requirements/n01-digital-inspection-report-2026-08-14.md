# N01 数字化验货报告（2026-08-14）

## 业务目标

将现行纸质《验货报告》完整搬入节点 01“发起返工”。系统内发起的报告均已确定需要返工，不新增“合格 / 不返工”分支；正式提交后继续进入现有 N02。

## 三步录入

1. **订单、验货资料与尺寸核验**：订单责任资料、验货阶段、地点、颜色、抽查数量、验货日期和尺寸记录。
2. **资料与面辅料核对**：确认样、批版卡、供应商自检报告、大货面料检测单、面料颜色匹配、版型、工厂准备及三类面辅料结论。
3. **问题、结论与证据**：问题分类、描述、严重 / 轻微数量、不合格主因、批复、供应商签名、返工数量和 QC 附件。

页面一次只展示一个步骤，支持上一步、下一步和直接点击步骤号；任一步均可保存草稿，第三步继续使用现有“提交返工”动作。

## 尺寸核验

- 单位固定为厘米（cm），录入精度为 0.1 cm。
- 当前没有标准尺码与公差资料库，因此不得猜测标准值或自动判定超差。
- 每个“尺码 + 抽检件”独立保存；每个部位记录实测值、人工核对后的偏差值，或标记不适用。
- 默认部位为衣长、肩宽、胸围、腰围、脚围、袖长、袖肥、袖口、领阔、领围，并允许增加其他部位。
- 手机端以尺码 / 抽检件标签切换当前纵向表格，不使用需要横向滚动的纸质矩阵。
- 数据结构保留未来接入标准尺码库后自动计算偏差与超差提示的能力。

## 数据与校验

- 草稿允许三步内容不完整，并必须完整恢复继续填写。
- 正式提交必须通过三步完整性校验；报告、尺寸、资料和问题记录均写入返工单审计快照。
- 问题分类与描述自动生成现有下游流程使用的“问题部位 / 问题描述”摘要，避免重复填写。
- 订单详情向原有有权查看订单的角色展示只读数字化验货报告。
- 查货人由系统操作人与审计日志确定；供应商签名与日期为可选补充字段。

## 非本次范围

- 不建立标准尺码、公差或版型资料库。
- 不改变 N02 以后节点、权限、工资、责任、扣款或钉钉通知逻辑。
- 不改变附件数量、OSS 权限和现有返工单号规则。
