# 订单终点节点 UI 治理增量（2026-08-14）

适用范围：新建返工单的订单详情流程展示、责任结算台账、订单完成与后续结算、移动端阶段折叠。

## 1. N09 自动完成

1. N08 老板确认同意后，由系统原子生成 N09 责任结算台账。
2. N09 不配置人工处理人，不显示“处理中”；生成成功即显示“已完成”。
3. 生成失败属于系统异常，不得伪装成业务人员待办。

## 2. N10 订单完成与扣款展示

1. 订单详情不再单独展示 N11 节点或“工资结算进度”阶段。
2. 最终节点统一表达“订单完成与扣款”，订单完成即进入扣款流程。
3. 最终节点只展示订单完成状态和扣款状态；工资金额仅供财务按需查询、对数和导出，不是流程状态。
4. 工资不设置初核、行政复核、月结、会计锁定、待办或阻断条件。
5. 订单完成后，无论扣款记录是否已经生成，扣款状态都不得回到“未开始”。

## 3. 响应式折叠

1. 视口宽度不超过 640px 时，订单流程三个阶段首次进入默认折叠。
2. 电脑端首次进入保持三个阶段默认展开。
3. 用户在任一终端均可手动展开或折叠；本次只调整默认状态。

## 4. 数据边界

本次不迁移、不回填、不兼容现有测试订单的历史状态；业务负责人将删除现有测试订单。数据库中的后续结算独立状态与内部路由标识继续保留，不因 UI 合并而删除。

## 5. 管理卡片完成态与扣款状态（2026-09-05纠偏）

1. 返工单管理卡片中的“订单已完成”统一使用成功态颜色；逾期或后续扣款事实不得覆盖订单完成态颜色。
2. 已完成订单不再展示“生产返工已结束”“存在逾期后续事项”“后续异常”或“独立的外部扣款后续仍按实际状态统计”等尾部说明。
3. 卡片摘要移除“附件”，改为“扣款状态”，仅展示“未开始 / 未扣款 / 扣款完成”三态：
   - 订单尚未完成：未开始；
   - 订单已经完成，但有效外部扣款单尚未全部关闭；或者扣款记录尚未生成：未扣款；
   - 订单已经完成，且有效外部扣款单已全部关闭：扣款完成。
4. “未开始”只由订单未完成决定；不得根据“是否存在扣款单”判断。三态表示扣款流程是否开始、是否结束，不表示实际扣款金额是否足额；部分扣款或不扣款结案在全部关闭后同样显示“扣款完成”。
5. 本纠偏只调整管理卡片摘要。实际扣款金额、结案类型、待办、审计和附件仍保留在订单详情及原业务台账中。
