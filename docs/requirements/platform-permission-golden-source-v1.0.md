## 0. 权威顺序与施工原则

### 2026-09-12 首次打板流程（APPROVED）

- 依据 `pattern-room-finance-v1.0.md` 第 5–9 节：Root 可验收每个增量；普通账号的订单业务统一等 PR06 完成后开放。PR03 不接入工资账本，不提前放行普通账号。
- `pattern_room:orders:view`：设计师、唯一板房主管、工人、老板、生产管理。设计师仅自己的订单；工人仅当前轮次最后执行归属为自己的订单，金额仅自己的执行段；板房主管、老板、生产管理可看全部板房订单与本业务成本。技术管理员、财务总监不因此获板房订单操作权。
- 创建、编辑制作资料、确认交接分别为 `pattern_room:orders:create/edit/handoff`，仅设计师且限本人订单；派工 `assign` 仅板房主管；完工 `complete` 仅本轮当前工人。所有权限均有角色和 capability 双门槛，并在数据库重核当前有效身份；Root 保持全流程验收能力。
- 创建必须本次款号、启用品类、正整数数量和至少一份已就绪 PDF/清晰图片。品类、单位、价格及版本在提交时固定；参考款号独立且可选。提交即资料齐备。
- 主管待分配 → 当前工人执行 → 原设计师确认收到样板。工人完工仅通知主管，不增设主管/老板工资审批；原设计师交接后正金额执行段才取得计薪资格。
- 完工前原设计师可修正制作资料，必填原因；旧文件不删除，派工后通知主管及当前工人，不新增重复执行待办。完工后新需求须走后续返工流程。
- 所有操作校验订单版本及当前轮次，重复请求幂等。待办链接携带轮次，历史轮次仅查看。待分配、制作、交接记录自然时间，按现有手动刷新规则显示，不参与工资计算。

## 1. 平台通用硬规则

### PERM-PLATFORM-ROOT-001 · Root 全部开放

**状态：APPROVED**

- Root 可查看、操作和调试全部业务模块与平台技术管理。
- Root 可进入人员与权限管理。
- Root 保留特殊调试绕过能力，但不得破坏历史不可变、审计留痕等底层完整性规则。

### PERM-PLATFORM-OWNER-001 · 老板业务最高权限

**状态：APPROVED**

- 老板保留业务最高权限，可查看全部业务模块、业务事实、报表与业务基础资料，并执行既有老板审批职责。
- 老板不获得平台技术管理能力。
- 老板不得进入“人员与权限管理”；该入口只允许 Root。
- 老板不得因为“业务最高权限”获得未明确批准的技术异常处置能力。

### PERM-PLATFORM-SYSADMIN-001 · 系统管理员仅技术管理

**状态：APPROVED**

- `system_admin` 保留系统配置、技术异常处理、审计等既有技术职责。
- 不允许因为系统管理员身份进入业务模块或读取业务数据。
- 不允许进入“人员与权限管理”。

### PERM-PLATFORM-LAYER-001 · 分层鉴权一致

**状态：APPROVED**

同一权限必须在 UI、HTTP Route、Service、数据库/数据查询边界和 Todo 深链保持一致；前端隐藏按钮、菜单或字段不构成授权。

### PERM-PLATFORM-ACCESS-ADMIN-001 · 人员与权限管理只允许 Root

**状态：APPROVED**

- 只有 Root 可以进入人员与权限管理、查看角色配置并执行人员角色维护。
- 老板、财务总监、系统管理员及其他所有角色均不得进入。

- 角色退役是停止作为当前真人业务角色使用，不等于删除员工或删除历史审计事实。
