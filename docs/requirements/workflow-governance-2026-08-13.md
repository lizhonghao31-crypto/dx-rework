# 返工流程与通知治理增量记录（2026-08-13）

状态：已确认  
适用范围：新建返工单、钉钉待办、订单详情、管理看板、工资与供应商扣款后续结算  
基线关系：本记录补充 `startup-requirements-v1.2.md`；与其中旧节点编号或旧责任结算描述冲突时，以本记录为准。

## 1. 主流程与完成口径

1. 主流程固定为 N01–N10：发起返工、配置工序、IE 审核、分配人员、完成数量登记、整单确认、责任判定与资料核验、老板确认签字、系统生成责任结算台账、订单完成。
2. N07 由生产管理核对责任比例、实际供应商、倍率与资料完整性；资料齐全后提交 N08。
3. N08 由老板确认整套责任事实。老板可以直接同意或直接驳回，不要求填写驳回理由。
4. N08 同意后，系统自动生成 N09 责任结算台账，并自动完成 N10。没有额外的“确认供应商”或“确认应付”人工节点。
5. N10 完成后，订单状态保持完成，不因工资月结或供应商实际扣款尚未结束而重新变成处理中。

## 2. N11 后续结算

1. N11 是订单完成后的独立后续结算区，不属于 N01–N10 主流程，也不阻塞订单完成。
2. 工资结算与供应商扣款是两个相互独立的进度：任一项待处理时，N11 显示对应的业务状态；两项都不需要处理或均已结束时，N11 显示已结清。
3. 工资结算顺序为尾部主管初核、行政复核、月结角色锁定月份。只有工资月份锁定后，工资结算才算结束。
4. 供应商扣款按责任方分区展示。每个外部责任台账独立记录实际扣款、退回资料、责任变更和未扣差额处理。
5. Root 具备全局查看和处理能力；其他角色只看到其权限允许的明细和操作。无权限用户不得看到敏感工资金额或操作入口。
6. 页面不得把 N11 待处理状态显示成“订单未完成”，也不得用“未开始”描述已经进入工资或扣款跟进的事项。

## 3. 钉钉待办展示

1. 钉钉待办标题必须使用中文业务名称，不得直接显示 `work_report_return` 等内部枚举。
2. 订单类待办正文依次显示款号、返工单号、订单号和当前事项；款号优先，缺失字段显示“未填写”。
3. 工资类待办显示工资月份和当前事项。
4. 提醒和逾期待办分别加“提醒：”与“逾期：”前缀；未知类别使用通用中文标题，不泄露内部枚举。
5. Web 待办列表与钉钉待办共用同一套业务名称映射，避免两端口径漂移。

## 4. 编号与兼容边界

1. 草稿属于 N01，不再对业务人员显示 N00。
2. 工资后续结算统一显示 N11，不再显示 N10-A。
3. 旧数据库表名、旧类别和历史接口可在内部保留，但不得继续出现在新订单的业务 UI 或通知中。
4. 本次不迁移测试旧订单，不扩大到生产配置、钉钉应用配置、密钥或生产数据修改。
