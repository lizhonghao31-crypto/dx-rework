# 第一阶段流程优化需求（v1.0）

> 业务确认：2026-08-16  
> 适用范围：达兴广州尾部返工系统第一阶段  
> 本文件在冲突处替代 `startup-requirements-v1.2.md` 的对应流程描述。

## 已确认规则

1. 不处理跟单归属；待业务在周一确认订单与跟单的识别方式后另行决定。
2. N01 保持现有数字化验货单和附件留痕，不重复施工。
3. N02 仅由尾部主管填写“工序 + 预估数量”，预估数量只用于安排，不限制最终上数；N02 不填写单价，也不经过 IE 审核。
4. N02 确认后直接进入 N03 人员分配。
5. 最终单价由尾部主管在 N05 填写，IE 在 N06 仅审核价格；IE 不录入或修改价格。
6. 所有工资按人员单独计算。临时工为可复用人员档案，由尾部主管代上数；临时工按“人员 + 工序”设置工资调整系数，默认 1.0，可批量设置，非 1.0 必须填写原因。
7. 临时工加价是否计入供应商计划扣款，暂不决定。第一阶段及后续默认不改变供应商计划扣款基数，等待周一业务确认。
8. 钉钉首页/工作通知和待办标题信息优化属于第二阶段，不纳入本轮施工。

## 第一阶段完整目标流程

| 节点 | 处理人 | 最小可用规则 |
| --- | --- | --- |
| N01 发起返工 | 品控/有权限发起人 | 数字化验货单、订单与供应商快照、至少一张纸质报告附件 |
| N02 返工计划 | 尾部主管 | 工序与预估数量；确认后进入 N03 |
| N03 人员分配 | 尾部主管 | 分配正式工或临时工；临时工人员档案可复用 |
| N04 完工上数 | 正式工/尾部主管代临时工 | 正式工只有“完工上数”；按工序一次性填写最终数量；确认即完成，可退回返工 |
| N05 尾部确认 | 尾部主管 | 对照预估与实际；正常确认或退回指定人/工序；录入最终单价和临时工系数 |
| N06 IE 核价 | IE | 仅通过或驳回；驳回必须写原因 |
| N07 判责 | 有权限判责人 | 一个主责任方，可选共同责任记录；不分摊比例/金额 |
| N08 老板签字 | 任一老板权限人 | 通过或驳回；外部责任默认倍率 1.2，特殊倍率在此处折叠调整并写原因 |
| N09 扣款台账 | 指定经办人/财务总监 | 每次扣款流水；部分结清可申请财务总监结单；生产完工与扣款结清分开显示 |

## 非目标

- 不接入 ERP；不迁移或清理历史订单；不为临时工提供外部登录、公开链接或共享账号。
- 不修改钉钉通知投递配置，不部署生产环境。
