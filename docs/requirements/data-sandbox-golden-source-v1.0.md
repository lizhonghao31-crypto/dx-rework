# 数据沙盘 Golden Source V1.0

状态：APPROVED（2026-09-17）

## 1. 总体目标

在订单打板、外发定价&选厂、订单返工、供应商中心、实时生产、订单回货六个模块建立二级“数据沙盘”。数据沙盘负责跨订单汇总、双期间比较、趋势、节点流转、排行与异常定位；原业务页面继续负责当前业务事实和办理，不把日常操作搬进沙盘。

返工作为首个试点。完成返工试点并业务验收后，再复制公共结构到其他模块。

## 2. 原工作区保护

- 返工单的实收、工序、当前节点、照片、流程、办理按钮继续留在原返工看板和详情。
- 订单回货原筛选及“期间收货订单数、期间实收数量、异常订单数量、差异率”四个基础数字必须保留。
- 实时生产原订单进度、简要追单提示和填报入口继续留在原看板。
- 沙盘失败、无权限或无数据不得阻断原业务办理。
- 不新增一线填报、计时打卡、审批或另一套业务主数据。

## 3. 固定流程指标

除供应商中心外，流转模块统一使用：

1. 业务进入与完成：分别展示，不计算含混的“完成÷新增”。
2. 期末未完成：按各统计期间结束时的真实节点事件还原。
3. 平均流转时长：已完成业务从规定起点至规定终点的总经过时间平均值。
4. 流转最久环节：本期已离开节点的完整流转记录中，平均流转时长最高的环节。

节点分析固定展示：环节、平均流转时长、对比期变化、有效样本数、期末未完成数量、最长已停留、原单下钻。

## 4. 流转时间口径

- 单次节点流转时长 = 离开节点时间 - 进入节点时间。
- 未完成节点已停留时长 = 统计期末 - 本次进入节点时间。
- 从进入节点即开始计时，包含排队、等待、夜间和休息时间；它不是劳动工时。
- 补图、报数、查看、普通保存不得重置节点等待时钟。
- 退回后重新进入同一节点形成新的流转记录；历史记录保留。
- 缺进入或离开时间显示记录不足，不使用更新时间补造，不按零计算。
- 流转时间可用于发现业务停留在哪个环节，但不能单独认定人员偷懒或责任。

## 5. 双期间

每个沙盘使用分析期间 A 与对比期间 B。A、B 必须使用完全相同的统计对象、事件、版本、权限和缺失规则。历史期末状态按真实事件还原，不能使用今天状态倒推。

时长、异常等明确越低越好的指标：增加红色↑、减少绿色↓；明确越高越好的指标反向；订单量、金额等中性数据不自动评价改善恶化。颜色不得成为唯一信息载体。

## 6. 指标说明

每个核心指标右上角提供小型说明图标。电脑悬停/聚焦、手机点击后显示：指标含义、计算公式、管理用途、统计范围及注意事项。说明和实际公式必须同源维护。

## 7. 返工试点

### PR01
建立独立返工数据沙盘入口；双期间查询；业务进入/完成、期末未完成、平均流转时长、流转最久环节；各节点平均流转、期末积压、最长停留和原单下钻。

### PR02
增加工序数量榜、工序费用榜、已确认费用与责任结构、重复往返与规则式异常摘要；金额按既有字段权限服务端控制；不将返工工资命名为完整质量损失。

## 8. 权限

数据沙盘不自动扩大数据范围。返工试点沿用 `dashboard:management:read` 管理读取边界，Root 原能力保留。工资、责任、达兴价格等敏感字段继续按现有 Golden Source 单独鉴权。前端隐藏不构成权限边界。

## 9. 暂不建设

供应商综合评分、人员综合评分、自动责任认定、外发到期履约 KPI、供应商准时履约评分、预测性 AI 决策均不在首轮范围。
