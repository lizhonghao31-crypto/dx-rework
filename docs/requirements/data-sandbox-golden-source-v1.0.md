# 数据沙盘 Golden Source V1.0

状态：返工试点施工中  
日期：2026-09-17

## 1. 目的

数据沙盘用于把跨订单的趋势、期间对比、节点流转、专题排行和原单下钻集中到各业务模块的统一分析入口。它不是新的业务办理系统，不能替代原工作区，也不能要求一线为分析重复填表。

返工先做试点；试点验收后再复制到订单打板、外发定价&选厂、实时生产、订单回货和供应商中心。

## 2. 原工作区保护

- 返工单的实收、工序、当前节点、照片、流程、办理按钮保留在原订单与返工看板。
- 数据沙盘只承接跨订单分析，不新建办理表单，不修改状态机、计薪、责任、扣款算法。
- 返工看板原关键词、状态、责任、日期、异常筛选保持；旧的跨单“流程等待与往返”分析从看板移出，由沙盘承接。
- 分析读取失败只影响沙盘；原返工看板和办理流程继续可用。

## 3. 权限

返工数据沙盘沿用 `dashboard:management:read` 管理分析读取权限和 Root 特例，不因为拥有普通返工查看/办理权限而自动取得全局沙盘。服务端仍执行原数据库授权；前端入口隐藏不是安全边界。

本轮不增加工资、达兴价格或其他敏感字段可见范围。

## 4. 双期间

页面同时选择分析期间 A 和对比期间 B。相同指标必须使用相同统计对象、公式、权限范围和历史截点。

- 进入量：订单创建时间落在期间内。
- 完成量：订单第一次进入 `completed` 的时间落在期间内。
- 期末未完成：在期末已经进入返工、但尚未第一次 `completed` 且当时未取消的有效订单。
- 历史期末按真实状态迁移事件还原，不以今天状态倒推。
- 当前未结束日期以实际读取时间为截点，不能把未来的当天剩余时间计入等待。
- 缺记录与真实 0 分开，不能补造时间。

## 5. 流转时长

主口径是业务经过时间，不是劳动工时。

- 节点流转时长 = 本次离开节点时间 - 本次进入节点时间。
- 当前/期末已停留时长 = 统计截点 - 本次进入节点时间。
- 等待、排队、夜间、休息均计入业务流转时间。
- 补图、查看、普通保存不重置节点时钟。
- 退回后重进同一节点形成新的节点流转记录；往返记录保留。
- 返工主流程以首次业务完成为终点。首次完成后的重新判责追加流转不改写首次完成周期，后续专题另行分析。

固定首屏观察：本期进入/完成、期末未完成、平均流转时长、流转最久环节。节点表必须同时展示平均流转、对比期、期末未完成、最长已停留、有效样本并能下钻原单。

## 6. 指标说明

主要 KPI 和图表右上角使用统一小型说明入口，内容固定包括：指标含义、计算公式、管理用途、注意事项。电脑支持悬停/聚焦，手机支持点击阅读；不能只靠说明浮层才能理解指标标题。

## 7. 颜色与变化

- 明确越低越好的流转时长、积压等：增加红色向上，减少绿色向下。
- 明确越高越好的指标反向处理。
- 业务量、金额等中性指标只表示升降，不自动判断好坏。
- 颜色不是唯一信息，必须同时有箭头或文字。
- 对比期为零时不得显示无穷百分比；缺失或不可比不显示改善/恶化。
