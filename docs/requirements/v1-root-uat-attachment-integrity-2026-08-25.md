# 1.0 上线前 Root UAT：附件真实性与孤儿治理

状态：已确认  
确认日期：2026-08-25  
适用范围：Root 云窗口验收 PR-02

## 业务目标

防止伪装图片进入业务证据链，并避免失败或放弃的上传长期占用 OSS；上线前不改变一线人员现有上传方式。

## 已确认规则

1. 服务端最终确认附件时必须读取 OSS 中的真实对象字节，不能只信任文件名、客户端 MIME 或自报摘要。
2. 真实字节 SHA-256 必须与上传意图一致。
3. JPEG、PNG、WebP 必须分别通过格式签名、边界、尺寸与必要结构校验；PNG 压缩数据必须能够正常解压，解压输出上限为 128 MiB，防止压缩炸弹拖垮 2c2g 服务。
4. PDF 继续兼容，并校验 PDF 文件签名及结束标记。
5. 校验失败的附件保持不可绑定状态并写入既有安全审计，不暴露文件内容或 OSS 凭证。
6. 任何已绑定业务对象的附件都不得进入清理候选。
7. 未绑定的 `pending`、`rejected` 附件保留 24 小时；未绑定的 `ready` 附件为保护本机草稿保留 30 天。
8. 清理使用数据库行锁再次确认附件仍未绑定后才删除 OSS 对象和数据库记录；单次最多处理 50 个，每 6 小时运行一次。
9. 清理失败只记录成功数与失败数，不记录对象 Key、原文件名、人员资料或凭证，也不得阻塞 API 启动和正常业务。

## 明确不在本次范围

- 不改变上传页面、文件数量限制或现有业务节点。
- 不回扫或强制重验已经进入业务链的历史附件。
- 不新增管理页面、人工清理按钮、图片压缩或性能专项。
