# 客户报价与预算：本轮已批准规则的实现边界

本页执行2026-10-31三纪要及11-01已批准八PR方案、末尾金额口径修订。它不替换原外发IE报价、合同及批准链。生效取决于部署，不表示已上线。

- 设计填写面辅料、供应商及其价格；指定技术纸样岗位填写单件用量；指定IE或工艺跟单填写对应工艺价格。后端按本单和行责任校验，技术不读取整张成本和客户确认金额。Root保留调试职责，但不能绕预算总额上限。
- 客户确认报价与正式订单两条件齐备才转换预算草稿；确认先于下单、下单先于确认和重放事件均使用同一来源绑定。纯开发、预下单不要求完整预算。
- 新正式订单在数据库插入边界采用`quote_v1`，请求体没有关闭开关。迁移前订单不回填、不补造确认、不自动改变历史合同。历史在途采用仍需批准方案要求的资料确认和有权切换，不能仅上传一张报价就改变旧模式。
- 报价确认快照冻结客户、版本、原明细及填写人、内部录入人、客户真实确认时间、服务端记录时间、确认依据、币种、税费及件数口径。通用开发未明确客户可先存报价草稿，不能先确认一个不知归属客户的报价。
- 在线版本`online-quotation-v1`的`customerConfirmedTotal`是有权内部人员对真实客户确认记录的明确录入；没有从旧Excel或外发IE价格推测金额。既有模板尚无可靠映射时不启用自动提取，不能宣称旧模板已核实。
- `budgetComparableTotal`沿原预算单件不含税成本计算；客户确认按每件时同单位比较，按整单时乘冻结的正式件数并核对数量一致。只有人民币、不含税且数量口径可比才能发布；含税报价可以记录事实，但不能直接与不含税预算比较，也不默认税率或汇率。
- `budgetComparableTotal <= confirmedQuoteTotal`，相等允许，超出拒绝，老板/Root无特批。金额输入6位、乘积12位定点计算，显示四舍五入不参与放行。销售价、内部成本小计或利润均不自动替代客户确认金额；并不笼统禁止未来真实模板映射使用某个合法字段。
- 明细差异按稳定行ID、名称/规格/单位与同一确认版匹配。涨红↑、跌绿↓、持平中性；零基数、新项、空值或单位变化不显示虚假百分比。单项上涨不拦截；发布只核总额。
- 确认版不可覆盖；后续填写形成新协作版本，新的客户确认不会覆盖预算。跟单明确采用后保留原预算明细并生成待复核版本；已发布预算和原批准合同留历史。已绑定外发时沿原预算更正入口，不私改合同。
- 预算引用冻结版本送原IE→供应链总监→老板流程参考。执行价可高于预算，沿老板原批准链；没有额外执行超支审批、财务生产门禁或制单后48小时定价限制；2.0不建BOM。

PR02先提供有权技术直接填写的用量来源（实际人员、单位、值、版本、时间）。PR03接同一来源契约的技术成果引用，不以尚未实现成果或假ID完成报价。

UI使用原Shell/导航/单据组件和tokens。新报价入口位于原产前准备导航和原单内；不扩IE对其它数字生产页面的权限。预算表保留原字段、原按钮和原布局，只增报价依据及参考列，表内滚动。错误保留输入，结果未知使用原键原内容恢复；只读历史不打开当前可写版本。

回退须同时保留已采用新规则的服务端发布约束和已产生快照的可读性。可以停止新报价维护/转换，不能回退成新单无上限发布，不能删除或伪造已确认来源。原合同、仓库、返工及做尾规则未修改。
