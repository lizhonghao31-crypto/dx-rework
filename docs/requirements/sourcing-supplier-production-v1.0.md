## 1. 定稿结论

本项目不是把仍在运行的 ERP 接入数字助手，也不是在两个系统之间同步订单或供应商数据。正确方向是：

- 数字助手是未来唯一业务平台和唯一真实数据源；
- ERP 的现存订单、供应商、报价、生产等数据全部视为测试数据，零迁移、零同步、零引用；
- ERP 只提供供应商目录、业务一览和供应商协同页面的产品交互参考；
- 供应商中心、外发五节点、合同、正式派单、生产填报、实时看板和订单回货使用同一套平台事实，但保持清晰模块边界；
- 第一阶段只选择 2—3 个主要、稳定的加工供应商试运行，不提前建设复杂异常、自动排产、评分推荐或外部供应商账号；
- 先完成真实数据闭环，再基于实际使用优化复杂能力。

目标闭环：

```text
供应商资料 → 跟单创建外发单 → IE 审核价格 → 生产管理调价并选厂
→ 老板审批 → 系统生成合同 PDF → 跟单正式派单
→ 生产数据填报 → 实时生产看板 → 发货 → 订单回货
财务：后续付款/对账时核对系统信息，独立于派单与生产执行。
```

合同文件生成不代表供应商已经接单。只有“正式派单”成功后，才创建生产订单并出现在生产数据填报与实时看板中。

## 2. 项目目的与业务价值

### 2.1 直接目的

1. 让供应商资料成为选厂、合同和生产执行共同使用的可信主档，避免重复输入。
2. 让一份外发订单支持同批次多款号、多颜色和差异化价格，并完整通过 IE、生产管理和老板审核。
3. 由系统根据批准事实生成唯一合同 PDF，留下财务核对和责任追溯证据。
4. 通过正式派单将“批准决定”转换为“真实执行订单”，防止合同生成即被误认为已经生产。
5. 让驻外厂人员只维护必要的真实生产数据，管理人员通过双进度和预警快速发现落后订单。
6. 将发货与仓库实际回货分开记录，保留供应商执行事实和本厂收货事实。

### 2.2 数据价值

- `达兴价格`是内部成本价，是后续毛利、财务和供应商成本分析的基础事实；本期必须准确保存，并向外发五节点参与角色可见，但绝不能进入合同或无关岗位页面。
- 每个款号/颜色的数量和最终价格形成不可覆盖的批准快照，供应商资料以后修改不得改变历史合同。
- 每次生产上报形成事件，不覆盖历史；看板风险由生产事实和时间事实计算，不依赖人工主观填写。
- 财务核对的核心价值是把线下拿来核对的合同与系统生成版本对应起来，并保留核对人、时间和结果，便于事后追责；本期不建设财务直接向供应商发送合同。
- 订单回货数据以后可反哺供应商画像，但本期不建设自动评分、自动拉黑或自动推荐。

## 3. 系统边界与明确排除

### 3.1 唯一平台边界

- 不读取 ERP 订单；不建立 ERP 订单投影；不从 ERP 选择订单。
- 不读取或迁移 ERP 供应商；不建立供应商同步任务。
- 不迁移 ERP 生产记录、报价、合同、红黑榜或测试数据。
- 新页面、API、数据库、权限、待办、审计和附件全部建设在 `dx-rework`。
- 现有代码字段若仍使用 `erpOrderNo` 等历史命名，施工时应通过兼容迁移逐步改为中性的“订单号”语义；不得继续宣称其来自 ERP，也不得为改名破坏现有数字助手订单。

### 3.2 ERP 可以复用的内容

| ERP 资产 | 处理方式 |
|---|---|
| 供应商名录、联系人、地址、工艺、日产能等字段思路 | 选择性重建到数字助手的精简主档 |
| 供应商业务一览 | 复用信息结构，不复用数据 |
| 供应商切换、订单任务卡、日产量、完成、发货交互 | 作为“生产数据填报”页面的产品原型 |
| 累计数量不得超过订单数量等有效校验 | 按新领域模型重建 |
| ERP CSS、Tailwind 参数、页面外壳、浏览器弹窗 | 禁止复制 |
| ERP 本地存储、名称生成 ID、原生 API、巨型页面 | 禁止复制 |
| 五段复杂生产状态 | 不迁；一期只保留三种状态 |

### 3.3 一期明确不做

- 供应商账号、供应商门户或对外登录；
- ERP 数据迁移、ERP API、Excel/CSV 导入；
- 待接单、待发料、待收料、待开工等额外生产状态；
- 自动排产、可追回预测、延期追回模型；
- 供应商评分、雷达图、红黑榜、自动推荐和自动判责；
- 钉钉消息推送；
- Word 合同、电子签章、合同自动发送给供应商；
- 大屏模式、自动刷新和服务端实时推送；
- 复杂物流、拆单、多供应商并行生产；
- 低价值 KPI 大卡片、装饰性图表和无业务含义的动画；
- 质量事件中心的完整建设。

## 4. 信息架构与导航

### 4.1 供应商模块

一级模块只保留一个：**供应商中心**。

二级入口：

1. **供应商目录**：只读查看主档、合同资料状态、工艺、常规产能及已有业务事实。
2. **资料维护**：新增、修改、启停供应商资料和查看变更历史。

左侧平台导航保留供应商中心，模块顶部采用紧凑二级 Tab，使用现有主蓝色标明当前页。

供应商中心内不得放生产进度填报、生产订单队列或实时生产看板。

### 4.2 实时生产模块

一级模块：**实时生产看板**。桌面端顶部固定区按“我的待办 → 实时生产看板 → 订单回货”排列，三者同属一个顶部模块区；分隔线必须位于“订单回货”之后。实时生产看板不再作为下方可展开业务分组重复展示。

二级入口：

1. **实时看板**：跨供应商查看全部已正式派单订单，只读监控。
2. **生产数据填报**：驻外厂人员维护所负责供应商订单的生产数据。

两页读取同一套生产订单与生产事件，不建立两套台账。

### 4.3 我的待办

在现有“我的待办”中新增业务模块：**实时生产**。

- 进度落后、高风险和超过两天未更新的提醒进入该模块；
- 不建设钉钉推送；
- 点击提醒进入对应生产订单后，仅清除当前接收人的未读提醒图标；
- 订单真实风险仍然保留，不能因为点击而变为正常；
- 同一人同时具备老板和 root 等身份时必须去重，不生成重复提醒。

## 5. 外发五节点与权限边界

一期继续使用现有五节点，不新增“合同节点”：

1. 跟单创建订单；
2. IE 审核价格；
3. 生产管理调整价格并选择供应商；
4. 老板批准或驳回；
5. 财务核对。

### 5.1 跟单节点

- 跟单只能在节点 1 录入和维护订单初始价格；
- 节点 1 不得选择供应商；
- 提交后价格进入 IE 和生产管理审核链，跟单不能绕过后续审查直接形成最终价格；
- 订单被合法退回节点 1 时，按现有退回规则重新形成版本，不覆盖历史。

### 5.2 IE 节点

- 逐款号/颜色查看跟单价格和达兴价格；
- 记录 IE 审核或调整后的价格版本；
- 只审核价格，不选择供应商。

### 5.3 生产管理节点

- 查看跟单价格、IE 结果和达兴价格；
- 调整并形成待老板批准的逐款最终价格；
- 为整份订单选择一个供应商；
- 录入并确认有序的“工艺及承包范围”，可选已有或新增入库，提交必填；内容进入决定版本、批准快照及合同第二条红字；
- 所有款号、颜色共用同一供应商、交期、工艺和合同条款；
- 不做系统自动排名或自动推荐。

### 5.4 老板节点

- 查看精简决策摘要、逐款价格、达兴价格、供应商、总数量、总金额、交期和价格变化；
- 同意后冻结批准事实并触发合同生成；
- 驳回继续沿用现有五节点退回规则和版本审计。

### 5.5 财务节点

- 只读核对供应商、逐款价格、数量、合同总额和系统生成的合同 PDF；
- 不修改业务决定，不选厂，不转厂；
- 核对动作由系统自动保存核对人、时间、结果和对应合同版本；财务无需填写或判断技术指纹；
- 本期依靠系统留底和审计追责，不建设财务直接发送合同或技术性阻止线下另签合同的复杂方案；
- 财务只在后续付款、对账时顺便核对系统信息；不决定是否派单，不承担生产监督。
- 财务未核对、核对一致或记录差异均不作为派单和生产的前置条件；不得读取财务核对结果来放行或阻止派单。

### 5.6 正式派单

- 正式派单不是第六审批节点；老板批准且系统合同已生成后，由跟单执行，不等待财务核对；
- 由本订单跟单执行，root 保留兜底操作能力；
- 点击前必须明确二次确认供应商、总数量、交期和合同编号；
- 同一有效批准决定最多产生一张有效生产订单；重复点击、网络重试和并发请求必须幂等；
- 正式派单成功后才在生产数据填报和实时看板出现订单；
- 合同已生成但尚未正式派单的订单，不得提前出现在生产端。

## 6. 节点 1 数据结构与录入规则

### 6.1 公共信息

整份订单共用：

- 性别（男装/女装，下拉，必填，不预选）；
- 款式（必填，可搜索已有或输入新款式，提交时服务端去重入库，和款号分别存储）；
- 预计发裁片日期；
- 要求交货日期；
- 达兴价格；
- 现有流程仍需要的跟单和业务归属事实。

节点 1 订单图片必须上传，前后端一致校验并提供行内中文必填及失败提示；修复上传，不得取消或绕过必填。订单图片不进入合同主表；不追改历史合同。

平台订单号不再由用户录入；服务端内部稳定ID和历史关联保留。工艺及承包范围移至节点3，由生产管理确认，进入批准快照和合同第二条。完整动态字段、固定条款及签署区映射以 `sourcing-contract-field-audit-v1.1.md` 为准。

### 6.2 多款号明细

一份订单和一份合同允许包含多个款号，每一行代表一个款号/颜色组合。

| 字段 | 规则 |
|---|---|
| 款号 | 每行必填 |
| 代用款号 | 选填 |
| 颜色 | 每行必填 |
| 数量 | 每行必填，正整数 |
| 对外加工价格 | 每行必填，精确十进制 |

- 添加新款号时，必须同时产生颜色、数量和价格输入项；
- 新增行的对外加工价格默认复制第一行当前价格；
- 跟单可在节点 1 单独修改任意一行价格；
- 不同款号可以价格不同；
- 所有款号共用同一个达兴价格；
- 订单总数量由各行数量求和，不能另外维护一份可能冲突的总数量；
- 合同总金额由批准后的各行 `数量 × 最终对外加工价格` 求和；
- 删除行必须保留正常表单确认，已进入后续节点后不得直接删除历史行。

### 6.3 达兴价格

- 达兴价格是达兴内部成本价，一单一个值，必填；
- 仅向该订单的跟单、IE、生产管理、老板、财务和 root 展示；
- 普通工人、仓管、驻厂生产数据填报人员及其他无外发五节点权限者不得查看，后端响应也不得返回该字段；
- IE、生产管理、老板和财务页面均应展示；
- 必须进入数据库、版本快照和审计；
- 不得进入合同数据传输对象、合同模板、合同 PDF、供应商生产页面或供应商发货凭证；
- 必须有自动化负向测试，验证 PDF 文本、合同 JSON 和模板变量均不包含达兴价格及其值。

## 7. 供应商主档

### 7.1 一期精简字段

| 分组 | 字段 |
|---|---|
| 基础 | 供应商显示名称、启用状态、备注 |
| 联系 | 联系人、联系电话、地址 |
| 合同 | 合同主体名称、乙方代表 |
| 收款 | 收款人、收款账号、开户行 |
| 能力 | 可承接工艺、常规日产能 |
| 治理 | 稳定供应商 ID、版本、修改人、修改时间、修改原因 |

一期不增加统一社会信用代码、法定代表人、复杂开票资料、软/极限产能、能力评分矩阵等低频字段。

### 7.2 主档规则

- 继续使用数字助手现有稳定供应商 ID 和版本化供应商后端，不按名称生成 ID；
- 供应商只能停用或归档，不能物理删除；
- 停用供应商不能被新订单选择，但历史订单、合同和生产记录继续展示名称快照；
- 合同主体与供应商显示名称允许不同；
- 一期默认一名供应商对应一个主要生产场地，不建设一主体多工厂复杂模型；
- 合同和生产订单都保存创建时快照，主档后续修改不追改历史；
- 写权限使用独立 capability，不按姓名硬编码；人员未正式指定前只给 root，之后通过“人员与权限”配置授权，不需要改业务代码；
- 普通本厂员工不得因为能查看供应商而获得主档修改能力。

### 7.3 合同资料兜底

供应商主档缺少合同必需字段时，不得让整个订单永久卡住，也不得静默生成残缺合同。

- 合同区显示具体缺项；
- 本订单跟单或 root 可打开“本合同补充资料”；
- 仅填写本次合同缺失字段；
- 手动值保存到合同快照并记录来源、录入人和时间；
- 手动补充默认不反向覆盖供应商主档；
- 页面可以另提供“去维护供应商资料”的正常入口；
- 合同快照字段齐全后才允许生成最终 PDF。

## 8. 合同 PDF

### 8.1 生成时点和版本

- 老板批准后，服务端先冻结本次批准决定与当时可用的供应商合同资料快照；
- 合同字段完整时自动生成 PDF；字段缺失时创建“待补充合同资料”的合同记录，不得让老板审批失败，也不得静默生成残缺 PDF；
- 本订单跟单或 root 补齐本合同资料后，由服务端基于同一批准快照生成最终 PDF；
- 服务端生成唯一合同编号；
- 系统只生成 PDF，不生成 Word；
- PDF 生成失败可以安全重试，不得重复批准、重复合同编号或重复生产订单；
- 供应商资料后续修改不改变已生成合同；需要变更时建立新合同版本，不覆盖旧 PDF；
- 合同生成与正式派单分离。

**2026-11-26 G1 合同恢复验收口径（Eric 审核施工单）。** 自动恢复在 API 开始监听后运行，只领取未删除外发单的确切已批准文档、待生成或租约已到的生成中状态。明确失败仍由原授权入口人工恢复。后台沿文档原准备或补充操作的有效身份办理，受时钟管理的原单还需已验证的验收场景。每次领取都有独立凭证。正式附件登记、原文档绑定及首次就绪在同一事务提交，失去凭证的执行者不能发布 PDF、改失败状态、写待办或刷新时钟。当前业务文档的待办同步失败时，已就绪 PDF 保留并按原入口恢复对应文档的待办。

**2026-11-26 G2 原请求回执（Eric 审核施工单）。** 原合同补缺、外发改款、数字单补号和转厂发起／决定只在原事务首次真实写入并准备了文档、且该事务已提交时，触发对应文档的生成。已保存回执按原权限读返，不生成其他合同，不重新同步大货、处理待办或起钟。保留的完成回执即使超过通用时限仍只能读返，同键异内容拒绝。旧补缺回执不能唯一定位原合同则提示核对历史，不返回最新合同或提示重新提交。通用幂等时限及其他业务命令不变。数字补号内部生成继续核原岗位和本单归属，不向没有原权限的账号显示外发合同。借用事务由真正的提交者承接，无法当场触发的已提交文档走 G1。原人工生成仍可办理合资格的当前文档。

切换前先排空所有无凭证旧生成进程，再启用 `SOURCING_CONTRACT_AUTO_RECOVERY_ENABLED=true`。开关缺省关闭，仍可通过原入口人工生成。停用自动接手时保留迁移和已写事实。正在使用的验收场景留待后轮处理。正常退出先停领，给手头工作短暂收尾时间，随后取消该任务的渲染、存储及数据库等待。私有暂存身份在写对象前登记，提交不明先按原文档、附件和暂存登记核对。只有确认该次尝试已失去凭证、且对象无正式引用时才可处置暂存物。旧写者或历史身份无法核清时保留原单待办理。

### 8.2 字段来源

| 来源 | 合同字段 |
|---|---|
| 节点 1 公共信息 | 性别、款式、预计发裁片日期（工厂发出）、要求交货日期（到工厂） |
| 节点 3 确认 | 工艺及承包范围，进入合同第二条乙方负责的动态红字 |
| 多款号明细 | 款号、代用款号、颜色、数量 |
| 最终批准决定 | 每行最终对外加工价格、最终供应商 |

合同主表不放图片。若现有模板有“图片”列，应改为适配无图片的颜色/款式描述列，不得生成空白破图框。

### 8.3 合同红线

- 达兴价格永远不得进入合同；
- 合同不能从当前可变主档实时渲染，必须使用不可变快照；
- 金额使用精确十进制计算，不能使用浮点累计；
- 前端不能自行拼装合同编号或权威金额；
- PDF 下载必须经过服务端权限校验和附件绑定；
- 系统自动留存财务所核对的合同版本；技术指纹仅为后台完整性信息，不展示为财务任务，不作为派单门槛；
- 本期不建设自动发送、电子签章和单独“已签署”工作流；正式派单代表业务确认可以进入生产，不代表系统提供法律电子签署能力。

## 9. 生产订单、状态与填报

### 9.1 生产订单创建

正式派单成功后，从批准快照创建生产订单，至少冻结：

- 外发订单 ID 与批准版本；
- 合同 ID、合同编号和合同版本；
- 供应商 ID 与名称快照；
- 全部款号/颜色/数量；
- 工艺、要求交货日期、正式派单人和派单时间；
- 第一行款号，作为一期发货展示和回货关联款号。

生产订单保留对批准快照的内部关联，但生产数据填报、实时看板、发货和订单回货接口均不得返回达兴价格。达兴价格只在外发五节点及财务核对的授权页面展示，也不得进入合同 PDF、供应商对外文件或发货凭证。

### 9.2 一期生产状态

仅保留：

1. **生产中**；
2. **生产完成**；
3. **已发货**。

- 正式派单后直接进入“生产中”；
- 该状态在一期表示“已正式派出、尚未完成”，不等于工厂已经实际开机；
- 第一条有效生产数量上报的业务日期才是生产开始日期；
- 第一条上报前显示“待首次上报”，不计算时间进度，也不产生进度落后/高风险；
- 生产完成和已发货是明确人工动作，必须记录操作者、业务时间和系统时间；
- 不增加待接单、待发料、待收料等状态。

### 9.3 正常填报权限

**2026-11-01 数字生产有效增量：** 已批准的数字生产厂单由原任务指派的QC在同一入口填写裁剪/车缝/整烫现场进度、适用的本次新增成品量与现场照片。新增精确 `qc-production-progress` 能力，不授予整个旧 production_reporter 角色；旧独立厂单填报规则保留。数量仍写原正式报量账，QC无Root订正、生产完成、工厂发货或仓库改量权。工序比例不是成品量，记录不等于质量合格。旧“驻加工厂人员尚未确定”对这类已纳入订单不再适用。

- 正常生产数据最终由驻加工厂人员维护；具体人员尚未确定；
- 建设独立 `production-reporting` capability，后续通过人员与权限配置到具体驻厂人员，不在代码中硬编码姓名；
- 跟单、本厂普通员工、IE、财务不得录入或修改生产数据；
- 生产管理和老板具有查看权，但不因查看自动获得正常填报权；
- root 具有全量查看和异常纠错权，但日常上报界面与 root 修正界面必须分开；
- root 修正必须填写原因，追加一条修正事件，保留原值，不得覆盖或删除原始上报；
- 后续授权驻厂人员时不改变上述审计和修正规则。

### 9.4 填报界面和数据

生产数据填报页面应复用 ERP 供应商协同的以下交互：供应商切换、订单任务卡、累计产量、今日/本次上报、生产完成、发货和历史记录。

每次上报至少记录：

- 生产订单；
- 款号/颜色行；
- 业务日期；
- 本次新增数量；
- 上报人稳定 ID 与名称快照；
- 系统录入时间。

规则：

- 累计生产量等于所有有效上报与修正的净结果；
- 累计生产量不得超过订单总数量；
- 分款累计不得超过该款号/颜色数量；
- 页面自动汇总整单累计，不要求员工重复填写总数；
- 生产完成允许记录实际完成事实，不额外建设复杂短装、次品或追回工作流；
- 发货在“生产完成”后登记；一期发货单只显示订单第一行款号，所有行仍共用同一份生产订单；
- 发货只产生预计回货事实，不能自动认定仓库已经收货。

## 10. 实时看板计算规则

### 10.1 双进度条

每张生产订单上下显示两条进度：

1. **生产进度** = `累计有效生产数量 ÷ 订单总数量 × 100%`；
2. **时间进度** = `已消耗工作日 ÷ 计划总工作日 × 100%`。

两项均限制在 0%—100% 展示；数值计算在服务端或共享领域函数完成，列表、详情、待办必须使用同一口径。

### 10.2 时间进度

- 生产开始日期取第一条有效生产数量上报的业务日期；
- 截止日期取订单要求交货日期；
- 一期工作日按周一至周五计算，周六、周日不计；不建设节假日管理后台；
- 开始日和截止日均为工作日时均计入计划总工作日；
- 已消耗工作日从开始日计算到今天或截止日中的较早日期；
- 第一条数据产生前时间进度为空，显示“待首次上报”；
- 生产完成或已发货后冻结用于历史展示的完成时事实，不继续产生进度预警。

### 10.3 生产进度状态

令 `落后值 = 时间进度 - 生产进度`，单位为百分点：

| 条件 | 文案 | 表现 |
|---|---|---|
| 落后值 ≤ 0 | 进度正常 | 绿色文字与现有正常状态符号 |
| 0 < 落后值 ≤ 20 | 进度落后 | 黄色文字与警示符号 |
| 落后值 > 20 | 高风险 | 红色文字与高风险符号 |

- 状态名称固定为“生产进度”，不得使用“进度风险”作为栏目名；
- 颜色必须同时配合文字和符号，不能只靠颜色表达；
- 本期不计算能否追回、不预测完成日。

### 10.4 未更新预警

**2026-11-01 数字生产有效增量：** 已进入QC监督的厂单按各PO真实仓库发厂起点/最近有效现场采集时间连续48小时提醒原QC、72小时升级指定质检负责人及主跟单；同窗口/同人去重。首次未报也监督；照片补传、已读、改派和旧时间补录不重置起点。缺可信起点为未知，可由有权人员明确从当前开始监督，不伪造历史。该范围替代下列旧2自然日未报量提示/待办；产量和交期风险保留。未纳入的历史独立生产单沿旧规则。

- 仅对“生产中”且已经有过生产上报的订单计算；
- 距最后一条有效生产上报达到 2 个自然日时进入未更新预警；
- 文案显示实际天数，例如“2天没更新”“4天没更新”，不得统一写“高风险”；
- 未更新文案在主状态位置优先展示，底层生产/时间进度仍按统一公式计算；
- 新上报或有效修正后重新计算；
- 本期不建设复杂升级层级。

## 11. 实时看板 UI 与动态效果

### 11.1 页面布局

1. **生产运行状态栏**：当前生产态势、生产中/生产完成/已发货数量、需关注数量、数据截至时间、刷新按钮；
2. **最近生产动态**：真实生产事件的横向动态带；
3. **筛选区**：关键词、供应商、生产状态、生产进度状态；
4. **订单运行区**：订单信息、双进度条、交期、最后上报、进度状态和详情入口；
5. **订单详情**：多款号明细、上报历史、状态历史、发货和 root 修正记录。

页面不使用大型 KPI 卡片和装饰性图表。默认排序：未更新预警 → 高风险 → 进度落后 → 进度正常，同级按交期从近到远。

### 11.2 手动刷新

- 不自动刷新；
- 顶部保留一个明确的刷新按钮；
- 页面固定显示“数据截至 HH:mm”；
- 刷新期间只对刷新按钮和必要局部区域显示加载反馈，不让整页闪烁；
- 刷新完成后，新订单和发生变化的订单短暂使用主蓝色淡化高亮；
- 进度条可以从旧值平滑过渡至新值，但最终数字必须立即准确可读；
- 不使用持续闪烁的 `LIVE` 标识，不暗示服务端正在推送数据。

### 11.3 最近生产动态

动态带只显示真实事件：

- 新增生产数量；
- 生产完成；
- 已发货；
- 进入或解除进度落后/高风险；
- 达到“x天没更新”；
- root 完成数据修正。

每条包含业务时间、供应商、订单/第一款号、动作和关键数量，可点击进入订单。少于 3 条时静态排列，不强制循环。自动横向滚动时必须支持按钮暂停、鼠标悬停暂停、键盘聚焦暂停和减少动态效果；关键预警不能只存在于滚动带中。

### 11.4 有价值的动效

- 刷新图标仅在请求期间旋转；
- 新增或变化订单只做一次短暂高亮；
- 生产中的生产进度条允许极浅、缓慢的流动纹理；生产完成、已发货或未更新预警时停止；
- 状态变化只做一次 150—400ms 的过渡；
- 相对时间可在本地真实更新为“12分钟前更新”“2天没更新”；
- 遵循系统减少动态效果设置。

禁止渐变动态背景、霓虹、玻璃拟态、发光卡片、粒子、数字假增长、持续闪烁、多处跑马灯和无真实事件的假动态。

## 12. 其他页面 UI 定稿

### 12.1 供应商总览与资料维护

两条路由分离页面职责和草稿生命周期，共享供应商数据、权限和现有详情/编辑字段：

- 目录标题“供应商目录”；筛选名称/编码/工艺、类型、启停、工艺；列表展示供应商/编码、工艺与常规产能、状态/资料完整度和查看入口，详情只读；
- 维护标题“资料维护”；筛选搜索、类型、状态、资料全部/有缺项/完整；列表展示供应商、类型、资料状态、最近修改及操作，进入后复用现有编辑表单；
- 最近修改直接读取当前供应商版本的真实时间，不模拟时间，不引入第二份主档；
- 新增/编辑时离开（Tab、左侧导航、浏览器返回）统一确认；继续编辑保留 URL、草稿和选择；放弃清理草稿与创建/编辑状态，一次跳转；保存成功后不再提示未保存或重复创建，即使后续读取失败；
- 电脑端为紧凑目录/列表和详情工作区；移动端为列表进入详情；
- 详情分为基础与联系、合同与收款、工艺与产能、变更历史；
- 只显示“合同资料完整”或具体缺项，不做完整度百分比、评分和雷达图；
- 初期仅 2—3 个供应商，不建设无意义 KPI 卡片。

### 12.2 跟单节点 1

采用“公共订单信息＋多款号明细表＋内部成本区”：

- 电脑端多款号使用可编辑表格；
- 移动端每一款号/颜色转为紧凑卡片，不横向挤压；
- 达兴价格放在独立区域并固定标注“内部成本，不进入合同”；
- 页面顶部提供错误摘要，具体字段同时显示行内错误；
- 新增/删除行可以有短暂展开收起动效，但不得改变现有按钮参数。

### 12.3 IE 与生产管理

采用价格差异审核模板，只突出跟单价、IE 价、生产管理最终价及变化，不重复铺满所有公共信息。生产管理选厂区展示启用状态、工艺、常规日产能、合同资料缺项和必要历史事实，不自动评分。

### 12.4 老板与财务

继续使用现有简洁审批摘要，不换成仪表盘。老板聚焦最终决策，财务聚焦合同和系统事实核对。

### 12.5 合同操作条

在订单详情使用紧凑、固定位置的合同操作条展示合同编号、PDF 状态、财务核对状态和正式派单状态。缺资料时展开“本合同补充资料”；不得使用浏览器原生 `prompt`、`alert` 或把操作按钮零散放在多个卡片中。

### 12.6 生产数据填报

采用移动端优先的任务工作台：供应商/责任范围切换、订单卡、款号/颜色上报、累计数量、完成、发货和历史。删除 ERP 的五个巨大彩色状态卡、图片、报价、物料、AQL、门户头部和层层彩色嵌套框。

### 12.7 我的待办和订单回货

- 我的待办必须复用现有模块切换、搜索、订单行、移动端卡片和分页，不为实时生产另建视觉系统；
- 订单回货延续现有页面；供应商发货信息只作为预计回货和预填参考；
- 仓库实际录入的实收数量仍是唯一收货事实；
- 发货不自动认定收货，不新增生产状态。

### 12.8 外发订单列表信息布局（2026-09-23 确认）

- 列表卡片保留整卡进入详情、主订单流程状态和现有字段文案；详情页文案与交互不因列表改版改变。
- 左侧固定尺寸展示当前有效附件中按上传时间与附件 ID 排序的第一张图片；纠错移除的旧照片不参与首图选择。多款订单卡片仅列出前两条款号、颜色和数量，其余显示款色行数，完整明细在详情查看。
- 订单主状态仍用原状态标签；合同已生成且纳入监控时，在跟单姓名旁用原有彩色小标签显示合同回签状态；未监控订单不显示合同状态。
- 数量、按流程阶段显示的单价与加工厂放在一组，另一组上下展示“预计裁片发出”和“交货日期”。多款逐款定价显示现有“多款价 · 见逐款明细”，不把某一款价格当整单价；预算价仅向原授权岗位展示。
- 电脑端两组并排，手机端保持紧凑、可换行；原有搜索、筛选、分页、删除和详情返回入口不变。

## 14. 数据对象与技术不变量

建议领域对象职责如下；施工时可按现有命名约定调整表名，但不能改变职责边界：

| 对象 | 职责 |
|---|---|
| supplier profiles / versions | 精简供应商主档、启停和不可覆盖版本 |
| sourcing cases | 外发订单主事实和五节点状态 |
| sourcing line items | 款号、代用款号、颜色、数量和逐节点价格版本 |
| sourcing decision snapshots | 供应商、逐款最终价、达兴价格、数量和批准事实 |
| contract snapshots / files | 合同编号、模板版本、字段来源、PDF 和稳定指纹 |
| production orders / lines | 正式派单后的供应商生产订单和逐款数量 |
| production reports | 正常生产上报事件 |
| production corrections | root 修正原因、前后值和对原事件引用 |
| production shipments | 发货事实和第一款号展示引用 |
| production alert projections | 统一计算后的进度/未更新提醒投影 |
| todos / read state | 各接收人的实时生产提醒和已读状态 |

技术不变量：

- 金额和价格全部使用精确十进制；数量使用整数；
- 权限使用稳定用户 ID 和 capability，不使用显示姓名；
- 关键写操作使用事务、唯一约束、版本检查和幂等键；
- 合同生成、正式派单、完成、发货和 root 修正形成审计事件；
- 历史快照不可因主档修改而变化；
- 任何生产上报和修正都不能物理删除；
- 服务端是金额、合同编号、进度状态和权限判断的权威来源；
- 普通展示继续遵守全系统千分位和小数展示规则，底层精度不变。

## 15. 详细 PR 施工计划

> 历史SSP阶段施工计划，不恢复已完成批次。当前执行顺序、真实目标基线、Review和门禁按根AGENTS及最新明确授权；下列业务要求保持有效。

本路线使用 9 个中等规模功能 PR。不得合并成跨域巨型 PR，也不得再按单个按钮拆成大量小补丁。所有功能 PR 从届时最新 `main` 顺序施工；前一 PR 合并并核验最新 `main` 后再开始下一 PR。

### SSP-01：供应商领域底座

**目的：** 先建立后续选厂和合同共同依赖的最小可信主档。

**范围：**

**不包含：** 供应商页面、选厂改造、合同、生产订单。

**必须测试：** 新增/修改/停用、重名、稳定 ID、版本并发、允许/拒绝权限、敏感字段响应、零 ERP 导入。

### SSP-04：逐款审核、选厂与批准快照

**目的：** 让多款价格完整经过 IE、生产管理和老板审查，并冻结合同输入事实。

**范围：**

## 16. 每个 PR 的固定施工纪律

> 执行适配：本节源自历史SSP批次。当前施工规则按根AGENTS及最新授权，不恢复旧main基线、Gate后Review或批次审批；权限、数量、状态、快照及不删业务数据等业务约束继续有效。

1. 开工前读取根 `AGENTS.md`、施工流程、平台 2.0 索引和本文件；核本次授权目标分支的真实远端SHA及相关开放PR（旧SSP批次的main限制仅属当时历史）。
2. 输出仓库、base SHA、工作分支、唯一目标、允许文件、禁止文件和门禁。
3. 先完成本地/执行环境定向测试和 diff 审查，再一次性推送合理 Head；不得把 GitHub Actions 当调试器。
4. 所有本路线功能 PR 均涉及数据库、权限、金额、合同、状态或跨模块联动，默认 Full Gate。
5. 历史SSP批次曾采用Gate后人工触发Review；此顺序已退役。当前按根AGENTS：本地验证、light、必要Codex Review、集中修复、冻结Head、显式最终Gate。
6. UI PR 必须在编码前通过设计稿门禁，交付后提供真实浏览器截图；CI 全绿不等于 UI 验收通过。
7. 一个 PR 不得夹带下一 PR 功能、样衣模块、质量事件中心、ERP 数据接入或无关重构。
8. 数据库迁移必须可重复验证，提供回滚或向前修复策略；不得删除当前数字助手业务数据。
9. 用户要求停止时，按根AGENTS停止对应范围的新动作并核实/安全停止在途进程；不把外壳退出当全部子进程已停，不自行恢复业务施工。
