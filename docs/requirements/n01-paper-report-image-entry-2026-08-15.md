# N01 纸质验货报告识别与精简创建（2026-08-15）

## 业务目标

质检继续填写纸质验货报告。手机端 N01 用于上传报告图片、核对系统预填信息并创建返工订单；尾部人员从订单详情查看原图。不得要求质检在手机完整填写纸质报告后才能创建订单。

## 创建订单的八项必填资料

1. 供应商
2. 款号
3. 款式
4. 颜色
5. 验货阶段
6. 验货地址
7. 订单数量
8. 抽检数量

纸质图片识别仅预填上述字段，识别结果绝不自动提交、绝不覆盖已经手工填写的值。供应商仅在与现有供应商名录唯一匹配时自动选中；否则保留给质检确认。

## 页面与流程

- 默认页仅展示图片上传入口及八项必填资料。
- 八项采用紧凑网格：桌面端每行三项，普通手机端每行两项，窄屏一项，保证可读性。
- 既有完整数字化质检报告移至默认收起的 **“手动录入”** 区域，使用 `＋ / −` 展开；其中内容为补充资料，不是创建订单门槛。
- 原有订单跟单、订单号、客供代号、工厂货号、返工数量、返工原因及返工工序同样保留在“手动录入”中，均不阻塞 N01 创建。
- 创建成功后仍进入既有 N02；不变更 N02 以后角色、审批、工资、责任、扣款和钉钉规则。

## 图片识别与安全

- 浏览器只向系统 API 提交已上传附件 ID；OpenAI API Key 仅由服务器从 `OPENAI_API_KEY` 环境变量读取。
- 系统临时签发私有 OSS 图片访问地址给服务端识别请求；密钥、图片 URL、模型原文响应均不得写入浏览器、数据库日志或审计说明。
- 未配置密钥、识别超时或返回不符合字段约束时，系统明确提示手动填写八项资料，上传与创建订单路径保持可用。
- 默认模型由 `OPENAI_VISION_MODEL` 控制，默认 `gpt-5.6`；不在代码或仓库中保存真实密钥。
