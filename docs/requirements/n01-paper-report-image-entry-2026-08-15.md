# N01 纸质验货报告识别与精简创建（2026-08-15）

## 业务目标

质检继续填写纸质验货报告。手机端 N01 用于上传报告图片、核对系统预填信息并创建返工订单；尾部人员从订单详情查看原图。不得要求质检在手机完整填写纸质报告后才能创建订单。

## 创建订单的八项必填资料

1. 供应商
2. 款号
3. 款式
4. 颜色
5. 验货阶段
6. 验货地址
7. 订单数量
8. 抽检数量

纸质图片识别仅预填上述字段，识别结果绝不自动提交、绝不覆盖已经手工填写的值。供应商仅在与现有供应商名录唯一匹配时自动选中；否则保留给质检确认。

## 页面与流程

- 默认页仅展示图片上传入口及八项必填资料。
- 八项采用紧凑网格：桌面端每行三项，普通手机端每行两项，窄屏一项，保证可读性。
- 既有完整数字化质检报告移至默认收起的 **“手动录入”** 区域，使用 `＋ / −` 展开；其中内容为补充资料，不是创建订单门槛。
- 原有订单跟单、订单号、客供代号、工厂货号、返工数量、返工原因及返工工序同样保留在“手动录入”中，均不阻塞 N01 创建。
- 创建成功后仍进入既有 N02；不变更 N02 以后角色、审批、工资、责任、扣款和钉钉规则。

## 图片识别与安全

- 浏览器只向系统 API 提交已上传附件 ID；识别服务密钥仅由服务器环境变量读取。
- 系统临时签发私有 OSS 图片访问地址给服务端识别请求；密钥、图片 URL、模型原文响应均不得写入浏览器、数据库日志或审计说明。
- 未配置密钥、识别超时或返回不符合字段约束时，系统明确提示手动填写八项资料，上传与创建订单路径保持可用。
- `INSPECTION_IMAGE_PROVIDER` 控制识别提供商；为保持已有环境兼容，缺省仍为 `openai`。
- 中国大陆 ECS 正式环境使用 `dashscope`：密钥读取 `DASHSCOPE_API_KEY`，兼容接口读取 `DASHSCOPE_BASE_URL`，模型读取 `DASHSCOPE_VISION_MODEL`（默认 `qwen3-vl-plus`）。
- OpenAI 路径继续保留为可回退选项，读取 `OPENAI_API_KEY` 与 `OPENAI_VISION_MODEL`。
- 百炼请求关闭思考模式并要求 JSON 输出；无论提供商返回何种内容，系统都必须使用同一八字段 Schema 校验后才能预填。
- 真实密钥不得写入代码、仓库、前端、日志或审计说明。

## 识别提供商调整记录

2026-08-15 现场验证确认中国大陆 ECS 直连 `api.openai.com` 超时。为避免增加海外代理与跨境网络单点，经业务负责人确认，将正式环境识别提供商调整为阿里云百炼；页面、八项字段、手动回退、OSS 私有附件和 N01 后续流程均保持不变。
