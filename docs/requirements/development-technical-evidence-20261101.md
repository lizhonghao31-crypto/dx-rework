# 开发技术资料、最终评语及内部周期（2026-11-01）

本记录落实已批准八个PR施工方案的PR03。依据为三部门原纪要及业务负责人10/31—11/1的明确纠正，详见`../engineering/new-flow-20261031-approved-plan.md`和`../engineering/new-flow-20261101-authorization.md`。本记录描述代码规则，不表示已部署或现场业务验收通过。

## 适用与历史

新建开发来源在真实创建审计事件下采用`development-20261031.1`并冻结独立开发参数版本；首次发布和每次实际复版分别保留发布起点。历史来源、旧已完成任务及原全局SLA配置不自动迁入、不补造PLT或客户确认。全局调整只对之后新建来源生效。已开始任务及已采用版本必须保持可读；回退不得丢失工资、实际完成或版本记录。

2.0不建立BOM，不新增“样衣表”或条码编码系统。创建开发单尺码选填（包含有客户订单场景）；后续纸样完成须形成技术自己的基码依据。技术负责跳码和客户尺寸模板，模板是本客户实际规则的版本化保存，不宣称通用推码算法。

## 纸样与成果引用

纸样原任务或最终评语后的尺寸复核任务，由该任务有效纸样人员维护PLT原件、结构单件用量、基码尺寸表。三者是一组不可改写的成果版本，支持不完整草稿；发布必须有就绪PLT、本单真实材料的单位/用量、基码、尺码列、部位和有效尺寸。尺寸支持厘米小数及英寸带分数，创建时原设计数据不被技术改写。

PLT通过专用任务/来源授权通道上传为私有不透明原件；通用图片/PDF上传白名单不放宽。文件名、大小、哈希、私有对象及服务端就绪回执全部核对，不执行CAD内容或承诺未经验证的厂商格式解析。下载仍核来源/任务权限，强制下载，不以内联网页执行。跨单、跨轮次或其它任务文件不能直接冒用；明确沿用的原有效成果及历史文件引用保留。

当前成果、原设计资料版本和技术内容指纹同时核验。原任务完成引用已发布成果组及精确版本，不再次上传同一原件。修改技术尺寸/物料/工艺后，受影响依据显示待重核；历史已采用版本仍可查。

内部复版若无法沿用原技术成果，而且本轮未安排纸样生成路径，发布须明确拒绝并保留草稿、原轮次及原任务；加入纸样后再发布。不能先撤销原工作再留下无技术成果可办的新轮次。

定位图由设计确认，以本轮有效纸样为依据，与裁板并行；发受影响二次工艺前须同时具备原裁片条件和有效定位图。内部工艺负责人员录入实际回样照片，随后由设计完成原工艺确认。新原件变版不能继续借旧定位图发工艺。

板房质检记录适用洗前检查与最终尾查；新规则免洗尾查也须有实际成衣尺寸和尾查照片，采用技术尺寸表，不能以图片或“通过”文字代替。扫码仅定位已有办理入口；认证、实物交接和主动提交仍保留。

## 客户最终评语与唯一有效依据

本单设计记录客户真实反馈性质、结论、文字及依据；中间沟通不触发尺寸复核。每一份最终评语版本独立发起技术24小时复核，后到新最终评语撤销尚未完成的旧复核并保留历史。发生时间与记录时间分开，复核窗口从实际登记该最终评语开始，改派不重启。

纸样师必须明确“沿用”或“改版”；无变化也要沿用确认。改版必须发布引用该最终评语的新成果，不能只选择“改版”便完成。并发、幂等和预期版本在同一事务核验，失权后不能借旧请求重试办理。

`effectiveTechnicalEvidence`是共同有效性来源：来源、轮次、适用范围、客户、最终评语版本、技术复核和成果版本同时匹配才有效。新规则走货准备读取此结果，历史来源沿原客户样板确认。PR05正式制单和PR08节点材料一览继续读取同一结果，不另造真假依据。待客户下单的纯开发只保留开发结果，不自动转母单。

原内部设计确认及计件交接继续独立办理，不等待客户最终评语或报价确认。报价中的用量由负责技术人员明确选择本单、同单位的具体技术材料采用，并记录成果版本；不按名称/行号猜匹配，不自动改写已确认报价或预算，也不改变PR02客户确认总额的上限语义。

## 周期与实际时间

正常7天、批准加急5天，连续自然时间，自本轮资料发布至本轮合格尾查。客户等待、后续寄样不并入板房内部超时。工艺4/4/7天仍是原独立“工艺就绪→实际回收并确认”窗口（含原发出/确认目标）；实际外发排除另按真实交出→真实回收，不把两条时钟混用。

真实工艺外发、外洗及外部纸样区间取并集，重叠只扣一次。请求发出不是实际交出。外部纸样实际交出须由技术主管明确登记依据，实际收到沿原记录；缺起止、补报未核实或实际时间被订正为未知，只标精度受限，不伪造结束或新增业务拦截。实际尾查完成而时间未知也保持未能评价，不改写业务完成状态。

外部纸样交出录错或无法核实时，技术主管/Root在原外部纸样区域追加带原因的新版本，也可明确改为未知；保留旧值、登记人、原因和版本历史。期望版本冲突拒绝，重试不重复追加；已实际收到的状态和原收回事实不被订正动作清空。周期读取最新核验状态，不持续采用已失效的旧交出时间扣时。

内洗默认1天沿原冻结标准，外洗默认3天含往返。独立开发参数位于现有时效设置页，由原有效供应链总监、老板、Root预览后发布；只影响后续新来源。板房加急由老板/供应链总监/Root批准，继续使用原发布起点，不能抹掉已发生迟延。此权不等于PR04少于30自然日正式单审批权（仅老板/Root）。

合同回传原48小时业务时钟继续按北京时间周日暂停，周六计时；开发自然日规则不替换合同规则。船样不新增全链门禁；缺可信时间仅限制SLA评价。

## 补片、报废与工资

新规则尾查退回先形成真实问题记录，技术主管根据报废范围及关键成果可复用性判定。发生裁剪本身不能作为整单重走的唯一标准。

- 局部补片且关键成果仍有效：保留开发轮次，衔接原计件单真实新增执行轮次，主管重新核定本次实际新增金额（含明确零额）及执行人；不复制原金额、不另建工资账。实际补做→补做尾查（照片/尺寸）→原设计确认后按原规则计件。
- 整件报废或关键成果须重做：原执行单重新申请并建立新开发轮次，原实绩/逾期/工资均保留。

开发创建时未有逐码数量的，整件重做必须以技术已形成的尺码列，明确填写本次新轮的制作数量；零表示本次不做，合计须等于本轮制作件数。不能从总件数猜分配，也不把新轮数量回写原设计快照。

补做绑定技术主管的当前问题判定，不向公共返工API开放“跳过开发轮次”参数。新增任务与本次原执行段的派工/转交同步，不能借原车板任务改写历史归属；重试不会重复计件。原已完成未交接段仍按原金额平衡与交接规则处理。

Root沿原计件单合法派给本人时，补做激活保留已核验当前原生执行段的Root自执行例外，不要求给Root增授普通纸样师岗位，也不把此例外扩到无原生执行依据的普通任务。

## UI与交付边界

沿用现有工作台、任务页签、原办理按钮和底部操作区，新增内容仅在原开发/报价/设置区域，局部CSS复用现有tokens。模板、历史及技术补充默认折叠；主办理入口直接可达。版本冲突保留输入，已提交但读取失败沿同一操作标识恢复；上传状态按用途显示，不能把另一个物料/任务文件默带入。

本次不施工计划A/B生产事件、跟单正式制单、工厂节点退役/QC统一报量、相关单据目录及节点清单；分别由PR04–08按已批准顺序完成。不改手机端专项布局、不更换组件库、不触碰真实业务数据或部署。

0268是追加迁移，不提供删除成果/计件关联表的降级SQL。发生问题优先停止新增办理并向前修复；已有新节点开始执行后，旧二进制不具备这些节点的办理契约，不能直接退回旧版本并声称原任务仍可继续。保留全部成果、最终评语、原执行计件、实绩和历史时钟；修复版本必须继续读取并完成已开始任务，不重标为历史旧规则来绕过核验。部署及应急切换仍由业务负责人执行。
