# 返工、本厂做尾与裁床计件 V1.0

确认日期：2026-09-24

## 1. 业务目标
在既有订单返工、裁床实裁和财务工资基础上增量建设，不重做已有模块，不引入新的 UI 组件库。

## 2. 返工类别
- `qc_rework`：现有质检返工。现存历史返工单全部属于该类，不根据加工厂或责任结果反推历史类别。
- `inhouse_finishing`：本厂做尾。由尾部主管、老板或 Root 从订单回货发起；同一回货订单只有一个有效任务状态，不建设两种类别并行防重。
- 本厂做尾保留原加工厂和原订单跟单；从明确的外发→裁床→回货关联自动带入款号、加工厂、跟单和款图。
- 本厂做尾不要求上传质检报告，不询问是否整查；前段复用返工执行流程，IE 最终数量复核通过即完成，不进入责任判定、老板责任签字或供应商扣款，但正常进入工资。

## 3. 尾部固定工价与包装统一上数
- 先审计现有工序重名和历史引用；历史工序、历史单价和历史工资不得被新目录覆盖。
- 固定工序选中后自动带出目录价格且不可现场修改；工价至少保留三位小数，0.005 不得因显示规则改变计算值。
- 指定的前 9 个包装工序使用现有“本单工人/默认候选人”能力，不建设包装组管理。
- 这 9 个工序每道选择一个默认上数人，由该人上报工序总数；其他候选人不分别上数。数量和工资按本单实际成员平均分配。
- 新增包装工序时，默认上数人自动带入当前尾部主管最近一次成功保存的包装上数人；失效人员不自动带入且不阻断办理。
- 查货与整查是不同数量口径：查货可只查部分，整查代表整款全查。

## 4. 裁床计件
- 裁床工艺只能从固定目录选择，禁止自由输入名称或单价。
- 一个基础款式价可叠加多个附加工艺；代布印花属于附加工艺。
- “对格/对横条”两个价格档互斥；选择“对条衬衫”后不能再选择对格/对横条。
- 每项金额=固定工艺单价×实裁数；本款金额为各项金额合计，多款订单再汇总订单金额。
- 裁床计件不记具体领取工人；登记人仅用于操作审计，不能被当成工资领取人。

## 5. 财务
- 继续使用财务中心→工资管理，不新增一级财务模块。
- 人员工资支持返工类别筛选；包装可查看工序总数、人数、个人分摊与个人金额。
- 裁床作为独立工资来源按订单/款号显示总金额和工艺细分，不进入人员人数、人均工资或个人工资条。

## 6. UI
- 增量使用现有页面和控件；不新增突兀大框、重复信息区或第二套设计语言。
- PC 保持已有对齐和左右结构；移动端按现有卡片自然纵向排列。
- 固定单价采用紧凑只读信息，不用大面积 disabled 输入框。
- 默认上数人与现有人员区域对齐，不建立独立“包装设置”页面。
