# 业务分析与限定区域 UI Golden Source V1.0

日期：2026-09-10。适用于达兴数字助手的分析、筛选、入口及明确点名的局部 UI。依据 B 方案及业务负责人本轮批准口径；不替代各业务领域的金额、权限和状态机规则。

## 1. 每个分析区域必须回答五问

1. 识别了什么业务问题？
2. 为什么值得现在关注？
3. 能否下钻到具体订单、供应商、责任版本或记录？
4. 由谁处理，依据哪个现有角色或待办？
5. 是否能进入已有办理入口，处理后回读结果？

不能回答的展示框先合并、移位或删除。只为排版补数字、增加无依据评分、做人员绩效排名、把相关性写成处理成效，均不建设。

## 2. 数据与动作

- 汇总基于全部有效筛选集，分页只影响明细。行、汇总和下钻必须交代一致范围；独立口径必须写明。
- 进入时间取真实状态迁移；中途补充或报数不重置等待起点。缺记录显示“未记录”，不能用更新时间补造。
- 缺日期、缺上报、缺数量与真实零值不同。近 3 个有效生产日只取最近 7 个自然日实际记录，缺失不补零。
- 供应商集中度只描述本系统可见在产任务，不推断供应商全厂总产能。交期压力有真实分母和计算说明，可进入原生产单。
- 差异处理必须对应本次快照；历史旧处理可查，但不能遮住当前新差异。
- 不要求一线为分析重复填表，不引入另一套业务主数据。供应商导入可参考已有 ERP 的匹配/补全方式，分析不因此新增 ERP 数据源。
- 供应商批量录入先按编码或唯一名称与类型识别，补空、合并工艺；有效字段差异明确选择，重复资料不重复新增。具体规则仍以供应商领域 Golden Source 为准。
- 本轮新增或修改的金额展示最多 2 位；不改存储和原金额算法。本厂责任使用原工资等额口径，外厂责任使用既有倍率。

## 3. 原工作区保护

返工节点、收货及多次收货、报数、IE 核价、判责、扣款、样衣借还/处置、外发五节点都是原工作区。分析只能链接到它们，不能另造表单或重排业务顺序。

分析读取失败应在自己的区域说明，可重试；原列表和办理入口仍可使用。加载、空数据、无权限、读取失败要可区分，不能把失败显示成业务零值。

订单重新判责是本轮单独批准的状态机扩展：正式重判角色及 Root 发起，记录原因，原处理人接 N07，重新老板确认；旧责任、签字、扣款、工资事实保留。同订单/责任类型/供应商的历史已扣进入新台账，只办理余款。退款、抵账、冲销的新流程不在本轮范围，不能静默覆写旧账。

## 4. 筛选、层级与密度

- 一页一套主筛选；分析使用相同关键词、节点及日期时复用状态，不再复制输入框。分析专用的等待/往返/缺记录维度可在分析中补充。
- 禁止重复业务列表。分析明细只有在提供独立事实时保留，例如节点往返、版本价格、供应商在产明细；必须可下钻。
- Accordion 适合历史、照片、口径说明、技术诊断及低频资料；当前办理区和常用筛选不能层层隐藏。
- 复用现有蓝白配色、深色导航及组件；优先现有 spacing tokens，局部间距使用 8/12/16/24px。通过对齐、分组和留白减负，不靠不断加框。
- 只写页面/组件命名空间 CSS。不得使用全局标签样式影响原工作区；桌面与手机规则分开。

## 5. 手机

以 16px 作为业务文字和输入的基准。搜索独占一行，常用筛选保留 2–3 项；日期等移入更多筛选，有已选条件时能看见。窄屏应换行，不通过 10–12px 字号挤压。

返工详情优先当前节点和原办理区，再显示核心订单事实及当前责任；照片、完整流程、历史默认折叠。工人嵌在工序组的小行中，责任控件点击“编辑”后展开；仍是同一套字段和提交函数。

操作区避开底部导航与安全区，小高度或键盘场景允许回到自然文档流。部署验收至少查看 320/375/430px 和桌面，覆盖展开、编辑、提交、返回筛选等正常动作。

## 6. 交付边界

“源码已审查”“测试通过”“Gate 通过”“独立 Review 完成”“合并”“部署”“业务验收”分开记录。没有真机或截图证据时不得宣称视觉验收通过。

全系统审查可以登记后续业务事项，但不自动授权修改其他业务规则。优先正常流程、事实准确、可恢复的常见异常；不为极低概率场景扩展本轮施工。Gate 按实际改动分级，仅在当前 Head 通过后合并。
