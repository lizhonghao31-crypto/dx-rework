# 移动端订单详情信息密度治理（2026-08-14）

## 业务目标

减少订单详情在手机上的纵向滚动与重复说明，让业务人员在一个视区内快速读取订单、数量、人员、工厂与问题事实。

## 验收口径

- `<=640px` 时，订单事实区使用三列紧凑矩阵，不允许回退为单列长条。
- 前九项按现有业务顺序组成三行；“问题部位”占一列，“问题描述”占两列。
- “发起人”“发起时间”“最近更新”同处一行；不再展示与发起时间高度重复的“首次提交”。
- 其他附件与取消原因继续占满整行，避免长文本被强行压入窄列。
- 移动端隐藏“订单是唯一的流程与执行载体”说明；桌面端继续显示。
- 桌面端现有五列布局、字段值、颜色、组件和交互保持不变。

## 非本次范围

- 不修改订单数据、接口、状态流转、权限或时间格式。
- 不修改订单图片、节点流程和业务操作区。
- 不引入新的 UI 组件、依赖或调色盘。
