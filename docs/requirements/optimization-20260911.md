# 2026年9月11日工资与权限优化

本轮唯一需求来源为业务负责人提供的《9.11需求.docx》，当前授权全程接手四个 PR 并合并，由业务负责人验收。

PR01 工资已发放标记：按人员编号去重，正式工/临时工与实际完工日交叉筛选，含起止两日。沿用既有报工关联，不增加日期录入、关联回填或工资副本。当前预览最多500行，工人汇总、总额、确认人数/条数、导出和标记均使用完整筛选结果。确认前读取实际明细编号，确认后只处理这批且仍符合条件的未结算记录；后续新增工资默认未结算。独立权限 wage:settlement_mark 给予工资月结会计、现有工资财务 finance_read、财务总监及原有 Root 特权。无付款、审批、锁定、撤销或调账流程，不改变工资金额、订单及扣款状态。

旧月结清理：移除当前报表和导出的月结状态与旧锁定写入实现；历史月份与锁定明细读取继续保留。WageService.lock 只保留明确拒绝的兼容入口，数据库历史迁移、约束及工资数据不删除。旧月结不是工资已发放标记。

PR02 待办关联真实跟单姓名搜索；返回保留搜索词、模块与页码。PR03 质检仅增加返工基础看板权限，仓管原页加“查看订货回货”小按钮。PR04 财务总监各节点实际内容只读，独立判断读写权限。

每PR最终Head执行Full Gate，Codex Review最多一轮；只用隔离测试数据。沿用原布局、类名及现有业务行为，root既有权限不变。
